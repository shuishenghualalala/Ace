# Visual Precedent Library

This library is a user-curated set of visual precedents. It is descriptive, optional evidence for
composition and visual grammar; it is not an additional brand system, object specification, or
mandatory template. Official Kimi brand sources, user intent, object fidelity, Daimon runtime rules,
semantic fit, and accessibility always have higher authority.

This library does not decide whether a Pixel/ASCII carrier exists. The Default carrier gate does that;
this library only helps choose a transferable composition for the carrier.

The images live in `assets/references/visual-precedents/`. The source folder did not include source
metadata, so these assets must not be presented as official Kimi, product, or vendor references.

## Selection protocol

1. Identify the user job, object gate, archetype, P0, and unresolved visual problem first.
2. Read this index before opening an image. Do not load the full image set for every widget.
3. Select at most one primary and one secondary precedent when a precedent can answer the unresolved
   visual problem. Skip the library when the task is already structurally resolved.
4. Extract transferable relationships: hierarchy, density, alignment, field placement, control/output
   proximity, material depth, or disclosure. Do not copy exact layout, wording, brand marks, palette,
   icons, or decorative marks.
5. Recompose the extracted relationship for the current object, archetype, tier, theme, host safe
   zone, and Kimi token system. A precedent may suggest a candidate; it may never add unjustified
   content or override a higher-authority rule.
6. Record the selected precedent's pattern role in the internal design proof. Do not mention the
   library in the routine user-facing response unless the user asks for references.

## Transferable pattern families

| Pattern | What to learn | Suitable jobs | Do not import automatically |
|---|---|---|---|
| Large P0 + evidence field | one immediate read plus a subordinate signal field | measure, answer, monitor | a fixed dashboard shell |
| Open expressive Pixel Field | broad negative space carries direction, density, or atmosphere | wind, flow, readiness, resolve | tiny icon-like Pixel clusters |
| Pixel P0 display | cells can form a short readable title, value, or state | market pulse, budget, clock, status | unreadable long copy or chart labels |
| Instrument readout | labels, scale, mark, and value share a precise axis | measure, compare, simulate | decorative gauges without a job |
| Dense control surface | controls sit beside the output they change | media, tuning, simulation | a remote settings sidebar |
| Grid-framed data | construction lines establish alignment and time/scale | chart, calendar, market | dense scan lines behind copy |
| Open panel + field | a bounded local cluster coexists with open content | default Kimi utility | wrapping the whole widget in cards |

## Case index

### `pixel-density-timeline`

- File: `assets/references/visual-precedents/pixel-density-timeline.jpg`
- Pattern: time-series density field with active/idle contrast.
- Learn: repeated cells can encode intensity over time while labels remain direct and sparse.
- Route to: measure, compare, monitor, data visualization.
- Avoid: treating the cell count as a chart without a real source signal.

### `radio-control-surface`

- File: `assets/references/visual-precedents/radio-control-surface.jpg`
- Pattern: media readout with station choice, tuning scale, transport, tempo, equalizer, and volume.
- Learn: object-specific controls form one operational surface and stay close to their output.
- Route to: object-led media or explicit audio-control requests.
- Avoid: importing a radio skeleton into an unrelated default widget.

### `threshold-signal-instrument`

- File: `assets/references/visual-precedents/threshold-signal-instrument.jpg`
- Pattern: two large readings, a threshold bar, small source marks, and a compact status badge.
- Learn: P0 values dominate; baseline, status, and supporting inputs remain legible without card piles.
- Route to: measure, compare, signal, readiness.
- Avoid: promoting every supporting value to a separate focal point.

### `subscription-calendar`

- File: `assets/references/visual-precedents/subscription-calendar.jpg`
- Pattern: calendar grid with sparse category marks, date navigation, and a quiet summary footer.
- Learn: a semantic grid can carry repeated time structure while controls stay local.
- Route to: sequence, schedule, choose, recurring events.
- Avoid: copying the dark calendar surface or adding unrelated subscription semantics.

### `kimi-pixel-build`

- File: `assets/references/visual-precedents/kimi-pixel-build.jpg`
- Pattern: large type, visible construction grid, and a dense symbol field resolving into a subject.
- Learn: brand atmosphere can be structural and expressive, with type and field sharing a system.
- Route to: explicit Kimi art direction, resolve, build, concept.
- Avoid: treating the image as an official brand asset or requiring a subject silhouette everywhere.

### `kimi-pixel-sphere`

- File: `assets/references/visual-precedents/kimi-pixel-sphere.jpg`
- Pattern: light field, large editorial type, and a localized Pixel subject.
- Learn: Pixel density may occupy a meaningful open region and coexist with generous negative space.
- Route to: expressive or resolve tasks with a contextual subject.
- Avoid: using a localized Pixel blob as generic decoration.

### `wind-direction-open-field`

- File: `assets/references/visual-precedents/wind-direction-open-field.png`
- Pattern: high-priority weather readout paired with a broad directional field in open space.
- Learn: the field can be the visual content, with direction and motion tied to the phenomenon.
- Route to: Default Kimi flow, wind, weather, vector, atmosphere.
- Avoid: putting the field under a panel by default or using pointer motion without domain meaning.

### `cycling-background-field`

- File: `assets/references/visual-precedents/cycling-background-field.png`
- Pattern: a foreground instrument surrounded by a large Pixel-built environmental subject.
- Learn: the Pixel field can fill the background and open sides of the composition while P0 and a
  normal chart remain crisp in the foreground.
- Route to: motion, fitness, transport, object atmosphere, expressive Default Kimi backgrounds.
- Avoid: requiring a literal silhouette when an abstract flow/density field serves the task better.

### `market-pulse-pixel-p0`

- File: `assets/references/visual-precedents/market-pulse-pixel-p0.png`
- Pattern: Pixel-built P0 word/value above a square construction grid and status rows.
- Learn: a short P0 can be constructed from cells while ordinary labels and states remain readable.
- Route to: market, status, alert, monitor, Pixel display.
- Avoid: replacing a legible chart or long title with ambiguous Pixel glyphs.

### `fear-greed-instrument`

- File: `assets/references/visual-precedents/fear-greed-instrument.png`
- Pattern: direct gauge, semantic state color, compact Pixel badge, and a baseline strip.
- Learn: an instrument can combine a normal readable graphic with one coordinated Pixel region.
- Route to: measure, threshold, sentiment, risk.
- Avoid: using color without a named state or making the Pixel badge the only explanation.

### `widget-instrument-atlas`

- File: `assets/references/visual-precedents/widget-instrument-atlas.jpg`
- Pattern: many small instruments with a strong P0, direct units, tiny charts, and local semantic color.
- Learn: widget families can vary by job while sharing compact information discipline.
- Route to: default inspiration when the job is known but the composition is not.
- Avoid: copying the whole atlas into one widget or forcing every sample to be equally dense.

### `tvl-data-instrument`

- File: `assets/references/visual-precedents/tvl-data-instrument.jpg`
- Pattern: large P0, trend line, hover evidence, secondary flow values, and period controls.
- Learn: evidence can expand around one dominant value; inspection belongs near the mark.
- Route to: measure, compare, finance, analytics.
- Avoid: adding hover-only evidence that is unavailable to keyboard or reduced-motion users.

### `subscriber-compare-chart`

- File: `assets/references/visual-precedents/subscriber-compare-chart.jpg`
- Pattern: aligned P0 metrics, period selector, two direct-labeled comparison series, and tooltip evidence.
- Learn: comparison needs a stable basis, direct labels, and one selected period.
- Route to: compare, trend, growth, benchmark.
- Avoid: relying on color alone or hiding the comparison basis in a distant legend.

### `budget-pixel-panel`

- File: `assets/references/visual-precedents/budget-pixel-panel.jpg`
- Pattern: readable Pixel P0 inside a bounded panel with a large expressive Pixel field outside it.
- Learn: Pixel may occupy open space beside or below a panel; P0 and background field can share cells
  without making the panel opaque.
- Route to: budget, quota, allocation, default Kimi measure.
- Avoid: treating under-panel placement as the universal Pixel rule.

## Evaluation use

Use selected precedents as visual evidence during review, not as a screenshot-matching target. A
passing widget preserves the user's object/job, has a singular P0, recomposes by tier, fits the host,
and uses only the transferable relationship that remains semantically justified. If the result needs
the precedent's exact layout or decorative content to look resolved, the Skill or implementation is
underspecified and must be repaired.
