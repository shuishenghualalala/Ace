| 体验 | 当前代码/真实会话证据 | 改造要求 |

| 一致且克制的视觉 | `web-messages.css` 为宿主加边框、圆角、内边距；生成页面又加同类容器和重复标题 | 普通图表直接使用对话背景；标题只出现一次；图表与正文对齐；只有必要的指标或选项使用轻量卡片 |

| 自然滚动 | `inline-widget.ts` 将 iframe 高度限制到 720px，文档明确内部滚动 | 常见原生图表无内层滚动；合理响应宽度与内容高度，长表格另行处理，不靠无限撑高解决 |

| 结果生成不像网页开发 | 实测出现 HTML 文件改动卡、网站入口和侧栏预览 | 常见图表/表单直接走结构化展示工具，不创建 Widget 网页项目；真实项目文件改动仍正常披露，不全局隐藏工具记录 |
| 版本与状态连续 | 两次 show 产生两个工具调用快照；原组件独立恢复已通过 | 显式区分“替换当前展示版本”和“新增比较组件”；不静默改写历史，不因为流式消息重复插入；稳定组件 ID 保持输入状态 |

## 本轮实施顺序

1. **结构化内容协议与内置渲染器**：常见折线/柱状图、指标、滑块、数值/文本输入、选择器、动作。模型提供数据、标签、单位、参数和允许动作；前端不执行模型提供的任意脚本。以通用声明描述业务数据，避免写死一个“收益分析小程序”。动态图需要声明受支持的计算/变换，服务端与前端均校验；不使用 eval 或把公式当任意 JS 执行。
2. **回答内排列与共享视觉**：复用桌面字体、颜色、间距和主题变量，支持图表内容块的稳定位置；移除双层外框与重复标题，控件保持紧凑，主图及轴标签可读。
3. **交互与会话桥接**：本地参数计算、悬停、图例切换；明确动作才调用模型，保留已有会话隔离、输入验证、防重复、草稿保护与状态恢复能力。把可读摘要与完整机器数据分开保存，重开后仍能核对。
4. **Agent 使用路径与真实验收**：常见可视化默认选择结构化展示工具；不要求用户说出工具名或手写 JSON。使用实际配置模型生成自然回答并在桌面操作，不能拿独立示例代替验收。

## 验收场景

### A：静态比较回答

自然提问比较三组月度数据。正文中直接出现一张清楚的多系列图；有标题、轴单位、图例和悬停读数；没有无关输入框、续问按钮、网页文件卡或自动侧栏。宽度变化和明暗主题切换均可读。

### B：参数探索回答

沿用 12 个月收益情景：初始投入 3,000，收入 8,000，成本 6,000。修改收入到 12,000、成本到 7,000，图表和对应结果即时一致，过程中不新增模型请求。明确点击继续分析后恰好发送一次，模型使用正确数值，聊天展示可读摘要而不是裸 JSON；草稿与附件保留。参数/公式口径明确，不要求模型逐次生成 HTML/JS。

### C：状态与历史

流式续写、切换会话、退出后重启桌面及 Gateway，组件与输入恢复；两个不同组件互不覆盖，替换版本不导致重复卡片。测试跨会话提交拒绝、非法数值、未知组件类型及加载失败降级。重启遵守 AGENTS.md：先停旧 Gateway，再 `cd desktop && npm run dev`。

验收证据应包含实际聊天截图、关键参数与模型输入核对、针对协议和会话边界的测试结果。原 HTML 版本的旧截图只能证明旧链路，不证明本轮改造完成。

## 范围

仅桌面端。聊天回答不再渲染既有 HTML 内联快照，也不批量改写旧用户会话；独立 App 的 Widget 面板和 Canvas 预览保持不变。Web/移动端、完整插件 UI 生态、复杂自由模拟、全屏和悬浮模式留待后续，不在本轮扩张。
