1. 验证目标

  • 服务按 Session、User、Workspace、Global 的顺序解析，租户之间不串值。
  • 激活中贡献不可见，提交后整体可见，停止开始后立即拒绝新解析。
  • required 缺失阻止就绪，optional 缺失只进入诊断。
  • 静态依赖批次、无 Provider 断路和循环等待可被识别。
  • 配置更新失败或 Generation 过时不改变 effective revision。

3. 不变量

  • 同一 Service Key 在同一精确作用域不能重复注册；不同作用域可以并存。
  • 旧 Token 再次释放不能误删后来注册的新 Generation。
  • 依赖图的启动批次只用于静态诊断，真实激活仍以当前作用域的可见服务为准。
  • desired revision 单调递增；只有仍匹配最新 desired 的 Generation 能成为 effective。

4. 跨平台说明

全部测试只使用 Python 标准异步与内存结构，没有平台路径、Shell、信号或文件锁差异。
