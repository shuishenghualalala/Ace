验证目标

  • product.team Generation 统一拥有 InProcessTeamManager、mode=team Execution Driver 与 ServiceKey("team") 服务；CrewApp 不再手写构造 Manager/Driver。
  • Manager 增加 shutdown() 与 _closed 守卫；停用后新请求 fail-closed，在途 delegate/recovery 任务被取消。
  • App 级 owner Provider 缓存通过可调用对象注入 Manager，模型切换时同步失效；同时保留 app.team 兼容表面与 set_team_manager() 测试路径。
  • build_app(enable_team=True) 正确激活 Feature，enable_team=False 时不注册 Team Driver；旧测试通过 set_team_manager() 继续工作。

生命周期核验要点

  • install 先注册 manager.shutdown disposer 再装配 Driver/Service，激活失败时 Runtime 正常回滚。
  • CrewApp 通过 build_team_feature(..., activate=enable_team) 在 build 期激活；激活记录由 declare_managed_feature() 纳入 Runtime，后续 startup() 不再重复安装。
  • Owner Provider 缓存同时存在于 App 与 Manager：App 维护跨调用的长效缓存，Manager 在 Generation 内做同代缓存；切换模型时 App 先清空自身缓存再调用 manager.invalidate_owner_provider()。
  • Gateway 通过 getattr(crew, "team", None) 安全设置 interaction_bridge；Team 未启用时跳过。
  • set_team_manager() 仅在测试路径使用：注册独立的 product.team-driver-adapter 桥接 Scope 以托管注入 Manager 的 Driver，避免污染 product.team 生产路径。
