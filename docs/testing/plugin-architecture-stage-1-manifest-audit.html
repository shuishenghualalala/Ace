1. 验证目标

  • 加载顺序由服务图而不是目录名或操作系统枚举顺序决定。
  • required 缺失进入 Waiting 且不执行插件；optional 缺失不阻止激活。
  • Manifest 承诺的 provided Service 必须由当前 Generation 实际注册。
  • 后到 Host Service 可使 Waiting 插件重新激活。
  • 启动审计和 CLI 输出包含缺失服务与注册所有权，阻塞时返回非零状态。

3. 新增回归场景

  • 字母序在前的 Consumer 等待字母序在后的 Provider，最终按 Provider → Consumer 激活。
  • 未兑现 provides 的插件进入 Failed，已暂存服务被回滚。
  • 未声明的 Service 发布或消费在插件边界失败。
  • Waiting 记录输出确切缺失 key；Active 记录输出 Contribution/Resource 标签。
  • CLI JSON 与人类可读输出共享同一审计模型，并确保退出时释放 App。

4. 跨平台说明

激活批次使用排序后的稳定 key，不依赖 APFS、ext4 或 NTFS 的目录枚举顺序。Host Service 发布和重试均为进程内 Python 生命周期操作。
