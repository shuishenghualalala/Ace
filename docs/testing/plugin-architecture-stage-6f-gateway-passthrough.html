阶段 6F · Gateway 流事件出口灰度开关

2026-09-11。兼容层删除路线 Step 2（依据 6C 就绪度调查）：为 WS 出口增加 feature_event 透传灰度开关。基线提交 36b0a92；已验收通过并随本记录提交。

方案

环境变量 CREW_GATEWAY_FEATURE_EVENT_PASSTHROUGH（模块加载时解析一次缓存，热路径不读 env；1/true/yes/on 大小写不敏感）。默认关闭=现状（出口转换旧帧、未登记丢弃、replay 缓存旧帧）；开启后 feature_event 帧原样透传——插件贡献的未登记事件不再被出口丢弃，回放缓存与线上帧同形态。短路点在 push_payload 的 expand 调用（_outgoing_frames），推送/缓存时序与限流语义不变；启动日志输出当前出口模式。迁移期临时机制，删除条件 = Step 3 随 event_compat 整体摘除。

已知边界

  • 透传帧按普通帧参与出口限流（与旧路径对转换后帧一致）。
  • 开关为进程级一次性读取，运行中改 env 需重启生效（重启灰度语义，启动日志可诊断）。
  • 第一方客户端就绪前提已满足：Desktop 6D 完成双协议等价、Web 双解析、CLI 不经 Gateway。Step 3（删 event_compat）前仍需：透传模式全量回归 + 已发布旧客户端最低支持版本的产品决策。
