  • product.cron 在宿主事件循环中 activate，并完整拥有 Scheduler、Tools、Context 与 Host Binding。

  • Gateway Logout 始终解析当前 Generation 的 Service，停用不删除持久任务数据。

3. 关键断言

  • 激活前记录为 DISCOVERED 且 Cron 工具不可见；提交后状态 ACTIVE，诊断包含 resource:cron.scheduler、tool:cron_create 等标签。
  • 停用后 CrewApp.cron_service 清空、工具和 Contributor 消失，SQLite 任务数据不被删除。
  • restart 后旧 Service 不再运行，新 Service 指向 g2 且已挂载原 Active Owner。
  • 启动异常后的 Runtime 状态为 FAILED，不存在孤儿工具或上下文贡献。

4. 跨平台说明

生命周期代码只使用 asyncio 与对象身份校验；测试临时目录沿用 TemporaryDirectory(ignore_cleanup_errors=True)，避免 Windows 在 SQLite 句柄释放时序上的目录清理差异。无 POSIX-only 分支。

5. 基线与环境约束
