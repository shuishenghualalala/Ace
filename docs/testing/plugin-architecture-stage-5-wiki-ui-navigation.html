插件架构阶段 5 · Wiki UI Navigation Registry

分支：refactor/plugin-architecture-stage-0 · 日期：2026-09-07 · 编码与测试：相互独立的 Luna 子 Agent

验证目标

  • Desktop/Web 建立构建期可信的 UI Navigation Registry，支持注册、确定性排序、重复冲突失败和可逆 unregister/dispose。
  • Wiki 由独立 UI module/descriptor 提供导航贡献；核心导航 inventory 与 render 分支不再硬编码 Wiki descriptor。宿主 capability state 以及现有 SidebarView/TabKey 兼容类型仍在迁移期保留，Assistant 与 Work 原有共享导航语义保持不变。
  • 以现有 /api/config 的 wiki.enabled 作为兼容能力事实来源；配置加载中或失败时保持旧行为，明确禁用时隐藏 Wiki、拒绝程序化切换，并从当前 Wiki view 安全回落 Chat。
  • 本切片不迁 Wiki 页面生命周期、API Client、Feature Event Reducer，也不迁外援、Team 等其他 UI Contribution。

设计与边界

Registry 是宿主拥有的构建期装配面；Wiki module 只返回自己的 navigation descriptor，宿主显式 mount 并持有 disposer。重复 ID 立即失败，投影按声明顺序和稳定 ID 排序，旧 disposer 不会删除 unregister 后重新注册的替代贡献。Backend capability 与本地构建能力同时满足时才展示入口。

待办：Wiki 页面 activate/dispose 生命周期、Wiki API Client、全局 Feature Event reducer/未知事件处理、Composer 贡献，以及 External Agent、Team 等其他 UI Feature 尚未迁移。下一项后端优先级为阶段 3C Work Foundation + API Consumer；本阶段没有修改后端协议。
