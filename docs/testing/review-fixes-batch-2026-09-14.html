A · 配置隔离与事务（crew/state/config.py）

A-1 隔离：anchor 共享 extra 串改

根因：_write_channel_config 中 current = dict(platform_value) 为浅拷贝，_deep_merge_dicts 结果的嵌套 dict 与源对象共享引用；remove-keys 循环 extra.pop(key) 原地修改共享对象，YAML anchor 让两个渠道共享 extra 时删除 A 的字段同时删掉 B 的字段并污染输入。修法：构造写入对象前 deepcopy(platform_value) + deepcopy(channel_effective) 与源数据脱钩。

A-2 事务：内存先于磁盘发布

根因：_persist_channel_config_locked 等四个 persist 在 Path.replace() 之前更新 self.channels / self.platforms / self.raw_config，写盘失败后内存是新值、磁盘是旧值。修法：提取 _atomic_write_yaml（tmp 写入 + 原子替换 + 失败清理残留并重抛，文件内 5 处写盘点收敛）；channel / mcp_servers / model_profiles / evolution 四个 persist 统一为磁盘提交成功后再发布内存状态。

测试：tests/test_channel_config_write_isolation.py 10 用例（anchor 共享 platform/channel 嵌套 extra 删除隔离、输入与兄弟渠道不串改、tmp 写失败 / replace 失败 / mcp / model_profiles / evolution 写失败注入、成功路径）。修复前 6+2 用例红 → 修复后 10 全绿。回归 test_config_crud.py + test_config_features_namespace.py + test_channel_config_api.py + test_channel_sessions.py 全过。

B-2 · Wiki 能力门控统一（desktop + web）

根因：双端 Wiki 入口只读旧 wiki.enabled，Runtime failed / available=false 时仍判定可用，入口、页面、reducer 不同步停用。修法：Desktop wiki-feature.ts 新增 WIKI_FEATURE_ID，wikiFeatureEnabled 改能力优先 + legacy 回落；页面 PageContribution isAvailable 第二源消除、reducer 注册门同源。Web featureFlags.ts 新增 WIKI_FEATURE_ID / wikiFeatureAvailable，wikiNavigationEnabled 同语义改造。

语义真值表：能力字段缺席 → 旧 wiki.enabled !== false 默认可见；字段存在且条目 available=true → 可用（能力优先）；条目缺席或 available=false → 不可用（state=failed 时 wiki.enabled=true 也不可见）。

测试：探针转两端正式用例（wiki-feature-capability.test.ts 7 例、wiki-page / wiki-reducer-lifecycle 扩展、web wiki-navigation / featureFlags 能力用例）。修复前 desktop 4 failed / web 10 failed → 修复后全绿；双端 typecheck 通过。
