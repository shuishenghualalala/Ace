1. 验证目标

  • replace 在新 Generation 可用后原子切换 Service，并等待旧代 Lease 结束。
  • replace 安装失败完整回滚新代，旧代和 effective revision 保持不变。
  • restart 严格先清理旧代再安装新代；失败时恢复旧配置并保留 desired revision。
  • restart_required 记录新 desired revision 和宿主重启要求，不破坏当前 Generation。
  • 同一 Feature 的并发更新按 Generation 顺序串行化。

3. 关键回归场景

  • 新服务在 Activating 阶段不可见，提交后解析立即指向新 Generation；旧代 disposer 不会删除新代注册。
  • replace 旧代 drain 超时后，新代继续服务，旧代以 retiring Generation 出现在启动审计中；后续停用可继续收口。
  • restart drain 超时会重新开放资源完好的旧代，并允许相同 desired revision 重试。
  • restart 新代失败时恢复为新的 Generation 序号；若恢复也失败，错误同时保留更新原因和恢复原因。
  • 配置更新试图改变依赖、Service Scope 或更新策略时被拒绝。

4. 跨平台说明

更新串行化、Lease drain、服务可见性和失败恢复全部基于 Python asyncio 与内存状态，不依赖 POSIX signal、fork、Unix socket 或平台文件锁；测试在 macOS 执行，代码路径对 Linux 和 Windows 一致。
