插件架构阶段 1 · Drain Lease

分支：refactor/plugin-architecture-stage-0 · 日期：2026-09-02

1. 验证目标

  • Drain 开始后拒绝新请求，已有请求结束前不释放资源。
  • Cancel 能中断异步请求；同步线程未结束时不得提前释放 Lease。
  • Timeout 保持 Draining 并允许在遗留 Lease 释放后重试。
  • Immediate 与 restart_required 都产生可机器读取的诊断。
  • 目录插件入口自动进入同一 Generation Lease，无需业务 Handler 手工接线。

3. 关键回归场景

  • 活跃 Wiki 查询持有 Lease，停用任务停在 Draining；释放后才按 Contribution → Resource 顺序清理。
  • Browser 类 Cancel 策略取消持有 Lease 的 asyncio Task，并等待 finally 释放。
  • 同步 Tool 在线程内阻塞时取消超时，插件仍保持已装配且拒绝新增；线程退出后第二次停用成功。
  • restart_required 的运行期卸载保留工具和 Generation；应用关闭边界完成最终释放。
  • Feature dump 包含 active leases、timeout、forced leases 和 restart required。

4. 跨平台说明

测试不依赖 POSIX signal、进程 fork 或特定文件系统。同步 Handler 继续使用 asyncio 的跨平台线程池，并显式等待线程真实结束后释放资源所有权。

5. 暂存快照扩展观测

额外在仅含暂存内容的导出目录运行扩展套件，得到 323 通过、1 跳过、2 失败。两个失败都位于 CLI 环境检查：导出目录不携带可执行的原生安全 Runtime；隔离目录的示例 Provider 配置尝试连接无效外部地址。核心 staged-tree 套件全绿，这两项不涉及 Feature Lease、Plugin Adapter 或本次 Manifest 变更。
