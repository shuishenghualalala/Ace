阶段 6AA · Channels 配置命名空间读写闭环

2026-09-14。6X 的 features.channels 双读只有读侧归一：保存路径仍只写顶层 channels，导致新节配置下「保存成功、重载回退旧值」；owner overlay 则完全不识别新节。本片在 crew/state/config.py 内统一读写规则，设计与决策见 ADR-0039。

处置

  • 写入收敛：新增模块级 _write_channel_config()，全局与 owner 两条持久化路径共用。以磁盘原始数据判定目标节——存在有效 features.channels 时写入新节，否则落回旧 channels 节；无论落点，都把该渠道的完整有效值（platforms ⊕ channels ⊕ 新节 ⊕ 本次 payload，owner 不含 platforms）归入选定节，并清除该渠道在其他别名节中的残留，杜绝删除字段、清空 extra 在下次合并时复活。
  • owner 新节读取：owner_overlay_data() 接入与主配置相同的 _apply_features_namespace() 归一，owner 分支经归一后的 channels 布局读取（新节优先、旧节兜底），写入与读取对称。
  • 内存态同步：全局保存后同步刷新 self.channels、self.platforms 与 raw_config，保存后同进程读取与重载结果一致。
  • 主 agent 审查修正：子 agent 初版在 owner 读取分支引入了 overlay.platforms 旧别名回读，与 ADR-0039「owner 延续不读取 platforms 旧别名」的已确认契约及其测试 test_owner_channel_config_does_not_fallback_to_owner_platforms 冲突（复现 1 failed）。修正为 owner 仅读 channels 布局并保留 deepcopy 隔离，套件恢复 30 passed。
