Ace / 文档总览

AAce 多智能体平台

开源版 Crew，以单智能体调用为核心，支持 Team 多智能体协同、Skills 技能运行时、Native Security Runtime 与浏览器自动化。 下面是 Ace 的架构分层与一次请求的典型流转，每个模块都可点击进入对应文档。
Python 3.11+ FastAPI + WebSocket SQLite OpenAI 兼容 Provider Native Security Runtime

1. 一次请求怎么运转

下面是一次对话请求的完整内部流转：从用户输入到模型调用、工具执行、安全审批、状态保存，再到响应返回。流程图中的模块只做示意，点击下方的「架构分层与模块索引」卡片可进入对应文档。

1. 输入层
CLI / Web / Desktop 发起一次用户请求，携带文本、附件、上下文 session_id 与结构化 mention（Team 场景）。
↓
2. Gateway / Auth
网关完成认证、鉴权、Owner 隔离与协议转换：
  • 校验 token 或本地 session，按 Owner 划分资源边界；
  • 复用或新建 Session，加载对话历史与工作空间；
  • 将外部请求统一封装为 Core 层的 Envelope / Message。
↓
3. App 装配层
crew/app.py 根据 mode 与请求类型做装配：
  • 从缓存或配置中取出 Agent / Team 实例；
  • 注入 Provider、Tools、Memory、Plugins、Security 等依赖；
  • 路由到 agent、team 或 cron 执行路径。
↓
mode = agent
直接进入单 Agent 内核循环，适合一对一对话。
mode = team
Leader 做规划并委派给 Teammate，通过 Team Bus 协同。
mode = cron
Cron 调度器定时构造 Envelope，投递到 App 执行。
↓
4. 任务运行时
无论是 Agent 独立执行、Team 委派还是 Cron 触发，都会产生可追踪的运行时单元：
  • Tasks：维护 task 状态机、超时、取消、看板与历史恢复；
  • DynamicKanban：把复杂工作流解析为 DAG，按节点状态驱动多 Agent 协作。
↓
5. Agent 内核循环（单 Agent 或被 Team 复用）
  1. 加载上下文：从 State 读取历史消息、配置、工作空间；
  2. Memory prefetch：根据当前 query 召回相关记忆；
  3. Plugin pre-hook：在调用模型前执行插件钩子；
  4. 调用 Provider：把历史 + 系统提示 + 工具 schema 发给 LLM；
  5. 解析响应：拆分文本、thinking、tool_call；
  6. 工具执行：若产生 tool_call，进入 Tools 执行流程：
    • Security Broker 做审批与沙箱约束；
    • 按需调用 Browser、Wiki、Skills、文件系统或外部 API；
    • 执行结果回灌到对话历史，回到步骤 4 继续循环。
  7. Plugin post-hook：在响应生成后执行插件钩子；
  8. 持久化：Memory write、State save、更新 Task 状态。
↓
6. 响应返回
将最终响应切分为帧（delta / thinking / tool / final / error），经 Gateway 推送到 CLI 或 Web/Desktop；同时把终态写入 Task、Team Bus 与历史会话，供后续恢复。

3. 推荐阅读顺序

第一次理解 Ace，建议按下面顺序读，先建立整体链路，再下钻到具体模块：

  1. Core：先看 core，理解 Envelope / Message / 接口契约。
  2. State + Provider + Tools：补齐 Agent 需要的历史、模型和行动能力。
  3. Agent：理解单智能体循环；这是 Team、Tasks、Skills 的复用基础。
  4. App + Gateway / CLI：看入口怎么装配、怎么路由。
  5. Team + Tasks + DynamicKanban + Cron：在单 Agent 基础上理解多智能体协同、任务看板、工作流与自动化。
  6. Security + Browser：理解 Native Runtime 与浏览器自动化如何保障行动边界。
