背景与决定

两端已有可撤销的 Wiki 导航贡献，但宿主仍直接装配页面及会话行为。桌面页面和 Wiki Agent 存在全局监听，Web 的新建、删除会话及知识库加载存在跨页面、跨知识库的异步回写边界。

沿用构建期可信 Feature Registry，增加页面贡献与页面宿主调度。Desktop 使用可释放的页面控制器，Web 使用 React 挂载和卸载；二者遵守同一资源归属与可用性语义，不要求使用相同组件实现。

生命周期契约

  • 注册返回幂等 disposer；旧 disposer 不得删除后来注册的贡献。
  • 激活前检查能力状态。离页时释放页面拥有的监听、计时器、观察器、编辑器和渲染资源。
  • 页面活动身份或知识库身份变化后，旧请求的响应不得更新新页面或加载旧会话历史；禁用后不得发起新的页面请求。
  • 活动身份不能在重置时归零复用。校验同时覆盖结果回写和后续请求调度，包括上传后编译与批量下一项。
  • 编辑器待保存内容在释放视图前交给明确的保存流程；不得仅清理 debounce 计时器而丢失用户编辑。保存完成后仍需检查视图身份。
  • 跨页入口和发送参数解析归 Feature 安装期，页面 DOM 与渲染订阅归页面活动期。离页不停止后端会话，也不删除历史数据。
  • 普通离页与登录身份重置分别处理：离页释放 DOM、订阅和渲染任务，但保留未发送草稿及附件；不能复用身份重置函数而丢失用户输入。
  • 离页重进保留已有知识库选择语义；Desktop 的 Wiki 仍可作为 Work 模式的共享页面显示，活动状态由实际可见页面决定。
  • 重复激活、退出、禁用、重新启用不累积监听和资源。能力禁用后的导航回落沿用现有 Chat 行为。

实施边界

两名 Luna 开发 agent 分别负责 desktop 与 web 产品代码，独立 Luna 测试 agent 负责行为验证。主 agent 负责契约、差异审查、模块 HTML 与测试记录收口。每个通过验证的切片单独提交；阶段 4 的后端改造由另一任务负责，本批不修改其文件。
