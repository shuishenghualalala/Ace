1. 设计原则

  • 黑白极简：白底，文字与边框走灰阶，强调色只用黑色，不出现大块彩色。
  • 结构清晰：三栏布局（会话 / 对话 / 任务板），组件单一职责，无状态管理库。
  • 零额外依赖：不引 UI 组件库 / CSS 框架，纯手写 CSS（一个 global.css + markdown.css），便于同事维护。Markdown 渲染使用 react-markdown。
  • 复用后端契约：完全沿用已有 WebSocket /ws 与 REST，前端不发明新协议。

4. 数据流

用户输入 ─▶ Composer.onSend ─▶ App.handleSend ─▶ useChat.send()
        ─▶ ChatSocket 发 {query, session_id, mode, attachments} 到 /ws
后端流式回 Chunk ─▶ useChat.handle()：先按 chunk.session_id 路由到对应会话的桶，再处理：
   kind=thinking ─▶ 追加到该会话当前 assistant 消息的 thinking 字段
   kind=tool     ─▶ 按 tool_call_id 聚合 start/result 事件，更新 ToolCallInfo
   kind=status   ─▶ 含"排队" → 写该会话 queueHint（队列卡片）；其它（Team 派发）→ 状态斜体行
   kind=final    ─▶ 写助手消息（含 toolCalls/thinking），重置该会话聚合，结束 busy，刷新会话列表 + 任务板
   kind=error    ─▶ 追加错误行，置该会话状态为 error
切换会话 ─▶ 直接取该会话的桶渲染；无缓存时 GET /api/session/{id} 回放历史
切换模型 ─▶ TopBar select ─▶ POST /api/config/model ─▶ 后端重建 Provider
Team 模式 ─▶ 右侧 TaskBoard 轮询 GET /api/tasks/{id}
附件上传 ─▶ POST /api/upload → 附件元信息 → 随 WS 发送
@引用补全 ─▶ GET /api/complete?query= → 文件/文件夹列表 → 选择后注入附件

7. 如何扩展（给前端同事）

  • 加一种消息渲染：在 types.ts 的 MsgRole 加类型，在 MessageItem.tsx 加分支，global.css 加对应样式。
  • 加一个面板：仿 TaskBoard 写组件，在 App.tsx 接一个开关 state，.app 的 grid 列宽同步。
  • 对接新端点：在 api.ts 加一个方法即可，组件用 hook 调用。
  • 原则：样式只进 global.css/markdown.css（用 CSS 变量），不内联大段 style，不引第三方 UI 库。
