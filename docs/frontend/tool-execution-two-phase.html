Tool 执行两阶段前端渲染

后端工具执行拆成两个阶段：

  • generating：模型已经决定调用某 tool，正在生成参数；前端应立即渲染出工具卡片，给用户「已开始处理」的反馈。
  • start / result：参数就绪并真正执行，最终返回结果；前端更新为 running → done/error，并展示耗时。

该文档记录 Web 与 Desktop 两端的状态映射、本次改动点与排查思路。

1. 协议事件

后端通过 WebSocket 推送 { kind: "tool", body: { phase, tool_call_id, name, ui_label, args, detail } }。

phase含义前端状态
generating模型生成参数中status: "generating"
start参数就绪，开始执行status: "running"
result执行成功返回status: "done"
error执行失败status: "error"

2. Web 端

2.1 状态机

  • 文件：web/src/hooks/useChat.ts
  • 新增纯函数 applyToolChunk(toolMap, body, now, fallbackId)，负责把 tool 事件应用到 toolMap，保持状态流转可单测。
  • 关键修复：generating 阶段新条目状态从错误的 "done" 改为 "generating"。
  • generating → start 保留最早的 startedAt，使最终 duration 覆盖「决定调用 → 执行完成」全过程。

2.2 UI 组件

  • ToolCallCard.tsx：running/generating 用 SVG 旋转动画图标替代静态 ⏳，并实时显示已运行秒数。
  • AgentProcessTimeline.tsx：时间线工具标题增加状态后缀（完成/失败），file_write 生成/运行时显示「写入 xxx…」并显示实时耗时。
  • utils/time.ts：新增 formatDuration 与 useElapsed，供上述组件共用。
  • styles/global.css：新增 .tool-card__spinner 旋转动画与 .process-timeline__icon--running 脉冲动画。

2.3 测试

  • useChat.test.ts 新增 applyToolChunk 单测，覆盖 generating → start → result 完整流转、duration 计算与 error 分支。

3. Desktop 端

3.1 状态机

  • 文件：desktop/src/ui/reducers/chat-reducer.ts
  • reducer 原有逻辑已正确区分 generating/running，并保留 startedAt。本次未改变状态映射，仅补充单测锁定行为。

3.2 UI 渲染

  • chat-render.ts：running/generating 工具卡片使用 SVG 旋转动画图标；通过全局 250ms interval 轮询 [data-active] 时长标签，实现实时耗时更新。
  • assets/styles/stream-chat.css：新增 .tool-card__spinner 旋转动画。

3.3 测试

  • 新增 chat-reducer.test.ts，覆盖 toolReducer 的两阶段流转与 duration 计算。

4. 排查清单

  • 工具卡只在 result 后才出现 → 检查 applyToolChunk / toolReducer 是否把 generating 状态正确设为非 done。
  • 运行中没有动画 → 检查 CSS 是否引入 tool-card__spinner 动画，组件是否正确输出 running 状态。
  • 耗时显示 0 或巨大数字 → 检查 startedAt 是否在 generating 阶段正确写入，且 result 阶段用同一 tool_call_id。
  • Web 与 Desktop 状态不一致 → 对照本节「协议事件」表，确认两端 generating/running/done/error 映射一致。
