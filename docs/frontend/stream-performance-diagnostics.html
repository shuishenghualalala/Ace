流式首 token 性能诊断

该诊断用于区分模型 TTFT、Ace 网关转发和桌面端渲染耗时。埋点只记录时间、请求标识和请求规模，不记录 prompt、回答正文或密钥。

开启方式

  1. 桌面端 DevTools Console 执行 __mmStreamDebug.enable()，然后刷新页面。
  2. 发送一条消息，执行 __mmStreamDebug.dump() 查看最近事件，按同一个 request_id 串联。
  3. 关闭时执行 __mmStreamDebug.disable()。

关键事件

  • dispatch / send-ws：桌面端发起时间。
  • gateway_request_received：网关接收时间。
  • llm_first_event：provider 首个流事件，包含模型首 reasoning、正文或工具事件类型。
  • llm_first_text：provider 首个正文增量。
  • gateway_first_push：网关完成首帧 WS 推送。
  • ws-renderer / proxy-event-message：桌面端收到 WS 帧。
  • ttft-first-visible-text：前端收到首个有效正文。
  • ttft-first-dom-patch：前端首次将正文 patch 到 DOM。

判读

  • llm_first_event 本身很慢：主要是模型/上游服务或请求负载问题。
  • provider 首事件很快、gateway_first_push 明显变慢：检查网关发送限流或连接状态。
  • 网关已 push、前端收到很快但 DOM patch 变慢：检查渲染主线程或 Markdown 增量渲染。
