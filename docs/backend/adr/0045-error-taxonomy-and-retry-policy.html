ADR-0045 · 错误类型化与统一重试策略

状态：已批准 · 日期：2026-09-17 · 批次：agent-core-defects 批次 0。

背景与候选方案

现状：Ace 错误以字符串消息 / 通用异常传播，重试判定散落在多处且彼此不一致：

  • crew/agent/providers/openai_provider.py 与 anthropic_provider.py 各持一份字符串类名启发式重试判定（_is_retryable / _error_category），同一错误在两家的分类结论可能不同；
  • loop/resilience.py:147 还有第三份类名白名单，调用点绕开 provider 时完全无类型信息可用；
  • 429 / 503 响应的 Retry-After 在包装成 ProviderError 时被丢弃（连 status 都没存），重试退避只能盲算指数；
  • ResponseChunk.error 预留的 code 参数无人使用，错误帧只有自由文本 message。

候选方案：

A. 全仓 40+ 个模块自建异常统一迁入 CrewError 层级——否决：改动面爆炸（40+ 模块的 raise/catch 点、跨边界序列化面），与本项收益不成比例；本 ADR 只收敛 LLM / 工具 / agent 主路径，其余模块留待各自批次。

B. 维持 ProviderError.retryable 布尔 + category 字符串——否决：category 是自由字符串，消费方无法穷举判定（字符串拼写漂移即静默行为变化）；retry_delay 无处安放；白名单分散问题原样保留。

C.（选定）CrewErrorKind 枚举 + kind/status/retry_delay 字段 + 类级 RETRYABLE_KINDS 白名单 + provider 层统一分类助手：判定收敛到一处，枚举穷举可静态检查，Retry-After 不再丢失。

决定

  • CrewErrorKind 枚举：crew/core/errors.py 扩展 CrewErrorKind：stream / timeout / context_window_exceeded / usage_limit / quota / server_overloaded / auth / forbidden / unsupported_capability / tool / config / cancelled / internal / unknown。unknown 兜底，枚举穷举保证新错误不会静默落入错误分支。
  • 统一重试白名单：CrewError.is_retryable() 按 kind 判定，类级 RETRYABLE_KINDS 常量一处维护，仅 stream / timeout / internal 可重试；server_overloaded 与 quota_exceeded 不可重试——overloaded 状态下对同一服务重试无意义（压测式重试只会加重过载），欠费重试不会恢复额度；429（usage_limit）由分类器显式携带 retryable=True 保留限流退避语义，是白名单之外的唯一例外。调用点不再各自做类名启发式。
  • ProviderError 扩展：增 kind / status / retry_delay；category 保留为兼容别名（映射到 kind 的同名字符串），旧消费方不破坏。重试时优先使用 retry_delay，指数退避只作为无 retry_delay 时的兜底（封顶）。
  • provider 统一分类助手：openai / anthropic provider 共用一份分类逻辑——HTTP status + 错误体解析为 kind；Retry-After 解析为 retry_delay（header 优先，body 的 retry_delay 字段兜底），429 / 503 时随 ProviderError 一并携带。resilience.py 的类名白名单废弃，改读 kind。
  • error 帧：ResponseChunk.error 带 {kind, retryable, retry_delay} 结构化 body（code 参数投入使用），不再只有自由文本。
  • 工具层不加自动重试：工具失败语义由 agent 主循环裁决（可见、可恢复），本 ADR 不引入工具级自动重试。
  • 语义对齐声明：kind 枚举 + is_retryable() + retry_delay 的设计语义与 codex protocol/src/error.rs 的 CodexErr / is_retryable() / retry_delay() 一致（错误类型化、可重试判定、服务端建议退避时长的三件套）。

跨平台影响

纯 Python 枚举类型与 header/body 解析逻辑，不触碰平台相关系统调用，mac / linux / windows 三平台无差异。

回退方式

category 兼容别名保留，旧消费方（读 category / 自由字符串路径）在迁移窗口内不破坏；回退 = revert 对应 commit，重试白名单与分类助手整体撤销后旧的类名启发式不再存在——故回退动作需在同一批次内整体完成，不做部分回退。
