ADR-0042 · 会话存储增量事件表（session_events，W4/W5）

状态：已批准，W4 已实施（W5 树形与恢复待做） · 日期：2026-09-14 · 批次：dsh-remediation W4（存储）/ W5（树形与恢复）。

背景与候选方案

现状：sessions 表把整条消息列表序列化为一个 JSON blob 存 messages 字段——每回合 json.dumps 全量重写（O(历史大小)）、load 全量 json.loads 逐字段重建；无增量 append、无分页、无树形/回退/fork、无回合级崩溃恢复语义；token 估算全程 chars/4 粗估，压缩水位判断误差大。W0 已把 save/load 包 to_thread 止血（消除事件循环冻结），但写放大与能力缺口未解。

参照系结论（dsh / pi v3·v4 / codex 三方源码对照，详见 docs/todo/ace-weaknesses-dsh-remediation-plan.md §1.2–1.3）：三家都以 append-only 日志为格式根解法；Ace 选 SQLite 后物理防撕裂整体免写（事务原子性），真正要拿的是数据模型（parent 树 + leaf 指针）、多进程租约（pi v4 writer_leases）与语义修复（孤儿合成，W1 已落地配平扫描）。

候选方案：A. 保持 blob + 全异步化——止血已做，但每回合写放大依旧，分支/恢复能力永远欠着；B. JSONL append-only 文件（pi v3 式）——本地 CLI 的取舍，服务端多进程/多租户下无锁互斥与撕裂恢复都要自建，放弃 SQLite 事务优势；C. SQLite 增量事件表 + per-session 单写队列 + leaf 指针。

决定

采用方案 C。分两个批次：W4 做存储格式与计量，W5 做树形与恢复。

  • 表结构（W4）：session_events(owner_account_id, session_id, seq INTEGER, type TEXT, payload JSON, created_at)，主键 (owner, session, seq)，seq 会话内连续；sessions 表加 leaf_seq 指针列，元数据轻量化。数据边界声明：session 是 core 域（sessions 本在主库 9 表清单内），session_events 作为 core 状态表进 crew.db，不破坏 ADR-0038「主库无 Feature/插件表」终态。
  • 写路径（W4）：每回合只 INSERT 本回合新事件（O(新事件)），经 per-session 单写队列（一个写 task + asyncio.Queue）串行落库——对应 dsh 的 per-handle promise 链；不再有全量 dump。
  • 读路径（W4）：按 seq 流式读行 + per-session 内存投影缓存（derive_messages 等价物：只解析自上次以来的新事件，O(增量)）。
  • 多进程互斥（W4）：gateway 与 CLI 可能打开同一会话，sessions 侧加 writer 租约（模板取 pi v4 SQLite 后端 writer_leases：TTL 30s + 心跳 10s + fence 抢占，进程崩溃后 TTL 到期自动可接管）。
  • 兼容迁移（W4）：保留旧 blob 列，一次性迁移脚本逐会话导入为事件行；读取端双格式兼容一个版本窗口后删旧列。该兼容 Adapter 创建时即声明 deprecated_after（目标删除版本）与消费者清单，窗口关闭条件写进批次记录。
  • TokenMeter（W4）：per-session 增量计量——锚点 = 最近一次真实 usage（复用条件：请求信封一致且 usage ≥ 锚点启发式估价），锚后 delta 按 chars/4 保守累加；接口返回三值 {exact|estimated|none}，精确/估算/零值从不混淆；compact/tokens.py 的水位判断改消费它。
  • 树形（W5）：事件加 parent_seq（可空，默认前一条）；回退/rewind-and-edit = 校验目标 seq 合法（不在开放回合中）→ 移 leaf 指针，旧分支保留可回；fork/clone = 复制前缀 + 切口写 end_seed 型标记。
  • 崩溃恢复（W5）：会话加载后跑配平扫描（W1 的 repair_orphan_tool_calls 直接复用）；启动时扫描各会话开放回合向用户报告断点（「上次会话在第 N 步被中断」，断点报告不自动续跑）；未知事件类型 fail-closed 拒绝加载。
  • checkpoint 收敛（W5）：processes.json / tasks 表等多份 checkpoint 统一恢复入口；未来检索索引定位为可弃读模型，损坏即重建。

验收要点

  1. 断言每回合 INSERT 行数 == 本回合新消息数（写放大 O(新事件)）；
  2. kill -9 注入中途崩溃 → 重启后会话可加载、孤儿 tool_call 有合成结果、下一轮 LLM 请求不报错；
  3. rewind 后旧分支可导航回来；leaf 指针移动不改写任何已存在行；
  4. token：有真实 usage 的会话测量 kind=exact 且与 usage 一致；无 usage 时 kind=estimated/none，绝不伪装精确；
  5. 迁移幂等：重复执行零重复行；旧 blob 列在窗口期内可回退读取；
  6. writer 租约：两个进程打开同一会话时后者被拒绝或抢占（fence 防脑裂）；
  7. 全量测试 0 failed（不含基线 flake）。

不照搬

zstd 帧压缩与世代迁移链（SQLite 行追加天然免整文件压缩）；按 cwd 目录分组 + 无超时 flock（多租户服务端按 owner 维度 + 租约/超时）；dsh「回退=遮蔽投影」的完整语义（首期用 parent 树 + leaf 指针，遮蔽只在压缩里用）；pi/codex 的「完全不 fsync」（WAL 默认持久性语义即可）；codex 的 Copied/Referenced 双轨 fork。

codex 对照修订（2026-09-14）

对 codex-rs（rollout/recorder、thread-store/local/{live_writer,writer_lock,revert_thread,paginated_fork}、context_manager/normalize、session/rollout_reconstruction）源码精读后的吸收结论：

  • flush barrier 语义：leaf 指针与投影推进必须 await 单写队列 flush 的 ack 往返；写失败保留队列重试一次；投影允许滞后、禁止超前（SQLite 投影即可重建视图）。leaf 的 UPDATE 要么与事件批次同事务，要么在 barrier 之后单独提交。
  • writer 互斥选型修正：确认选 pi v4 式 SQLite writer_leases（TTL 30s + 心跳 + fence），不选 codex 的 flock（劝告锁、无 fence、无 TTL，服务端多进程下无法区分「持有者已死」与「只是慢」）；原子取租用条件 UPDATE + rows_affected，每批写入校验 fence 吊销慢进程旧写入。
  • compaction 事件自包含：单行内联完整 replacement payload + 窗口代际元数据 + 重锚定 token 估算；事件表只增不改，旧 checkpoint 永不覆盖；恢复 = 定位最近 checkpoint seq 后正序重放（一条 SQL 可得），无需全表反向扫描。
  • 分支指针模型：分支/回退指针存 (source_session_id, parent_seq) 二元组；指针切换用 UPDATE ... WHERE head_seq=? 的 CAS，affected≠1 即 Conflict 并回滚；fork 在行模型下 O(1) 不复制行（优于 codex 的文件前缀引用）；字节偏移在行模型下禁止作为指针。
  • 孤儿合成 id 规范：固定 namespace 常量 + 类型前缀 + 源调用唯一 id 派生（不用随机 id），模型可见文案逐字固定，幂等读时合成不落表（codex normalize.rs 语义；W1 已落地初版，W5 对齐此规范）。
  • TokenMeter 锚点：usage 快照作为 meter_checkpoint 事件追加；compaction 事件内联重锚定估算；delta 计算 max(0) 钳制；保留真实累计值，禁止用 context_window 整数值覆盖（codex 的 fill_to_context_window 是展示层妥协，不学）。
  • 配平游标对账：projected_seq 等游标遇缺口必须报错重试，不可静默跳过；游标与数据单事务推进；批次写入以 (session_id, seq) 唯一约束兜底去重。
  • SQLite pragma 基线：WAL / synchronous=NORMAL / busy_timeout≥5s / auto_vacuum=INCREMENTAL（仅新库）；禁止启动时 VACUUM；compaction 只逻辑截断（leaf 前移）不物理删除旧事件。
  • durable/transient 事件分类：事件类型枚举标注是否落盘，瞬态事件（错误、进度、队列变化）不写 session_events。
  • 读一致性边界：读者以 leaf/head_seq 快照读取（WHERE seq <= head_seq）；游标绑定 session_id 校验防串会话；写者推进 leaf 不影响读者。

明确排除（文件存储特有、SQLite 事务模型下无对应问题）：逐行 flush / torn-tail 补换行 / 坏行跳过 / 压缩文件物化 / 文件系统扫描双通道列表。

实施订正与批次记录

W4 存储批次（2026-09-14，分支 fix/dsh-w4-session-events）已落地 D1a–D1e 与 D6，实施中的订正如下：

  • events_generation 代际列（D1c 新增）：sessions 表在 leaf_seq 之外增加 events_generation，事件流被整体重写（调用方改写历史）时 +1。仅 leaf 游标无法区分「正常追加」与「跨进程整体重写」——读者会把新尾部增量拼在已过时的前缀上。读者按 (leaf_seq, events_generation) 快照对账：代际变化即全量重建投影。追加路径零成本。
  • 双格式窗口的双写成本（D1e 声明）：窗口期内 save 同时维护事件行与旧 blob 列（同事务），blob 重写是窗口的回退成本；读取端 read_mode="blob" 可紧急切回纯 blob 读取。兼容 Adapter 声明：deprecated_after = v1.3.0；消费者清单 = SQLiteSessionStore.load/load_child_sessions/load_async 读取端、runtime.py 冷读配平、gateway sessions router、channel sessions、Team 子会话聚合（load_child_sessions）；窗口关闭条件 = W5 树形批次上线后观察一个版本窗口（v1.2.x 全周期）且 blob 回退路径验证无回归，于 v1.3.0 删除 messages 双写与 blob 读取回退。
  • 租约心跳挂在单写队列 task 上（而非独立 per-session task）：队列空转超时即批量续约本进程持有的全部租约，少一类后台任务；close() 释放本进程全部租约。
  • schema_version 登记：sessions 域按主库 schema_version 机制 stamp 基线 v2（v1 = 单表 blob）；表结构演进仍走 sessions 自有的幂等 ALTER/PK 重建迁移。

批次 commit 记录：D1a schema 与 pragma 基线 → D1b 写路径单写队列 → D1c 读路径投影缓存 → D1d writer 租约 → D1e 兼容迁移 → D6 TokenMeter。

回退方式

双格式窗口内旧 blob 列保留不删，读取端配置切回 blob 模式即原地回退；窗口关闭（删旧列）前所有回退路径可用。每批次独立提交可 revert。
