ADR-0031 · Team Feature 生命周期

状态：已实施并验证 · 日期：2026-09-09 · 阶段：4C-1。

背景与候选方案

CrewApp 直接在组合根构造 InProcessTeamManager，并通过单独的桥接 Scope 注册 mode=team Driver。Manager 的生命周期、owner Provider 缓存与 Driver 注册分散在宿主和桥接代码中，停用/更新时无法保证 Manager 与 Driver 同代，且 app.team 在停用后仍可能指向已关闭实例。

决定

由模块自身声明 product.team Feature Bundle，统一拥有 InProcessTeamManager、mode=team Execution Driver 与 ServiceKey("team") 服务。宿主通过 build_team_feature() 构造 Bundle，按需同步激活并 declare_managed_feature() 纳入 Runtime 审计。

Bundle 安装时先注册 manager.shutdown() 资源清理器，再注册 Driver 与 Service；激活失败时 Runtime 按 LIFO 回滚。Manager 新增 shutdown() 方法设置 _closed 标志、取消在途 delegate/recovery 任务并关闭内部资源；interact() 在关闭后拒绝新请求。停用/更新由 Feature Runtime 的 drain/restart 策略驱动，保证在途请求完成后再切换 Generation。

App 级 owner Provider 缓存继续由 CrewApp 维护，但通过 provider_for_owner / provider_for_member_model 可调用对象注入 Manager；Manager 内部也保留同代缓存，避免重复解析。模型切换时宿主调用 manager.invalidate_owner_provider()，同时清空 App 与 Manager 缓存。测试兼容路径 set_team_manager() 保留，用于直接注入 Manager 实例，但不再由生产装配使用。

兼容、验证与回退

生产装配 build_app(enable_team=True) 验证 product.team 处于 ACTIVE 状态、mode=team Driver 可用、app.team 指向同代 Manager；enable_team=False 时 Feature 未声明且 Driver 不存在。Wiki 在 enable_team=False 模式下仍可通过 set_team_manager() 注入旧 Manager，回归通过。

新增 7 项生命周期契约测试覆盖激活/停用、更新换代、shutdown 幂等、停用后请求 fail-closed、生产装配与 disabled 模式；相关 Team 任务回归、external/team/gateway/runtime 组合回归未引入新失败。Ruff、compileall、Import Linter（6 contracts kept，0 broken）全部通过。

停用不删除 Team 业务数据；回退本切片可恢复桥接装配行为，但 4C-1 之前的代码已在当前分支被后续提交覆盖，回退需整体撤销本 commit。
