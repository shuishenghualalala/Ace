ADR-0050 · Subagent Stage D6：Continuable 收尾

状态：已实施 · 日期：2026-09-18 · 分支：codex/subagent-multiagent-upgrade · 前置：ADR-0048。

背景

D1-D5 已提供持久身份、隐藏会话、Activation 锁、持久邮箱和控制面，但冷恢复仍需要更严格的身份证明；运行状态也没有对外投影，后台任务只能单向关联 task，Web 只能观察而不能控制。

决定

问题决策
冷恢复授权恢复请求同时核对 run、descriptor 和当前请求中的 owner_account_id、直接 parent_session_id、subagent_id；descriptor 身份不一致时 fail-closed。
驻留状态Activation 状态由 running 标志和持久 inbox 派生为 running、ready、idle，通过 activation_running/ready/idle lifecycle event 投影。
任务账本后台任务创建时预分配 continuable subagent_id，写入 task progress；结算和 collect 结果保留 task_id 与 subagent_id。
Web 控制新增 owner-scoped POST /api/subagents/{id}/message 与 POST /api/subagents/{id}/interrupt，复用 Runtime 控制面，不在路由层复制授权逻辑。

关键路径

Web Activity Card
  ├─ GET /api/subagents?session_id=parent
  ├─ POST /api/subagents/{id}/message?session_id=parent
  └─ POST /api/subagents/{id}/interrupt?session_id=parent
          │ owner-scoped
          ▼
SubagentRuntime
  ├─ persisted identity proof → resume / reject
  ├─ Activation state → lifecycle event
  └─ task_id ↔ subagent_id → progress / collect / settlement

边界

  • one-shot 子智能体不创建 Activation，也不产生 activation 状态事件。
  • HTTP 控制接口要求显式 parent session；错误身份返回拒绝或不存在，不泄露其他 owner 的运行信息。
  • 脚本编排引擎仍不在本方案范围内。

验证

D6 专项覆盖冷恢复伪造 descriptor 拒绝、Activation 事件顺序、task/subagent 双 ID 账本、HTTP 控制入口和 Web 状态归并。
