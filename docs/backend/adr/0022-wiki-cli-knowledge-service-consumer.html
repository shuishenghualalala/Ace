ADR-0022 · Wiki CLI Knowledge Service Consumer

状态：Accepted · 日期：2026-09-05 · 阶段：插件架构 3B

背景

Wiki Gateway 已只消费 KnowledgeService，但 crew wiki 仍直接读取 App 上的 Store、Compiler、Querier 和 Session Manager，并在 CLI 内部处理 Wiki 数据目录、文档解析与媒体文件。这会把 Local Provider 的实现细节固化到 Host，也无法保证一次长命令所使用的 Provider 在 Feature 重启期间保持存活。

决策

全部 Wiki CLI 叶子命令在执行时动态取得当前 KnowledgeService 与同一 Generation 的 Lease；命令只消费稳定服务操作，Provider 的存储、解析和媒体处理不再进入 CLI。
  • 注册 Wiki 命令时统一包裹 Service Gate。能力缺失或进入 draining 后，新命令统一抛出 CliError("Wiki 未启用")；Skill 命令保持独立。
  • 同步 Handler 在返回或异常的 finally 中释放 Lease；异步 Handler 在完整 await 周期使用异步上下文持有 Lease。每次命令重新解析当前 Generation，不缓存 Service。
  • 没有 product.wiki 记录的嵌入宿主可以注入外部 knowledge_service；产品 Feature 已存在但不可用时，不允许回退到旧外部对象。
  • KB、页面、来源、搜索、ingest、compile、graph、query、lint 与 confirmation 均通过类型化 Service 操作完成。
  • CLI 只用 pathlib 读取用户明确传入的上传文件；文档解析、媒体理解、原始文件和 Wiki 数据目录都由 Provider 负责。
  • Wiki Agent 会话继续使用 Host 拥有的 SessionStore，但对应命令同样先经过 Knowledge Service Gate。

结果与后续

CLI 已成为 Provider-neutral Consumer，Feature 更新后新命令可直接选择新代，旧代等待在途异步命令结束后再关闭。Agent Preset、Event、Route 与 UI Contribution 仍是 Stage 3B 后续切片；Work 的可选 Knowledge Service 依赖归 Stage 3C。

跨平台

CLI 文件入口使用 pathlib.Path 和字节内容，不新增 shell 命令、平台固定目录分隔符或操作系统专属生命周期机制；Provider 接口在 macOS、Linux 与 Windows 使用同一参数和结果协议。
