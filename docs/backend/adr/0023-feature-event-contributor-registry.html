ADR-0023 · Feature Event Contributor Registry

状态：Accepted · 日期：2026-09-05 · 阶段：插件架构 3B

背景

feature_event 已提供稳定命名空间和旧帧出口适配，但 Wiki cards/changes 的生产仍写在 Gateway WebSocket runner 中，并直接读取 WikiSessionManager。事件信封虽然中立，事件来源、资源生命周期和 Generation 选择仍没有归属 Feature。

决策

建立中立的 FeatureEventContributorRegistry：事件来源由 FeatureScope 注册，Registry 按确定顺序在所属 Generation Lease 内生成并投递，Gateway 只提供标准事件 sink。
  • FeatureEvent 固定承载 feature/event/version/payload，中立 Registry 不包含任何 Wiki 名称或旧 ChunkKind。
  • Contributor 注册返回 Scope-owned Token；只有 Active Generation 可见。同一 contributor ID 在 replace 期间选择最新 Active Generation，draining 后拒绝新 dispatch。
  • 同步或异步 Handler、predicate、priority、timeout 和 DEGRADE/FAIL 策略属于显式契约；失败形成结构化报告或 fail-closed 错误，取消继续传播。
  • dispatch(envelope, sink) 在 Lease 内顺序调用异步 sink。Contributor 失败遵循自身策略；sink 投递失败原样传播并停止后续来源，避免把 Host 传输错误误记为 Feature 降级。
  • Wiki Bundle 注册 wiki.session.cards 与 wiki.session.changes 两个同代来源。cards 优先投递；若其 push 失败，changes 尚未被摘取，保持既有待处理事件语义。
  • WebSocket runner 仅 dispatch 中立 Registry 并发送标准 feature_event；连接已断开时不 dispatch，旧帧转换与 replay 继续由 Gateway 出口适配器负责。

结果与后续

Wiki 事件来源现在随 Bundle 激活、替换、回滚和停用自动注册或撤销；旧代在途投递结束前不会提前关闭。Stage 3B 仍需迁移 Agent Preset、Wiki API Route Contribution 与 UI Contribution；Work 的可选 Knowledge Service 依赖留在 Stage 3C。

跨平台

Registry 只使用 Python 类型、asyncio Lease 与内存事件，不依赖路径、信号、socket 绑定或操作系统命令，在 macOS、Linux 与 Windows 使用相同语义。
