ADR-0047 · Subagent Stage C：Feature 生命周期收口

状态：已批准，阶段 C 已实施 · 日期：2026-09-17 · 分支：codex/subagent-multiagent-upgrade · 前置：ADR-0045、ADR-0046。

背景

阶段 B 已建立 Subagent 的语义 Runtime、持久账本、四态通知和批量调度，但 build_app 仍直接构造 Store、Runtime、ActiveSubagents、通知队列和工具。这样工具、路由、事件和后台任务没有共同的 Generation，也无法通过统一 Feature Runtime 做停用、重启与代际租约。

决定

  1. 以 product.subagent 作为唯一 Subagent Feature ID。它必需依赖 core.agent-factory，提供 ServiceKey("subagent")，策略为 stop=DRAIN、update=RESTART、required_by_product=false。
  2. Bundle 每个 Generation 自己构造并关闭 SubagentRuntime、ActiveSubagents、SubagentStore 和后台任务。Store 继续使用既有 subagent.db、WAL、legacy copy-on-first-activate 与保留期配置。
  3. 工具注册通过 Feature-owned disposer 进入 Registry，并在 handler 外层持有 Generation Lease；通知 context、lifecycle event、preset contribution 与 product.subagent route 同属该 Scope。
  4. Gateway 只在启动装配时挂载 Route Registry 的稳定路由对象，运行期由 route gate 和 service lease 选择当前代；GET /api/subagents 返回当前 owner 的 active snapshot 与历史 runs。
  5. Runtime 只发布与 Feature 无关的生命周期记录，Bundle 在事件贡献者中转成版本化 feature_event(feature="subagent")，并按 parent session 一次性 drain。
  6. 保留 CrewApp.subagent_* 作为兼容视图。组合根只负责创建 Registry、读取 Config、按依赖顺序激活 Bundle；不再手写 Store、Runtime 或工具注册。

装配顺序

core.agent-factory
        │
        ▼
product.wiki  ── claim Wiki preset
        │
        ▼
product.subagent ── own runtime/store/tools/context/events/routes/presets
        │
        ▼
product.external-agents ── optional Subagent Service consumer

Wiki 在 Subagent 前认领自身 preset，避免通用 preset Registry 发生所有权冲突；external-agents 在 Subagent 后激活，确保其 owner-aware Provider resolver 只依赖稳定服务契约。

生命周期不变量

不变量保证方式
停用不接收新请求FeatureScope 进入 draining；工具、路由、服务租约都从同一代 admission boundary 获取。
在途请求可完成工具 handler 和 route gate 在请求边界持有 generation lease，DRAIN 等待释放后再清理。
旧代不误删新代Registry、Route Registry、Preset Registry 与 disposer 均按 Generation/对象 identity 精确撤销。
资源关闭顺序稳定贡献先撤销，后台任务与 Runtime/Store 再按 Scope resource phase 关闭。
事件不重复Runtime 按 owner/session 入队，Feature Event contributor 原子 drain；同一回合第二次 dispatch 得到空集合。

后果

Subagent 现在可以被统一能力诊断、停用和重启，新增消费方只依赖 SubagentService。组合根的兼容字段仍存在，因此旧 CLI、工具测试和中断链路无需同步重写。Bundle 的 route/event 贡献需要在 Gateway 构造期注册，FastAPI 路由树本身仍不在运行期物理增删；可用性由 Registry gate 表达。

验证

Stage C 专项与核心 Feature 测试：11 passed。子智能体既有定向回归：150 passed，2 warnings。专项测试覆盖 Feature event 版本化/一次性 drain、真实 Gateway route、owner 隔离、兼容视图清理、停用后的 Store/Runtime 释放以及生产装配记录。
