ADR-0019 · Browser Host-loop Feature

状态：Accepted · 日期：2026-09-04 · 阶段：插件架构 3A

背景

Browser 已通过目录插件 Scope 拥有 Tools、Skill、Context Contributor 和 BrowserManager.aclose()，但 Manager 的 startup() 仍由 CrewApp 手写调用。目录插件又在同步构造桥的短命事件循环中激活，不能直接在那里创建长期 idle/prepare Task；CrewApp.browser_manager 还是一次性对象快照，restart 后会过期。

决策

目录插件 manifest 增加 activation_phase。默认 build 保持兼容；Browser 使用 startup，Definition 先 discover，再由宿主事件循环通过同一 FeatureRuntime 激活。
  • Browser 注册器改为异步：先登记 aclose() disposer，再启动 Manager，随后发布 browser.manager Service、五个 Tools、Skill Root 和标签页 Context Contributor。
  • CrewApp.browser_manager 每次解析当前可见 Service；显式注入仅用于嵌入宿主和测试。
  • update_plugin_async() 用 restart 策略切换 Generation，失败时由旧 Definition 恢复。
  • pre-activation unload 会抑制后续 phase 激活；重复 unload 保持返回 false。
  • Gateway Browser Router 动态读取 Manager，并以 Browser Tool 是否可见作为 API Gate；路由本体迁入 Route Contribution 留在后续纵向切片。

结果

CrewApp.startup() 不再直接认识 BrowserManager。idle/prepare Task、Owner、Session、Tab、Page 与 Driver/Host 进程最终由同一 Generation 的 aclose() 回收；旧 disposer 不会清除新一代 Service。

跨平台

新增控制面只使用 asyncio、manifest 数据和 Feature Service Registry。BrowserManager 原有 Electron/Playwright 平台实现及 Windows/macOS/Linux 资源关闭路径保持不变。
