ADR-0018 · Sites Runtime Feature

状态：Accepted · 日期：2026-09-04 · 阶段：插件架构 3A

背景

Sites 原由 build_app() 构造 Manager、两类 SQLite Store、五个 Tools 和两个 Capability Profile，再由 CrewApp.startup()/shutdown() 单独启停 Blueprint Scheduler。贡献和资源分属不同清理路径，无法独立更新或停用。

决策

product.sites 使用 restart Generation，统一拥有 SiteManager、SQLiteSiteStore、BlueprintStore、Blueprint Scheduler、五个 Tools、两个 Capability Profile 与 Host Binding。
  • 每个 Definition 预建独立候选 Manager；失败重试创建新 Manager，不复用已关闭 Store。
  • Tools 与 Capability Profile 由稳定 identity 注销；旧 Generation 的 disposer 不会删除新一代贡献。
  • Tool handler 自动持有 Generation Lease，停用策略为 cancel。
  • 停用先撤销贡献，再停止 Scheduler 并关闭两个 Store；SQLite 数据不删除。
  • Gateway Router 每次从 crew.sites 解析当前 Manager。HTTP Route Contribution 留给后续纵向切片。
  • 显式注入的外部 Manager 可参与启停，但其 Store 不由 Feature 关闭。

结果

CrewApp.startup()/shutdown() 不再认识 Sites 具体 Manager；激活失败由事务回滚，restart 能原子切换 Host Binding 和运行贡献。Store 连接生命周期与 Scheduler 首次进入同一 Scope。

跨平台

生命周期层只使用 asyncio、对象 identity 与现有 SQLite 抽象，不引入 POSIX 信号、文件描述符或路径假设；原有 Site 构建器的 Windows/macOS/Linux 命令解析保持不变。
