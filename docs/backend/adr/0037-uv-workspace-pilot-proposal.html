ADR-0037 · uv workspace 首个试点（crew-wiki）提案

状态：试点与第二批已实施（2026-09-11 crew-wiki / 2026-09-12 crew-external-agents，本地全量验证通过；Docker build/CI 矩阵/打包态待远程验证） · 日期：2026-09-11/12 · 阶段：6。

背景与候选方案

workspace 评估报告（ace-workspace-split-assessment.md）确认 uv workspace 多包化可行，并列出 6 项必修逻辑拆分。截至本 ADR 撰写时，6 项已全部解除并有 9 条 import-linter 契约保护：① state→team/external（6I）、② team→external 数据耦合与 Store 继承（6G/6G-2，ADR-0036）、③ wiki→gateway 私有导入（6J）、④ state→browser 类型（6K）、⑤ gateway 协议设施下沉（6L）、⑥ executor→external 直连（6M）。ServiceKey 版本化（6N）进行中。

候选方案：A. 直接全量拆包（8 个成员包一次到位）——回退面大、CI/Docker/桌面打包链路一次冲击；B. 单包试点（crew-wiki）先行，验证四条交付链后再逐批拆；C. 暂不物理拆包，仅维持契约——放弃包管理器物理强制的收益。

决定（建议）

采用方案 B。试点成员 crew-wiki（评估报告 §5.2 论证：演进计划指定的首个 Feature Bundle 试点、不占 crew.db、依赖最干净、契约测试就位——6A 的 KnowledgeService 契约套件即其包级验收门禁）。

  • 目录：packages/crew-wiki/pyproject.toml + packages/crew-wiki/src/crew/wiki/（整个 crew/wiki/ 原样迁入）；发行版间 import 名保持 crew.*（评估报告：Dockerfile.pack、desktop spawn PYTHONPATH、PyInstaller spec 改动最小化的前提）。
  • 根 pyproject 增加 [tool.uv.workspace] members = ["packages/*"]；根包继续拥有其余模块；uv 单锁（uv.lock 共享）。
  • 依赖声明：crew-wiki 依赖 crew（根包，wiki extras 随迁：charset-normalizer/markdownify/pymupdf/...）；反向（crew 依赖 crew-wiki 的装配点）通过根包对成员的可选依赖或宿主装配层表达——试点期由 build_app 的既有惰性导入承载。

四条交付链验证清单（试点的验收门）

  1. uv sync --extra dev --extra wiki 单锁安装，editable 生效；
  2. CI（.github/workflows/ci.yml）矩阵全绿（ruff/lint-imports/pytest 全量）；
  3. Dockerfile.pack 构建通过（COPY 成员 + 安装 + PyInstaller datas/pathex 调整）；
  4. desktop 开发态 spawn（python -m crew.gateway.server，desktop/src/main/index.ts:1382）与打包态 PyInstaller 产物启动通过。

试点完成后的第二批（crew-external-agents）与第三批（粗粒度收尾）按评估报告 §5.2 顺序推进；.importlinter 契约在每批拆包后对应简化为物理事实。

实施补充决定：顶层 crew 转 PEP 420 命名空间包

实施中发现"目录迁移零代码改动"前提不成立：hatchling editable 安装是朴素路径 .pth（各发行版只把各自目录前缀塞进 sys.path），顶层 crew 保留 __init__.py 即为 regular 包，__path__ 被截断在仓库根，成员的 crew.wiki 必然不可导入；且 import-linter（grimp）只经 find_spec 扫描文件系统，pkgutil 式 __path__ 扩展对它不可见。最小可行解经独立探针工程实证：删 crew/__init__.py（原内容仅 docstring + 版本号，版本迁 crew/version.py），顶层 crew 成为 PEP 420 原生命名空间包，crew.__path__ 跨仓库根与成员 src 双 portion。暴露点修复三处：mcp_server 版本导入、process_registry trust root 改 portion 推导、wiki multimodal 的 skills 定位改遍历 portions（顺带消除一处拆包必断的文件系统耦合）。成员 hatch wheel 配置 packages=["src/crew"]（保 namespace 语义，wheel 内容不变）。

实施验证状态

本地已验证：uv lock/sync 单锁（成员 editable）、全量测试 4133 passed / 0 failed（weixin 5 例因 uv sync 精确剪除可选依赖转 skip，与 CI 行为一致）、ruff/compileall/lint-imports（9 kept）全绿、成员 wheel 资产收录核验、gateway 启动冒烟（desktop spawn 同款命令）。待远程验证：CI 矩阵实跑、Dockerfile.pack 构建、mac/Windows PyInstaller 冻结产物对跨目录 namespace 包的收集（回退预案：pack 脚本改双非 editable 安装）。

第二批实施记录（crew-external-agents，2026-09-12）

namespace 机制复用成功：中间层 crew/agent 同步 namespace 化（删 __init__.py，其 4 个 re-export 的消费方仅 5 处测试，机械改直连导入；生产代码因 6M 已 Lease 化而零改写）。依赖声明决策：crew-external-agents 列入根包 [project].dependencies（workspace 源）——app.py 对该成员是模块级硬导入，属核心依赖而非可选；uv sync 只装根包依赖闭包，硬依赖保证 CI 的 uv sync --extra dev（无 wiki）矩阵可用，CI 保持零改动。备选 uv sync --all-packages 未采用（会改 CI 先例）。全量 4094 passed / 0 failed、namespace 三 portion、gateway 冒烟 200。

回退方式

试点为纯目录/构建结构变化，业务代码零改动；回退 = 还原目录迁移提交 + 根 pyproject 的 workspace 段，uv.lock 重新生成。
