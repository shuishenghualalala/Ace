ADR-0037 · uv workspace 首个试点（crew-wiki）提案

状态：已批准（用户确认 2026-09-11），实施进行中 · 日期：2026-09-11 · 阶段：6 收官。

背景与候选方案

workspace 评估报告（ace-workspace-split-assessment.md）确认 uv workspace 多包化可行，并列出 6 项必修逻辑拆分。截至本 ADR 撰写时，6 项已全部解除并有 9 条 import-linter 契约保护：① state→team/external（6I）、② team→external 数据耦合与 Store 继承（6G/6G-2，ADR-0036）、③ wiki→gateway 私有导入（6J）、④ state→browser 类型（6K）、⑤ gateway 协议设施下沉（6L）、⑥ executor→external 直连（6M）。ServiceKey 版本化（6N）进行中。

候选方案：A. 直接全量拆包（8 个成员包一次到位）——回退面大、CI/Docker/桌面打包链路一次冲击；B. 单包试点（crew-wiki）先行，验证四条交付链后再逐批拆；C. 暂不物理拆包，仅维持契约——放弃包管理器物理强制的收益。

决定（建议）

采用方案 B。试点成员 crew-wiki（评估报告 §5.2 论证：演进计划指定的首个 Feature Bundle 试点、不占 crew.db、依赖最干净、契约测试就位——6A 的 KnowledgeService 契约套件即其包级验收门禁）。

  • 目录：packages/crew-wiki/pyproject.toml + packages/crew-wiki/src/crew/wiki/（整个 crew/wiki/ 原样迁入）；发行版间 import 名保持 crew.*（评估报告：Dockerfile.pack、desktop spawn PYTHONPATH、PyInstaller spec 改动最小化的前提）。
  • 根 pyproject 增加 [tool.uv.workspace] members = ["packages/*"]；根包继续拥有其余模块；uv 单锁（uv.lock 共享）。
  • 依赖声明：crew-wiki 依赖 crew（根包，wiki extras 随迁：charset-normalizer/markdownify/pymupdf/...）；反向（crew 依赖 crew-wiki 的装配点）通过根包对成员的可选依赖或宿主装配层表达——试点期由 build_app 的既有惰性导入承载。

四条交付链验证清单（试点的验收门）

  1. uv sync --extra dev --extra wiki 单锁安装，editable 生效；
  2. CI（.github/workflows/ci.yml）矩阵全绿（ruff/lint-imports/pytest 全量）；
  3. Dockerfile.pack 构建通过（COPY 成员 + 安装 + PyInstaller datas/pathex 调整）；
  4. desktop 开发态 spawn（python -m crew.gateway.server，desktop/src/main/index.ts:1382）与打包态 PyInstaller 产物启动通过。

试点完成后的第二批（crew-external-agents）与第三批（粗粒度收尾）按评估报告 §5.2 顺序推进；.importlinter 契约在每批拆包后对应简化为物理事实。

回退方式

试点为纯目录/构建结构变化，业务代码零改动；回退 = 还原目录迁移提交 + 根 pyproject 的 workspace 段，uv.lock 重新生成。

待用户确认的输入

  • 是否按本提案开工试点（涉及 CI/Docker/桌面打包链，建议醒后确认）；
  • 旧流事件兼容层删除（Step 3）的已发布客户端最低支持版本决策（前置已全部就绪：6D 双协议、6F 灰度开关、存量失败清零）。
