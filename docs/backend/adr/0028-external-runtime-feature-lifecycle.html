ADR-0028 · 外援 Provider 与 Run 生命周期

状态：切片已确认，契约实施与验证中 · 日期：2026-09-08 · 阶段：4A-2。

背景与候选方案

ADR-0027 已拆开外援 Catalog 与 Team 存储边界，但宿主和消费者仍长期持有对象，Adapter 运行也尚未整体归属 Feature Generation。仅在宿主退出时清理进程不能保护配置更新、单独停用和激活失败。

架构约束

外援通过稳定的 Catalog 与 AgentRuntimeProvider 能力接口供消费者调用，Adapter 保持 Provider 内部实现。复用已有 Feature Runtime、Service Registry、Generation 和 Lease，不引入第二套生命周期引擎。

每次运行持有同代服务至事件流与清理全部完成；后台任务及协议 reader、writer、stderr 任务必须有明确运行所有者。停止接收新请求后取消或等待在途工作，完成进程回收和任务等待后才能关闭底层资源。路径与进程控制沿用已有跨平台安全抽象。

Team 的兼容存储门面继续由 Team 模块维护。生命周期迁移必须保留编队引用删除守卫和原有事务边界，不能让 Team 通过残留宿主字段访问已关闭代。兼容入口需要明确消费者和退出阶段。

验证、交付与回退

2026-09-09 收口审查补充：Factory 在 Generation 安装阶段创建资源，创建后立即纳入回滚所有权；生产 Executor 必须按次解析同代 Catalog 与 Delegation 并覆盖完整执行期，不能只增加可选配置接口。尚未消费的 Run、部分消费的流和并发关闭均须有确定的取消与清理完成语义，Lease 只能在清理完成后释放。取消处理不能依赖等待 Lease 归零之后才运行的 Provider disposer。

外援 Bundle 遵守 Agent 不直接导入 Gateway/Team 的现有架构契约。Gateway 作为服务消费者接入请求门控；Team 的存储兼容路径须保留引用删除守卫与事务语义，并明确运行期对象的所有者。开发与独立测试并行，共享装配文件由主审串行分配。

独立测试覆盖激活、失败回滚、重复启停、代际更新、关闭后新增请求拒绝、活跃流取消、子进程及任务释放，并检查生产装配和 Team 消费路径。工具与 API 的可用性必须跟随生命周期。完整 UI Contribution 迁移仍按阶段 5 分切片实施。

停用和更新不删除外援、会话绑定或编队历史数据。本 ADR 尚不代表验证通过；完成后由测试记录列出实际命令、结果及 macOS、Linux、Windows 的实测或模拟覆盖。切片独立提交，回退通过撤销对应提交恢复前一装配，不执行数据删除。

后续延伸 · 2026-09-10

本 ADR 确立的 AgentRuntimeProvider 与 DelegationService 原本服务 Executor、Team 与 Gateway 三类消费者。后续设计把同一套能力扩展为 Subagent seam 的一种传输实现（external:<agent_id> provider，按外援 Catalog 注册，注册方向 external → subagent），使其同时成为子智能体委派的后端。

该扩展不修改本 ADR 的任何契约与生命周期决定：Catalog、Adapter、Store、Run 与 Generation 所有权全部不变，只新增一个消费者与一层适配。差异集中在三点：子智能体侧的 provider 能力位按适配器如实声明（agent_options / tool_filter / output_schema 默认不支持）；连续对话能力只有在适配器声明 resume_session_id 支持时才存在，且一旦事件流报出 session_reset 即作废并向父级说明；子智能体发起的外援 run 注入拒绝型审批 handler，不进入本 ADR 既有的人类审批链路。

设计与取舍见《Subagent 强化方案》§5.7 与 §6 D14–D16（subagent-strengthening-plan.md，已随本延伸节一并入库；方案为设计稿，实施另行立项）。
