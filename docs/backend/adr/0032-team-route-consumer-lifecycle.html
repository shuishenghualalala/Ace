ADR-0032 · Team Route/CLI 消费路径生命周期化

状态：已实施并验证 · 日期：2026-09-10 · 阶段：4C-2。

背景与候选方案

4C-1 把 TeamManager 收进 product.team Generation 后，Gateway 与 CLI 仍通过模块级 import crew.team.* 和散点 getattr(crew, "team", ...) 消费 Team 能力。CLI 还逆向 import gateway.routers.runtimes 的私有投影函数。这些路径让 Gateway 的静态依赖面与 Team 内部实现耦合，且 CLI 与 Router 的投影逻辑形成双向依赖。

决定

将纯展示投影函数（_runtime_availability、_external_agent_payloads、_external_team_payloads、_managed_temporary_agent_ids）下沉到 crew/team/payloads.py，供 CLI 与 Router 共同消费，消除 CLI→Router 逆向依赖。Gateway 模块级 crew.team.* import 全部改为函数体内惰性 import，缩小静态依赖面。sessions.py 与 interaction_bridge.py 的 TeamManager 散点统一为 crew.team 动态属性访问，保留 None 安全分支；Team 未激活时 interaction_bridge 端点抛 ValueError("Team 模式未启用")，由上层返回 503/降级。

兼容、验证与回退

runtimes.py 的 8 个 /api/external-teams* 端点行为不变（数据源仍是 external catalog store）；sessions.py 的历史投影与模型绑定端点在 Team 未激活时安全跳过原有降级分支。新增 tests/test_team_route_consumer.py 覆盖 team=None 降级、CLI 不再 import gateway router、payloads 导出正确性。回归 309 passed / 1 skipped，Ruff、compileall、Import Linter（6 contracts kept, 0 broken）全部通过。

已知边界：crew/gateway/routers/runtimes.py 仍通过函数内惰性 import 使用 Formation/Role/TeamSpec 纯函数；若未来需完全切断 gateway→team 调用链，需把这些能力也声明为 Service 接口，超出本切片范围。停用不删除 Team 业务数据；回退本切片恢复逆向 import 与模块级依赖。
