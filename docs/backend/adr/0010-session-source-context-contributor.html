ADR-0010 · Session Source Context Contributor

状态：Accepted · 日期：2026-09-03 · 阶段：插件架构 Stage 2 / Commit 4

背景

crew.agent.runtime 直接导入 Gateway 的 SessionContext、SessionSource、解析器和 prompt formatter。这使 Agent 同时理解渠道来源的数据结构与展示规则，并迫使 import-linter 长期保留 Agent→Gateway 豁免。

决定

Gateway 保留渠道路由数据所有权，并以 gateway.session.source Contributor 输出规范化 session_source 参数和动态模型上下文片段。Host 只负责把该 Handler 装入 FeatureScope；Agent 只读取通用参数与已排序 fragment。

职责所有者边界
来源解析与序列化Gateway Session Context接受对象或字典输入，输出稳定 source 字典。
模型可见文本Gateway Session ContributorContributor 生成来源、用户、Workspace、已连接平台和投递选项。
顺序与生命周期Feature Runtimepriority 300；请求执行持有 gateway.session-context Generation Lease。
消费Agent Runtime动态 fragment 进入通用 system-reminder；工具上下文读取规范化 session_source。

动态上下文而非静态身份

渠道、聊天、参与者和投递目标会逐请求变化，因此它们属于动态 runtime context，不属于静态身份或部署级 system section。将其放入通用 reminder snapshot 可避免会话来源变化破坏 system prompt 的前缀稳定性，也使未来按 Agent Scope 抑制动态上下文成为可能。

兼容与失败

  • WebSocket、渠道续聊和 Cron 仍可传入现有 SessionContext 对象；字典载荷通过统一 SessionContext.from_dict() 解析。
  • 缺少 session_context 时 Contributor 不产生输出；Agent 为工具 ContextVar 保留基于 Envelope 元数据的无依赖回退。
  • 无效字典按默认 degrade 策略记录贡献失败，不阻断请求。
  • 本切片删除 Agent Runtime→Gateway 的最后一条直接 import 和 import-linter 豁免；PluginManager 的平台装配懒加载随后续 Route Gate 切片迁移。

跨平台

Contributor 只处理普通字典、字符串和 pathlib 已归一的 Workspace 路径，不依赖平台进程、signal 或路径分隔符。
