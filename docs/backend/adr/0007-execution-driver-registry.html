ADR-0007 · Execution Driver Registry

状态：Accepted · 日期：2026-09-03 · 阶段：插件架构 Stage 2 / Commit 1

背景

CrewApp.handle() 直接判断 agent、team 和 dynamic_kanban。新增模式需要改中心文件，未知字符串还会落入默认 Agent，既不利于能力隔离，也无法让 Feature 停用真正撤销执行入口。仅建立普通字典同样不够：Driver 的活跃请求必须参与 Generation drain，更新时还要保证新旧实现原子切换。

决定

建立共享的 ExecutionDriverRegistry。mode 是开放的小写稳定标识；Driver 只能由 FeatureScope 注册，解析只返回 Active Generation，dispatch 自动持有该 Generation 的请求 Lease。

边界决定结果
所有权注册返回 RegistrationToken，Contribution 阶段先于资源撤销。Feature 停用或插件卸载后 mode 自动消失。
Generation同一 Feature 可暂存 Activating 新代；提交后选择序号最新的 Active Driver。replace 更新不产生路由空窗，旧代无法误删新代。
请求dispatch 在调用 Handler 前获取 execution:<request_id> Lease。drain 拒绝新请求并等待当前流结束。
协议Envelope.mode 从业务 Literal 改为开放字符串。新增 mode 不需要修改 Core 类型。
失败未注册 mode 返回最终 error chunk，稳定码为 capability_unavailable。调用方不会把拼写错误静默执行成默认 Agent。

首个真实消费者

默认单 Agent 路径已从 handle() 尾部移入 Driver Handler。旧 ID agent 与稳定 ID agent.default 由同一 Core FeatureScope 提供，保持客户端兼容。FeatureRuntime 与 PluginContext 暴露同一注册入口，目录插件可以提供新 mode，并在卸载时由 Scope 自动撤销。

迁移边界

  • Team 和 Dynamic Kanban 本切片仍保留旧分支；下一切片将 Manager 包装为 Feature-owned Driver 后删除分支。
  • Owner、Workspace、安全启动参数和后台通知仍是 Host 公共前处理；后续由 Context Contributor 继续拆分。
  • 默认 Agent Scope 目前由同步组合根创建，以保证未调用 startup 的既有入口仍可运行；Core Feature 完整迁移后进入统一启动审计。
  • ResponseChunk 的业务 kind 未在本切片改动，避免同时改变路由与前端事件协议。

设计核查

外部插件生命周期实现表明，注册项必须由执行它的生命周期单元精确持有，清理需要可等待且不能依赖全局名称删除。Ace 的 Driver Registry 因此复用 FeatureScope、RegistrationToken、Generation 可见性和 Lease，而不再建立第二套卸载清单。

跨平台

Registry、流式 dispatch 和 drain 仅使用 Python 对象与 asyncio，不依赖 Unix signal、fork、文件锁或平台路径语义；macOS、Linux 与 Windows 使用同一代码路径。
