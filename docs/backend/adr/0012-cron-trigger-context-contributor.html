ADR-0012 · Cron Trigger Context Contributor

状态：Accepted · 日期：2026-09-03 · 阶段：插件架构 Stage 2 / Commit 6

背景

Agent Runtime 曾根据 Envelope.channel == cron 直接拼装定时任务触发文案。该分支虽然很小，却让 Agent 内核认识 Cron 产品语义；关闭 Cron 调度器也不会撤销这段行为。

决定

由 Cron 模块提供 cron.trigger.reminder Prompt Contributor。仅在 cron_enabled 时由 Cron bridge Scope 注册；Agent 只运行通用 Prompt Contributor，不再包含 Cron 文案或渠道判断。

职责所有者契约
触发语义与文案Cron读取 channel 与 cron_job_name，输出单个瞬时 prompt fragment。
能力启用Host 组合根只有 cron_enabled=true 才注册 bridge Scope。
匹配与顺序Feature RuntimePrompt phase、priority 50、仅匹配 cron channel。
撤销FeatureScope应用关闭时 Contributor Token 随 Scope 精确释放。

行为兼容

  • 定时任务名、立即执行说明和“不要反问是否到时间”的约束保持原文。
  • 当前时间仍由通用动态 reminder 提供，Cron fragment 与其在同一 request view 中合并。
  • 普通 Web、CLI 或渠道请求不产生该 fragment。
  • 该信息每次触发重新计算，不写入 canonical history。

边界与后续

本次只迁移模型上下文。Cron Store、Scheduler、Tool、Router、Owner mount 和后台 Task 仍由组合根手工管理，阶段 3A 再把它们收敛到支持 restart 的完整 Cron Feature。

跨平台

Contributor 只处理 Envelope 字段与普通字符串，不依赖系统时区 API、进程信号或平台路径。
