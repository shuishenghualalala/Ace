ADR-0020 · Wiki Knowledge Feature Foundation

状态：Accepted · 日期：2026-09-04 · 阶段：插件架构 3B

背景

Wiki 的 Store、Compiler、Querier、Summarizer、Session Manager、24 个 Tools 与 Prompt Context 原本由 build_app() 逐项构造。调用方又通过 CrewApp._wiki_* 私有字段直接持有具体对象，因此无法用一个生命周期单元启停、更新或替换本地实现。

决策

建立稳定的 knowledge Service Definition，由 LocalWikiProvider 提供当前文件系统实现；product.wiki Feature Generation 统一拥有 Provider、Tools、Context Contributor 与逃逸调用栈的后台 Task。
  • KnowledgeService 首批稳定接口覆盖 query、search、ingest、document read 与 index status；Gateway/CLI 尚未迁移的细粒度调用暂经显式 Components 兼容视图访问。
  • Wiki Tools 先纯构造，再逐个登记 identity-safe disposer 并发布；同步 Handler 在 Generation Lease 内继续通过工作线程执行。
  • Wiki 使用 DRAIN + RESTART。当前按名称寻址的 Tool Registry 不能安全暂存两套同名贡献，因此不使用 replace；更新失败由旧 Definition 重建恢复 Generation。
  • FeatureScope.create_task() 为每代只登记一个 Task Owner，drain 时关闭准入，dispose 时 cancel 并 join；Wiki Compiler 的 Home 导读刷新成为首个真实消费者。
  • CrewApp 的迁移期 Wiki 属性动态解析当前可见 Service。Feature 停用后 Service、Tools、Context 与兼容视图同步撤销，持久 Wiki 数据不删除。
  • Work 尚未迁成 Consumer Feature，本轮先保证关闭顺序为 Consumer stop 后 Provider deactivate。

结果与后续

build_app() 不再了解 Wiki 内部对象或逐项注册贡献。下一切片将把 Wiki API 与 CLI 消费者从 Components 兼容视图迁到 KnowledgeService，随后继续收拢 Agent Preset、Event、Route 和 UI Contribution；Work 的可选依赖在阶段 3C 处理。

跨平台

新增生命周期只依赖 Python asyncio、线程调度、pathlib 与既有文件系统 Store，不引入平台命令、POSIX 信号或固定路径语义，可用于 macOS、Linux 与 Windows。
