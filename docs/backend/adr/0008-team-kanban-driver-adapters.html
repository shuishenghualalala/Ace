ADR-0008 · Team 与 Kanban Driver Adapter

状态：Accepted · 日期：2026-09-03 · 阶段：插件架构 Stage 2 / Commit 2

背景

Execution Driver Registry 已承接默认 Agent 和第三方 Feature，但 CrewApp.handle() 仍直接判断 Team 与 Dynamic Kanban。这样中心入口仍认识产品业务，而且这两条长请求没有使用 Driver Generation Lease。两类 Manager 的内部资源所有权较复杂，不适合在删除 mode 分支的同时整体重构。

决定

先以窄适配层将 Team 与 Dynamic Kanban 的现有 interact() 包装成 Execution Driver。每个 Adapter 使用独立 FeatureScope；Host 只在组合时注册，handle() 只解析 Registry，不再包含任何业务 mode 分支。

DriverGeneration兼容行为
teamproduct.team-driver-adapter@g1仅在 Team 启用时注册；继续从会话配置补全 external_team_id。
dynamic_kanbanproduct.dynamic-kanban-driver-adapter@g1保留旧 mode、Manager 调用和流式 ResponseChunk。

生命周期

Driver dispatch 自动持有所属 Scope 的请求 Lease。应用关闭时先停止 Session Dispatcher，再并行 drain 默认 Agent、Team 与 Dynamic Kanban 的桥接 Scope，最后关闭 Team Manager、Provider、插件和 Store。禁用 Team 时不注册占位 Driver，请求统一返回 capability_unavailable。

边界

  • 本决定只迁移执行入口与请求 Lease，不迁移 Manager 内部结构。
  • Team 的后台任务、Provider 和活动协作状态仍在后续复杂并发阶段迁入完整 Product Feature。
  • Dynamic Kanban 的 Store、运行 Task 和 Provider 状态仍在后续复杂并发阶段迁入完整 Product Feature。
  • Gateway 对 Dynamic Kanban sidechain 的兼容判断暂不改变；后续由 Driver Descriptor 或策略贡献替代。

结果

新增执行模式只需注册 Driver；默认 Agent、Team、Dynamic Kanban 和目录插件共享同一解析路径。CrewApp.handle() 只保留 Host 公共前处理、一次 Driver 分派与标准 unavailable 响应。

跨平台

Adapter、Scope drain 与并行关闭只使用 Python asyncio；不依赖 Unix signal、fork、文件锁或平台路径语义，macOS、Linux 与 Windows 使用同一实现。
