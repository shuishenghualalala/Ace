ADR-0024 · Agent Preset Contribution Registry

状态：Accepted · 日期：2026-09-05 · 阶段：插件架构 3B

背景

Wiki Agent 的 prompt、专属 Skill、Toolset 扩展、Context tag 和披露模式此前分散在通用预设目录与 CrewApp 的名称判断中。关闭 Wiki 只能撤销工具和服务，预设本身仍可被发现；Agent 缓存也只按会话配置区分，无法识别 Feature Generation 更新。

决策

建立中立的 AgentPresetRegistry：Feature 以不可变数据声明完整预设策略，注册、解析、执行和缓存均绑定所属 Generation；产品预设资产由自己的 Bundle 持有。
  • AgentPresetContribution 只包含字符串与不可变集合，描述 prompt、agent ID、固定 Skills、工具选择与追加、Context tags、披露模式、模型和后台策略，不依赖具体 Agent 实现。
  • 注册返回 Scope-owned Token；只有最新 Active Generation 可解析。同名无关 Feature 冲突，rollback、restart 与 deactivate 通过同一 disposer 撤销目录可见性。
  • 普通预设由必需的 core.agent-presets Feature 注册；Wiki Markdown 资产迁入 crew/wiki/presets/，由 product.wiki 注册。用户同名覆盖仍可被 Wiki Bundle 幂等领取，但专属安全策略不能被覆盖。
  • 持久化主 Agent、上下文预览、前台与后台 run_agent 在完整执行期持有 preset Generation Lease。draining 后拒绝新执行，旧代执行结束前不释放所属资源。
  • 持久化 Agent 的一次性有效配置包含 Generation key 与已解析策略；缓存换代只退休同 owner/session 的旧实例，活跃 Agent Lease 结束后再关闭。
  • run_agent schema 从当前目录动态生成；工具披露与执行期 JSON Schema 校验读取同一份参数，Feature 停用后不再暴露已撤销预设。
  • 子 Agent 先应用父会话最终授权与禁止嵌套边界，再按预设收窄，最后仅追加该预设显式声明的专属 Toolset。

结果与后续

CrewApp 的 Agent 装配路径不再导入 Wiki 工具常量，也不按 Wiki 名称决定 prompt、工具、Skill 或 Context。Stage 3B 仍需迁移 Wiki Route 与 UI Contribution；Work 的可选 Knowledge Service 依赖留在 Stage 3C。

跨平台

预设资产通过 pathlib 定位；Registry、Lease 与缓存指纹只使用 Python 标准数据结构和 asyncio，在 macOS、Linux 与 Windows 保持相同语义。
