ADR-0025 · Work Feature 生命周期与 API Consumer

状态：Accepted · 日期：2026-09-07 · 阶段：插件架构 3C

背景

build_app() 原先直接构造 WorkService 和八个 SQLite Store，CrewApp.startup()/shutdown() 手写 Hook 启停与连接关闭；Work REST 和 CLI 又直接读取 app.work_service。个人知识长期持有 Wiki Store，使 Work 无法跟随 Wiki Generation 更新，也无法在 Wiki 停用时明确降级。

决策

建立 product.work Feature Bundle 和稳定的 work Service。每个 Generation 统一拥有 WorkService、八个 Store、agent:end Hook 与 REST Route Contribution；个人知识在每次调用期间动态租用可选的 knowledge Service。
  • Work 声明 optional=(knowledge,) 与 provides=(work,)，使用 DRAIN + RESTART；请求入口持有 Route Lease，并只解析同一 Generation 的 Work Service。
  • 同步 Store close() 登记在 Resource phase，异步 Service stop() 登记在 Contribution phase，确保先撤销 Hook 和服务能力，再关闭数据库连接。
  • FastAPI 在构建期挂载稳定 Route 表面；运行期 Gate 在停用、draining 或代际不匹配时返回 503，不修改 FastAPI 内部 route list。
  • 禁用不删除业务数据，也不保留可绕过 Registry 的兼容绑定。宿主显式注入的外部 WorkService 不归 Feature stop/close，停用后仍保留原始绑定。
  • crew/gateway/routers/work.py 仅保留兼容导入；真实路由归属 crew/work/routes.py。Work CLI 的动态 Service Consumer 作为后续独立切片，不混入本次迁移。

回退方式

可恢复 Gateway 的固定 Work Router 和 build_app() 手工装配，同时保留领域 Store 数据。Feature 停用只撤销运行时注册，不执行表或文件删除，因此回退不需要数据迁移。

跨平台

本切片仅使用 Python asyncio、pathlib、SQLite 与现有 Feature Runtime，不引入 POSIX 信号、平台命令或固定分隔符；数据库路径和关闭语义在 macOS、Linux、Windows 保持一致。
