ADR-0011 · Wiki Attachment Context Contributor

状态：Accepted · 日期：2026-09-03 · 阶段：插件架构 Stage 2 / Commit 5

背景

crew.agent.runtime 曾直接导入 Wiki Attachment 工厂、持有 WikiSessionManager，并在预览和真实执行路径分别判断 Wiki 模式。该结构让 Agent 内核理解产品 Feature，也让两条路径容易发生行为偏差。

决定

把 Wiki 活跃知识库上下文注册为 wiki.agent.context Prompt Contributor。Wiki 模块拥有 KB 解析与隐藏附件生成；Host 只装配 FeatureScope；Agent 只按通用标签运行 Contributor，并持久化契约允许的 Message。

职责所有者契约
KB 选择与上下文消息Wiki读取请求、持久配置或当前会话 KB，生成 wiki_agent_context hidden attachment。
能力选择Agent PresetWiki Preset 只声明通用 wiki context tag，不持有 Wiki Manager。
顺序与生命周期Feature RuntimePrompt phase、priority 100、FeatureScope 所有权和请求 Lease。
消息持久化Agent Runtime只有 persistent=true 且 model-visible 的 Contributor 可以返回 Message。

预览与真实执行

两条路径都先运行 Prompt Contributor，再构建动态 prompt。真实执行把 Wiki hidden attachment 写入 canonical history；预览只把同类消息放进临时 request view，不写回 Session Store。这样会话打开时的估算与下一次真实请求一致，同时不会制造重复历史。

边界与后续

  • 本切片删除 Agent Runtime→Wiki 的直接 import 和 import-linter 豁免。
  • Wiki Tool、API、Store、Preset 仍由组合根分别装配；它们将在阶段 3 收敛为完整 Wiki Bundle。
  • wiki_confirmation_id 等业务参数仍属于现有工具工作流，不计入本次 Attachment Context 迁移。
  • 重复执行代表新一轮上下文快照，仍会按原语义追加新的 Wiki attachment。

跨平台

新契约只使用 Python 数据结构、异步调用和已有跨平台 Store API，不引入 signal、shell 或平台路径假设。
