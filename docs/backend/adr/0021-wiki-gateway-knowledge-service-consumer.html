ADR-0021 · Wiki Gateway Knowledge Service Consumer

状态：Accepted · 日期：2026-09-05 · 阶段：插件架构 3B

背景

Wiki Foundation 已把本地实现交给 product.wiki Generation，但 Gateway REST 与聊天附件捕获仍读取 CrewApp._wiki_store、Compiler、Querier 和 Session Manager。这样会把本地文件布局、上传解析和生命周期对象泄漏到 Host，也会让请求在 Feature 停用或重启后继续持有旧 Provider。

决策

Gateway Wiki API 只消费动态解析的 KnowledgeService；Service Registry 在同一次解析中返回当前 Provider 与其 Generation Lease，使请求可见性、drain 和资源关闭属于同一生命周期边界。
  • KnowledgeService 增加类型化的 KB、页面、来源、图谱、编译、上传、捕获和会话操作；页面列表搜索使用 search_pages()，与面向问答的 search() payload 分离。
  • ServiceRegistry.acquire_lease() 原子选择当前可见实现并取得所属 Generation Lease，PluginManager.acquire_service_lease() 作为 Host Facade；Gateway 不穿透 Feature Runtime。
  • 全部 /api/wiki/* 入口在请求时重新解析 Service。能力不存在或正在 draining 时统一返回 503；进行中的请求持有 Lease，释放后 Provider 才能关闭。
  • 上传落盘、文档解析、安全启动上下文、旧布局迁移、原始文件定位与下载内容读取归 LocalWikiProvider；Gateway 不导入 Store、Parser 或本地目录 API。
  • 聊天附件任务在真正执行时取得 Service 和 Lease，并用同一实例完成 KB 解析与捕获；停用后不新建捕获，drain 中不会把合法 KB 回落到 default。
  • 无 product.wiki 记录的嵌入宿主仍可注入外部 knowledge_service；已停用的产品 Feature 不会通过兼容出口重新暴露旧实现。

结果与后续

Gateway Wiki API 已成为 Provider-neutral Consumer，替换 Generation 不需要重建 Router 或修改端点业务。Router 的启动期 Route Contribution、CLI Consumer、Agent Preset、Event 和 UI Contribution 仍按 Stage 3B 后续切片迁移；Work 的可选依赖归 Stage 3C。

跨平台

Gateway 契约只传递领域对象、字节内容和标准 MIME/文件名信息；本地路径处理留在使用 pathlib 的 Provider 内部，不新增 shell 命令、POSIX 信号或固定目录分隔符，可用于 macOS、Linux 与 Windows。
