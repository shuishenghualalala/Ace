ADR-0048 · Subagent Stage D1-D5：Continuable 身份与控制面

状态：已实施 · 日期：2026-09-17 · 分支：codex/subagent-multiagent-upgrade · 前置：ADR-0047。

背景

Stage C 已把 Subagent 资源纳入 Feature Generation，但每次委派仍是一次性运行。子身份无法被可靠寻址，父 Agent 不能在下一轮继续投递，也没有统一的 owner/parent 授权边界；同时，隐藏子会话的稳定命名还没有接入 continuable Provider。

决定

  1. 增加 features.subagent.continuable 开关，默认关闭。关闭时模型面工具完全保持 one-shot，避免旧部署出现可见行为变化。
  2. continuable 委派使用持久 subagent_id。descriptor 继续采用 first-wins，新增运行规格快照，使进程重启后可用同一 Provider、模型与工具约束恢复子会话。
  3. Runtime 在进程内维护最多一个 ContinuableActivation 记录。每个身份拥有一把 asyncio.Lock，所有 send_message 按身份串行，状态由 activation 和待投递队列派生。
  4. 增加三个控制面工具：send_message、list_agents、interrupt_agent。模型参数不携带 provider、owner 或权限字段；Runtime 根据当前 Context 与持久父子边验证授权。
  5. 进程内 Provider 通过相同的子会话 id 重建轻量 Agent，交由现有 Session Store 保存跨轮历史；不依赖 Unix fork、signal 或平台专用进程 API。
  6. continuable 的 session_persistence 固定为 hidden，canonical session 使用 {parent_session_id}::subagent::{subagent_id}；公开身份仍是不透明的 subagent_id，父子关系以 edges 与 descriptor 为准。

授权不变量

边界规则
owner请求 owner 必须与 run 记录的 owner_account_id 归一值一致。
parent请求 parent 必须与 descriptor/run 的直接 parent_session_id 一致。
descriptor后续请求不能改写首份 provider、深度、工具规格或子身份。
并发同一身份的多个消息不能同时进入子 Agent；不同身份仍可并行。

边界

本 ADR 已交付身份、驻留锁、控制面、持久邮箱和通知来源分离。trigger_turn=false 的消息写入 subagent_messages，消费时再次校验 owner/parent；后台结算通知以 agent_message 保存子级自述，以 settlement 保存运行时账目，格式化层不把诊断冒充自述。后续仍需补齐更细粒度的 cold-resume 身份验证、三态驻留事件。fork、结构化输出和 UI reducer 另属 Stage E。

验证

Stage D1-D5 专项测试覆盖跨轮恢复、隐藏 session、进程重启后 descriptor 与 inbox 恢复、owner/parent 隔离、消息串行、通知来源分离、配置开关和模型工具注册。
