ADR-0017 · Cron Runtime Feature 与 restart Generation

状态：Accepted · 日期：2026-09-04 · 阶段：插件架构 Stage 3A

背景

Cron 的 Scheduler、六个 Agent Tool、Trigger Context、Owner mount 和 Host Service 绑定分散在 build_app()、CrewApp.startup()/shutdown() 与 Gateway Logout 中。中心清单既无法表达配置代，也无法在启动中途失败时完整撤销贡献。另一方面，Cron 任务数据必须在运行能力停用后保留，供显式查询、清理和再次启用。

候选方案

方案结论
仅把 start()/stop() 包进一个 helper，继续由 CrewApp 手写调用拒绝；资源仍属于中心清单，不能参与 Generation 更新与回滚。
在同步 build_app() 中启动 AsyncIOScheduler拒绝；临时事件循环结束后 Scheduler 将绑定失效循环，也无法安全服务三平台宿主。
build 阶段声明、宿主事件循环中由 FeatureRuntime 激活采用；长生命周期能力得到真实异步激活边界，后续 Sites/Browser 可复用。

决定

建立 product.cron FeatureDefinition，更新策略为 restart、停用策略为 cancel。Feature 安装逐项取得 Scheduler、Tools、Context Contributor、Owner mount 和 Host Binding 的所有权；每个 Tool 与 Fire 持有 Generation Lease。CrewApp 只提供通用托管 Feature 声明、激活、更新和逆序停用入口，不再调用 CronService 的具体启停方法。

职责所有者契约
运行代crew/cron/feature.py候选 Service 不在同步构造期启动；FeatureRuntime 激活时启动并挂载当前 Active Owner。
公开贡献同一 FeatureScope六个工具、Prompt Contributor 与 Host Binding 先于资源关闭撤销；工具注销校验对象身份，旧代不能误删替换代。
活跃工作Generation LeaseTool/Fire 在运行期间持有 Lease；cancel 停用通知并取消旧代 Fire，结束后再关闭 Scheduler。
持久数据Cron 数据平面停用不删除任务和 Fire 记录；当前兼容 Store 由 Host 最终关闭，后续以稳定数据服务替换字段访问。
Gateway Owner动态 Service getterLogout/activate 每次解析当前 Generation 的 CronService，restart 后不持有旧 Service。

失败与回退

Scheduler 启动或后续注册失败时，FeatureTransaction 先撤销工具、上下文和 Host Binding，再停止候选 Scheduler，不留下半激活贡献。restart 新代失败时由 FeatureRuntime 以旧定义创建恢复 Generation。回退本提交可恢复原中心启停分支，SQLite 任务数据格式没有变化。

跨平台

新增路径只依赖 Python asyncio、Feature Runtime 和既有 APScheduler；未引入 signal、fork、Unix socket、路径分隔符或 shell 约定。SQLite 数据保留语义与 macOS、Linux、Windows 一致。
