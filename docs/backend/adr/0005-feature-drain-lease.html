ADR-0005 · Feature 请求 Lease 与停用策略

状态：Accepted · 日期：2026-09-02 · 阶段：插件架构 Stage 1 / Commit 6

背景

Scope 已能逆序撤销贡献和资源，但旧的停用路径不知道某个 Handler 是否仍在使用 Provider、连接或 Store。直接执行 disposer 会让运行中的请求访问已关闭资源；仅等待 disposer 又无法阻止新请求持续进入。

决定

每个外部可见调用在进入 Active Generation 时获取 Lease；停止先把 Scope 置为 Draining，关闭新 Lease 入口，再依据 Manifest 策略处理已有 Lease，最后进入两相清理。

策略行为典型能力
drain拒绝新增，等待活跃 Lease 自然释放。Provider、Wiki、一般工具。
cancel设置取消信号并取消持有 Lease 的异步任务，再等待其退出。Browser 操作、用户主动停止的后台工作。
immediate直接清理；若存在 Lease，将其标签记录为 forced cleanup。无状态纯贡献。
restart_required运行期停用失败关闭，保留当前 Generation 并记录待重启；宿主关闭边界可完成清理。稳定 Router 树、进程级资源。

入口覆盖

Plugin Adapter 自动包装 Tool、Hook、Middleware 和 Command，不要求现有插件修改 Handler。同步 Tool 在线程中运行时，取消只中断外层任务；Lease 必须等工作线程实际返回后才能释放，超时期间资源保持可用且 Feature 保持 Draining。

诊断与失败语义

Feature 快照新增 stop policy、活跃 Lease、restart required 和最近一次停止详情。Drain 超时返回失败，Scope 保持 Draining、拒绝新请求且不释放资源；释放遗留 Lease 后可重试。只有贡献已撤销、资源已完成清理时，Runtime 才把 Feature 变回 Discovered。

兼容与跨平台

旧 Manifest 缺省为 drain 和 30 秒。实现只使用 Python asyncio、线程池等待和单调状态转换，不依赖 Unix signal、fork 或平台特定句柄；macOS、Linux 和 Windows 共享同一语义。

后续

配置 replace/restart 已在下一切片落地：replace 原子发布新 Generation 后 drain 旧代；restart 先 drain 当前代，再以新配置激活并在失败时恢复。详细决策见 ADR-0006。
