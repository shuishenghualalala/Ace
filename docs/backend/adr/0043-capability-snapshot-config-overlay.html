ADR-0043 · 能力快照叠加配置可用性（半接状态源对齐）

2026-09-14 · 阶段 6AE · 状态：已实施并验证。

背景与候选

ADR-0040 交付的 feature_capabilities 快照表达 Runtime 请求准入（Feature 激活即 available），但 product.wiki 与 product.external-agents 的激活不随配置开关变化（build_wiki_feature/build_external_agent_feature 不带 enabled，external_agents_enabled 仅作请求时门禁），导致配置已禁用时快照仍报 available:true——两个事实源：前端若改从快照判断，会静默复活配置禁用的功能。Team 已按 enable_team 在激活层对齐，是唯一正确的范式。候选：改为激活层对齐（行为变更大、Route/Service 随配置下线，测试波及广）；在快照投影层叠加配置标志（单向覆写，不动激活）。

决定

采用投影层叠加：crew/gateway/helpers.py::config_body 新增 _apply_config_availability_overrides(snapshot, config)，对 product.wiki（wiki_enabled）与 product.external-agents（external_agents_enabled）在配置标志为假时把 available 翻为 false；条目保留（state/generation 原样）、缺席条目不动。最终语义：available = 配置启用 ∧ Runtime 激活，作为 UI 消费的唯一产品可用性事实源。Runtime 快照保持纯运行态投影、app.py 激活行为不变、请求时门禁不变（require_external_agents_enabled 与本覆写同源，无行为漂移）。

边界、验收与回退

本片只改 config 响应投影与测试，不动后端激活/路由/请求门禁，前端无需改动（wiki/external-agents 现有 config-flag 门控与叠加后快照一致）。验收：参数化测试覆盖 wiki/external-agents × 配置开/关 × Runtime available 真/假，断言 available = 配置 ∧ 运行；回归 config 响应/CRUD/能力套件 104 passed。回退：撤销覆写函数与调用，恢复纯 Runtime 投影。
