ADR-0046 · 任务存储异步门面

状态：已批准 · 日期：2026-09-17 · 批次：agent-core-defects 批次 0。

背景与候选方案

现状：TaskRuntime（crew/tasks/runtime.py）全部写方法为同步方法，内部 busy 重试带睡眠；事件循环上的直接调用点遍布 gateway/dispatcher.py（约 12 处）、crew/tools/builtin.py::handle_terminal（约 10 处）、packages/crew-team/delegate_tool.py（5 处）等。busy 重试的睡眠落在事件循环上即冻结所有会话——一次 sqlite busy 等待可能挂住 gateway 里全部活跃会话。

候选方案：

A. 调用点各自 asyncio.to_thread 包裹——否决：线程化决策散落在各调用方，sqlite 重试封装刚治理过同类问题，散包会让边界腐烂（子 agent 路径曾这么做过，本次一并收口）。

B. TaskRuntime 全面 async 化（含线程侧调用方）——否决：process_registry 的 heartbeat / reader 线程与 CLI 同步路径会被迫反向 sync→async 桥接，进入 asyncio_bridge 死锁陷阱区。

C.（选定）store 层异步门面：TaskRuntime 新增 async 方法，内部统一 to_thread 走同步实现；RLock + BEGIN IMMEDIATE 事务语义不变；同步 API 保留给线程 / CLI 调用方。

决定

  • store 层异步门面：TaskRuntime 新增 async 写/读方法（如 create_async / update_async / complete_async 等对应同步 API 的 async 变体），内部统一 asyncio.to_thread 包装同步实现。并发原语与事务语义不动：RLock 串行化 + BEGIN IMMEDIATE 事务保持原样。
  • TaskManager ABC 同步扩展：core/interfaces.py 的 TaskManager ABC 与 LegacyTaskManagerAdapter、InMemoryTaskManager 同步加 async 方法（默认实现可走 to_thread 包装同步方法），保证事件循环侧调用方依赖接口而非具体实现。
  • 调用点迁移清单：gateway/dispatcher.py（约 12 处）、crew/tools/builtin.py::handle_terminal（约 10 处）、packages/crew-team/delegate_tool.py（5 处）、gateway sessions router、channel sessions 等事件循环上的直接调用点统一迁移到 async 方法；process_registry 心跳/reader 线程与 CLI 同步路径维持同步调用不动。
  • 不借机改事务语义：create() 两步非原子维持现状（不作为本批次顺手修复项），避免行为变更与迁移混在一个批次里无法独立回退。

跨平台影响

asyncio.to_thread 在 CPython 三平台行为一致（默认线程池执行器），不触碰平台相关系统调用，mac / linux / windows 无差异。

回退方式

同步 API 未删除（线程 / CLI 调用方依赖保留），回退 = 调用点改回同步调用 + 撤销 TaskManager ABC 的 async 方法；门面与迁移属同一批次提交，回退按批次整体 revert。
