ADR-0034 · Dynamic Kanban 流事件命名空间迁移

状态：已实施并验证 · 日期：2026-09-10 · 阶段：4B-2 · 提交：4d9a782。

背景与候选方案

Team 与 Wiki 的生产侧已统一产出命名空间 feature_event（body = {feature, event, version, payload}），旧帧由 Gateway event_compat 适配器在出口转换，线上协议对现有客户端逐字节不变。Dynamic Kanban 是最后一个直接产旧 kanban / workflow_progress kind 的 Feature：runtime.py 6 处 kanban_event 与 1 处 workflow_progress 直接构造旧帧，核心 envelope.py 因此仍保留两个业务工厂与两个业务枚举。

候选方案：A. 生产侧继续发旧帧，Gateway 做反向转换——与统一生命周期方向冲突，且把业务枚举长期留在核心协议；B. 生产侧改发 feature_event，compat 出口重建旧帧——与 Team/Wiki 先例一致。

决定

采用方案 B。生产侧统一使用 feature_event(feature="kanban", event=<name>, version=1)，事件清单：started、board_changed、call_completed、workflow_progress。event_compat 登记 4 条映射；旧 kanban 帧 body 约定以 event 字段开头，而 feature_event payload 不重复携带事件名，compat 在转换到旧 kanban 帧时把事件名重建到 body 首位，保证出口旧帧与迁移前逐字节一致。未登记事件丢弃并输出诊断日志。

进程内消费路径（manager.py 后台 push_chunk）不经过 Gateway compat，新增 _is_unattached_control_chunk 判断：迁移期旧 status/workflow_progress 帧继续兼容，同时识别新 feature_event(feature="kanban", event="workflow_progress")，命中后清空 request_id 作为无归属控制帧推送，桌面端回合封口后仍能渲染。envelope.py 的 kanban_event()/workflow_progress() 工厂与两个 ChunkKind 枚举保留为迁移期兼容，标注删除条件为前端 reducer 全部迁移到 ace.feature-event.v1。

兼容、验证与回退

线上 WS 协议对现有客户端逐字节不变；前端 reducer 无需修改。新增事件契约测试覆盖 kanban 事件参数化映射、旧帧 body 重建逐字节对比、未登记事件丢弃诊断；更新 tests/test_dynamic_kanban.py 生产断言并新增后台化场景 request_id 清空测试。目标回归（event_compat、gateway api/ws、dynamic kanban 及生命周期、dispatcher）194 passed；Ruff、compileall、Import Linter（6 contracts kept, 0 broken）全部通过。

已知边界：Gateway 兼容层与 envelope 迁移期工厂须维持到阶段 5 前端 reducer 全部切换；manager 进程内消费路径依赖 feature_event body 结构，payload 形状调整需同步更新 helper。回退方式：恢复 runtime.py 使用旧工厂、删除 compat 中 kanban 映射、回退 manager helper。
