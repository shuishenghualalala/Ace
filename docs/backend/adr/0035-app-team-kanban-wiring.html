ADR-0035 · CrewApp Team/Kanban 中心接线收口

状态：已实施并验证 · 日期：2026-09-10 · 阶段：4C-3。

背景与候选方案

4C-1/4B-1 之后，Team 与 Dynamic Kanban 已是由 product.team / product.dynamic-kanban Generation 统一拥有的 Feature Bundle（Service、Execution Driver、Route 均已注册）。但 CrewApp 仍保留中心特判：steer/interrupt 的 getattr(self.team, …) → getattr(self.dynamic_kanban, …) 逐级硬编码链、active_tasks_snapshot 特判、use_model/update_model/remove_model 三处对 self.team.set_provider 与 self.dynamic_kanban.provider = … 的中心直写、owner provider 失效路径的 getattr 散点，以及 set_dynamic_kanban_manager 中与 Bundle 正式 Driver 重复的 product.dynamic-kanban-driver-adapter 注册。

候选方案：A. 保留 getattr 链——中心继续认识两个 Feature 的方法面，新增 Driver 仍需改 app.py；B. 新增 session-control 贡献注册表——当前只有两个消费者，属于过早抽象；C. 复用 4D-1 Channels 收口先例：compat 属性 + active-manager 解析 + 显式 provider 接口。

决定

采用方案 C。dynamic_kanban / dynamic_kanban_consumer 改为动态 compat 属性：测试注入走 override 位，生产解析经 Feature Runtime 检查 product.dynamic-kanban 状态后从 Service Registry 取 manager/consumer，Feature 非 ACTIVE 返回 None（fail-closed）；Bundle install/disposer 的 host.dynamic_kanban = manager / None 赋值自然落到 override 位，语义不变。steer/interrupt/active_tasks_snapshot 与 owner provider 失效路径统一经 _active_team_manager() / _active_dynamic_kanban_manager()（isinstance 守卫）分派，停用后安静降级，返回值与异常语义不变。三处 provider 同步点收口为 _sync_default_provider_to_features()：DynamicKanbanManager 新增与 Team 对等的 set_provider() 显式接口（只换全局默认 Provider，不动 owner 级缓存），app.py 不再直写 .provider 字段。遗留的 product.dynamic-kanban-driver-adapter 注册与 _run_dynamic_kanban_execution_driver 删除，mode=dynamic_kanban Driver 仅由 Bundle 注册。

兼容、验证与回退

对外语义全部保持：steer 无运行中会话返回 False、interrupt 聚合多来源结果、DK owner scope 校验留在 manager 内部、provider 切换仍触发 clear() 与旧 Provider 退休。新增 tests/test_team_kanban_app_compat.py 7 例：真实 build_app() 下 team/kanban 经 Service Registry 解析同代 Service、Feature 停用后 compat 属性 fail-closed、steer/interrupt 经 Registry 分派透传 owner scope。组合回归（compat、kanban、team、gateway 事件/API/WS/dispatcher）214 passed；Ruff、compileall、Import Linter（6 contracts kept, 0 broken）全部通过。

已知边界：self.team 仍保留 4C-1 的 override 位与 set_team_manager 入口，Team 侧字段彻底删除留待中心装配最终清理切片；set_dynamic_kanban_manager 保留为测试注入入口。回退方式：恢复普通字段与 getattr 分派链、还原三处 provider 直写。
