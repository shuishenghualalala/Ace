ADR-0016 · Core Feature 声明化与产品必需性守卫

状态：Accepted · 日期：2026-09-03 · 阶段：插件架构 Stage 2 收尾（§5.2、§6.2）

背景

组合根的内置能力（默认 Agent Driver、后台通知 Contributor、Host 路径、Session Source、Team/Kanban Driver Adapter 等）此前由 CrewApp 手写 FeatureScope 注册：有所有权，但没有 Feature 身份——启动审计、dump-features 和依赖图都看不见它们，「哪些能力是产品必需的」只存在于口头约定。

决定

FeatureDefinition 增加 required_by_product 标记；组合根的内置注册收敛为声明式 FeatureDefinition，经 FeatureRuntime 统一事务激活。deactivate 默认拒绝停用产品必需 Feature（feature_required_by_product），测试与部署装配可显式放行。同步宿主经共享的 run_async_compat 桥调用异步激活（原 plugins 私有桥上移为公共实现）。

职责所有者契约
产品必需性判定FeatureDefinition.required_by_product组合根约定：core.*/host.*/gateway.* 必需，product.* 可选；只影响控制面停用，不改变生命周期模型。
停用守卫FeatureRuntime.deactivate默认抛 FeatureRequiredByProductError；allow_required_by_product=True 供测试/装配放行。配置更新不受限。
组合根声明式装配CrewApp._install_builtin_feature10 处手写 scope 注册收敛为声明 + 激活；返回 scope 供关闭时逆序 stop，关闭路径不变。
同步宿主桥crew.features.run_async_compat无循环时 asyncio.run，有循环时 worker 线程持有兼容循环；plugins 私有桥改为委托。

行为兼容

  • 全部内置贡献的注册内容、顺序与关闭路径不变（现有 Driver/Context/插件测试全绿）。
  • 目录插件的加载/卸载语义不变；_run_async_compat 行为逐字保留，仅上移为共享实现。
  • 启动审计与 dump-features 自动覆盖 10 个内置 Feature（其中 6 个 required_by_product=True）。

边界与后续

本切片完成「声明化与产品必需性」，不等于默认 Agent Loop、Tool Runtime、Session/Task、LLM Provider 的资源所有权已迁入 Generation——它们的 store/连接/后台任务仍在 CrewApp.startup()/shutdown() 手写清单中，迁入属阶段 3 的纵向切片。产品控制面（UI/HTTP 的 Feature 开关）尚未暴露 required_by_product 拦截——目前守卫在 Runtime API 层，控制面落地时直接消费该错误码。

跨平台

同步桥只用 threading/contextvars 标准库，三平台语义一致。
