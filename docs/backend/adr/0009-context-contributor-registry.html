ADR-0009 · Context Contributor Registry

状态：Accepted · 日期：2026-09-03 · 阶段：插件架构 Stage 2 / Commit 3

背景

请求上下文仍由中心代码拼接：CrewApp 和 Agent Runtime 同时遍历 Gateway 的静态 REFERENCE_INJECTORS。新增引用来源必须修改 Host 与 Agent，Browser 被禁用后静态表仍会运行占位逻辑，且贡献没有 Feature Generation 所有权、超时或 drain 语义。

决定

建立共享 ContextContributorRegistry。Contributor 由 FeatureScope 注册，声明稳定 ID、阶段、优先级、失败策略、超时、匹配条件、模型可见性与持久性；每次执行自动持有所属 Generation Lease。

契约语义结果
顺序先按阶段，再按数字优先级和稳定 ID 排序；后执行者确定性覆盖同名参数。插件发现顺序不影响上下文。
失败degrade 记录结构化失败并继续；fail 返回稳定 context_contribution_failed。可选上下文留空，安全边界可失败关闭。
超时与取消异步 Handler 可设置正数超时；任务取消永远向上传播。慢贡献不无限阻塞请求，Host shutdown 可取消。
生命周期Activating 不可见，新 Generation 提交后接管；Contributor Handler 持有 Lease，并固定绑定该 Generation 拥有的资源实例。停用先隐藏入口，再等待在途上下文读取，旧代不会误用或关闭新代资源。
输出统一产出参数更新和有序 prompt fragment，并声明是否模型可见、是否持久。Agent 只消费通用片段，不认识来源 Feature。

首批真实贡献

  • host.reference.structured-path 由 Host Scope 提供，将显式 @file/@folder/@image token 解析为工作空间内授权路径；不产生模型文本。
  • browser.reference.tab 由 Browser 插件自身提供，将显式标签页 token 解析为有界只读快照和 prompt fragment；卸载插件后贡献自动消失。
  • 原静态 REFERENCE_INJECTORS 被删除，Agent Runtime 不再导入 crew.gateway.context，相应 import-linter 豁免同步删除。

边界

  • 本切片只接管请求阶段的引用上下文；Session Source、Cron Reminder、后台通知、Wiki Attachment 与 Plan 仍按后续真实消费者逐项迁移。
  • 持久 prompt fragment 已进入契约和报告，但写入 Session Event 的机制随 Feature Event 阶段实现。
  • 旧 resolve_browser_tab_references() API 暂由 Gateway 重导出，调用方迁移后删除。

设计核查

生命周期扩展系统的关键约束是：注册项由创建它的生命周期单元持有，顺序是显式元数据而非导入偶然性，卸载在返回前完成精确撤销。Context Contributor 因此复用 FeatureScope、RegistrationToken、Generation 选择和 Lease，不另建孤立的插件清理表。

跨平台

排序、异步超时、取消和 drain 使用 Python asyncio 与普通数据结构；路径贡献继续使用 pathlib 的工作空间 containment 校验，macOS、Linux 与 Windows 共享同一实现。
