ADR-0042 · 同伴（Nearby）渠道平台归属与产品范围

2026-09-14 · 阶段 6AD · 状态：已确认（AHUAMAO 拍板：同伴就近以 nearby 渠道平台身份进入 product.channels，不建独立 Feature）。

背景与候选

同伴的 PRD 已有两版（v2.1 待评审与 V1.0），技术路线在 PRD 中标注「已定」：以新渠道平台身份接入 gateway 渠道会话管道（入站 prepare_inbound_channel_envelope、出站 deliver_channel_session_reply，两钩子经核实存在）。但当前仓库中同伴没有任何业务实现：后端与 desktop 源码无 nearby 代码，仅存 desktop/nearby-bin/ 二进制暂存与空置的顶层 nearby/ 目录；PRD 所述旧实现（nearby-chat.ts 等）已不在树上。演进计划因此要求「按新 Channel Bundle 的产品范围另行明确，不将占位实现当作迁移完成」。候选：为同伴新建独立后端 Feature；作为 product.channels 内的第三平台（现有 feishu/weixin）；暂不立项。

决定

归属：同伴不建独立后端 Feature，以 nearby 渠道平台身份进入 product.channels Bundle——在 PlatformRegistry 注册 PlatformEntry，adapter 桥接本机 nearby 运行时。理由：PRD 技术路线已定的三件事（渠道会话管道复用、侧栏渠道分组、派生会话 id）全部是 channels Feature 既有机制（ADR-0030/0033）；独立 Feature 将复制渠道会话、绑定、路由三套设施。BLE 发现/收发/房间同步由独立 nearby 运行时（Rust 服务，桌面侧进程）承担，不进 crew 后端进程，Adapter 经 IPC 与之对话。

生命周期与配置：停用 product.channels → nearby 入站/出站随 Generation 下线；nearby 平台自身开关走 features.channels.nearby 平台配置节（复用 6AA 的读写闭环），单独启停不拖累其他平台。

产品范围（本期，按 PRD v2.1）：①管理中心——同伴页（发现、名片、群管理），Desktop 经 PageRegistry 生命周期接入；②对话——主对话侧栏 nearby 渠道分组，完整复用消息流与 Composer；③安全模型——私聊仅人与人、Agent 只在主人仍为成员的群内被 @ 触发，边界由后端会话路由强制。非本期（明确排除）：Agent 私聊、群全员 auto 触发（PRD 已否决）、第二套聊天 UI 与前端 driver 方案（已否决）、云端/局域网传输、nearby 运行时跨仓库迁出。

数据边界：nearby 会话即派生渠道会话（agent:main:nearby:{dm|room}:<hash>），路由入 channels.db 既有 channel_session_routes，不新建表；BLE peer/房间状态为运行时态，不落库。

完成标准与回退

同伴「迁移完成」以以下全部落地为准，此前演进计划继续将其列为未完成：nearby 平台 Adapter 随 channels Generation activate/deactivate 可逆；同伴页为可信 UI Contribution；nearby 会话经渠道会话分组投影；安全模型在后端强制并有契约测试。回退：撤销 PlatformEntry 注册与同伴页 Contribution，channels 其余平台与数据不受影响。
