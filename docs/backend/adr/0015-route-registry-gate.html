ADR-0015 · Route Registry 与运行期能力闸门

状态：Accepted · 日期：2026-09-03 · 阶段：插件架构 Stage 2 / 统一贡献注册表（§6.4、§6.5）

背景

目录插件的 API Router 由 Gateway 在应用构造期从 PluginManager._api_routers 字典挂载。FastAPI 路由树构造后固化：插件卸载只删字典记录，已挂载路由仍可到达，「禁用功能」对 API 层不成立（§2.3.6 缺口 4）。

决定

新增第四类贡献注册表 RouteRegistry（crew/features/routes.py），与 Driver/Context 注册表共用 FeatureScope 所有权与 Generation 语义。路由可逆性不由「热卸载路由」实现，而由「启动期从注册表装配 + 运行期闸门」实现：Scope 释放时注册项摘除，挂载点上的闸门依赖按注册表可见性返回统一的 capability_unavailable（HTTP 503）。

职责所有者契约
路由贡献注册crew/features/routes.pyRouteContribution（稳定 contribution_id + router + prefix）；冲突检测与新旧 Generation 原子替换同 Driver Registry。
Feature 安装入口FeatureInstallContext.register_api_routercontribution_id 默认取 feature_id；Scope 释放自动摘除。
目录插件桥接PluginContext.register_api_router旧 API 不变；同一贡献双写 legacy 字典（兼容）与 Route Registry（闸门事实来源），id 为 plugin:<name>。
启动期装配crew/gateway/app.py从 feature_runtime.routes.bindings() 挂载，确定性排序，日志带 owner Generation。
运行期闸门make_route_gate每请求检查注册表可见性；不可用返回 503 + capability_unavailable。

行为兼容

  • 插件启用且活跃时，路由路径、前缀（/api/plugins/<name>）与响应完全不变。
  • 旧 PluginManager.api_routers 属性与卸载回滚语义保留，其他消费方不受影响。
  • 内置路由器（sessions/wiki/work 等 23 个）本切片不迁——它们随各自 Feature Bundle 迁移（阶段 3 起）逐个进入注册表。

边界与后续

插件重新加载产生新 Router 对象时，已挂载的旧路由树不会自动换新——这属于 §6.5 的 restart_required 边界，本切片不做伪装热替换。后续：Cron/Sites/Wiki 等内置路由随 Feature 化逐个迁入；控制面「禁用 Feature → API 同步不可用」的端到端验收（§13.4）随第一个完整 Bundle 切片落地。

跨平台

纯注册表与 FastAPI 依赖注入，无平台分支。
