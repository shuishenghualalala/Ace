Acrew/dynamickanban

动态看板：多智能体 DAG 工作流引擎。

1. 职责

  • 规划并执行多智能体 DAG 工作流，维护工作流状态、任务依赖和结果。
  • 通过 mode=dynamic_kanban Execution Driver 对外提供交互入口，不参与核心 mode 路由。
  • 当前 Manager 与 Store 仍由 Host 构造；完整 Product Feature 生命周期在复杂并发迁移阶段收口。

2. 功能拆解

按子功能或核心流程拆解，这是本模块文档的重点。

子功能说明状态
Kanban Driver桥接 DynamicKanbanManager.interact()，保留现有 mode 和流式行为。已落地
工作流运行计划、DAG 调度、任务执行、暂停恢复与结果聚合。已落地
完整 Feature 所有权Manager、Store、运行 Task 与 Provider 状态迁入 Dynamic Kanban Generation。待迁移

3. 关键文件

文件作用
crew/dynamickanban/manager.py工作流交互入口与运行时创建。
crew/dynamickanban/orchestrator.pyDAG 工作流编排。
crew/dynamickanban/store.py按 Owner 隔离的工作流持久化。
crew/app.py迁移期 Dynamic Kanban Driver Adapter 的同步装配。

4. 数据模型与接口

Host 构造 Manager 后注册独立桥接 Generation；请求期间 Registry 自动持有 Lease。

mode = "dynamic_kanban"
generation = "product.dynamic-kanban-driver-adapter@g1"
execute = DynamicKanbanManager.interact

5. 当前存在的问题 / TODO

  • 桥接 Scope 当前只拥有 Driver 入口，尚未拥有 Store、运行 Task 和 Provider 状态。
  • Gateway 对旧 mode 的 sidechain 规则仍是兼容逻辑，后续应由 Driver Descriptor 表达。

6. 扩展点

  • 新增工作流入口应由 Dynamic Kanban Feature 注册能力，不得在 CrewApp.handle() 增加分支。
