Acrew/dynamickanban

动态看板：多智能体 DAG 工作流引擎。

1. 职责

  • 规划并执行多智能体 DAG 工作流，维护工作流状态、任务依赖和结果。
  • 通过 mode=dynamic_kanban Execution Driver 对外提供交互入口，不参与核心 mode 路由。
  • product.dynamic-kanban Bundle 在安装时创建并拥有 Manager、Store、运行任务、Driver 与 Route；当前切片正在独立验收。

2. 功能拆解

按子功能或核心流程拆解，这是本模块文档的重点。

子功能说明状态
Kanban Driver桥接 DynamicKanbanManager.interact()，保留现有 mode 和流式行为。已落地
工作流运行计划、DAG 调度、任务执行、暂停恢复与结果聚合。已落地
完整 Feature 所有权Manager、Store 与运行 Task 由同一 Generation 关闭；宿主提供的 LLM Provider 仍由宿主拥有。实施完成，待验收

3. 关键文件

文件作用
crew/dynamickanban/manager.py工作流交互入口与运行时创建。
crew/dynamickanban/orchestrator.pyDAG 工作流编排。
crew/dynamickanban/store.py按 Owner 隔离的工作流持久化。
crew/dynamickanban/feature.pyBundle、Service 和按 Owner 租用看板的 Team Consumer；安装失败由 Runtime 回滚。
crew/app.py同步激活 Bundle；显式嵌入用的旧 Driver setter 保留。

4. 数据模型与接口

Host 仅提交 Bundle 定义。安装时创建 Store 和 Manager，注册资源清理后再发布 Service、Route 与 Driver。请求入口持有同代 Lease，外层流关闭时逐层等待内部流清理。

mode = "dynamic_kanban"
generation = "product.dynamic-kanban@g1"
service = "dynamic-kanban"
execute = DynamicKanbanManager.interact

5. 当前存在的问题 / TODO

  • 独立生命周期与实际宿主装配的验收结果待测试记录收口；本页不代表阶段 4 全部完成。
  • Gateway 对旧 mode 的 sidechain 规则仍是兼容逻辑，后续应由 Driver Descriptor 表达。

Team 通过动态 Consumer Provider 访问当前代；每个同步 Store 调用持有 Lease，停用后不回退裸 Store。数据库行在停用和更新时保留。实现复用 pathlib、SQLite 与 asyncio，不新增平台信号分支；实际平台执行结果见测试记录。

6. 扩展点

  • 新增工作流入口应由 Dynamic Kanban Feature 注册能力，不得在 CrewApp.handle() 增加分支。
