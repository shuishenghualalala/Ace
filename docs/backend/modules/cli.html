CLI 子系统

crew/cli/ · 进程内命令树、非交互自动化、结构化输出 · 2026-09-05 更新

1. 定位

CLI 是 Crew 的本地自动化入口：默认交互式 REPL（chat），同时提供一次性对话（run）和覆盖全部后端模块的管理子命令。CLI 进程内消费 build_app() 装配的 Host Service，不依赖 Gateway 或桌面端；可选 Feature 的命令在执行时动态解析当前 Service。

自动化目标：所有命令支持 --json 结构化输出，失败返回非零退出码，可直接接入 pytest、shell 脚本与 CI。

3.1 交互会话续接

crew session list
crew chat --workspace-id <工作空间 ID> --session-id <会话 ID>
crew chat --continue
crew run --continue "继续这次工作"
crew run -p "继续这次工作"
printf '继续这次工作' | crew run

crew chat 启动与执行 /new 后显示当前会话 ID。显式续接在开启输入前查询当前账号的公开会话目录，并核对所选工作空间。不存在、属于其他账号、内部会话或工作空间不符时直接退出，不创建替代会话。续接用原 ID 读取历史和会话配置；终端不重印旧消息，可用 crew session show 查看。未传 ID 时沿用新建流程。

-c/--continue 在相同账号和工作空间中按最近更新时间选取第一份有消息的会话；置顶不改变最近判定，只创建未使用的空会话会被跳过。没有可续接内容时以退出码 1 结束且不创建新会话。--continue 不能与 --session-id 同时使用。非交互 crew run --continue 使用同一解析规则，把新问题追加到该会话，不生成第二个会话。

crew run 的消息可用位置参数、-p/--prompt 或非 TTY stdin 提供，三者只能选一个；stdin 读取后去掉首尾空白，空输入以退出码 1 结束，超过 1,000,000 字符同样拒绝。交互终端未提供消息时直接报错，不会阻塞等待输入。

3.2 本地技能市场目录

crew skill source add <绝对目录或 HTTPS 清单 URL> --label 团队技能
crew skill source list
crew skill source remove <绝对目录或 URL>
crew skill source refresh <URL 或展示名称>
crew skill import <含 SKILL.md 的目录> [--slug 名称]
crew skill list --store --json

市场源登记在 CREW_HOME/skill_market_sources.json，不影响 config.yaml。本地目录必须是已存在的绝对路径，不能与用户技能目录或固定的本地技能目录重叠；最多登记 16 个。目录内的技能与固定本地源一起出现在技能商店，带 market_source 和 market_label，同名时固定本地源优先。安装市场目录中的技能会复制整套目录到用户技能目录，之后源目录变化不自动同步；卸载只删除副本，不触碰源目录。移除市场目录只影响后续列表，已安装副本保留。移除可用路径、URL 或展示名称；同名展示名称有多个时拒绝并要求改用路径/URL。Ace 不从这里执行为技能中的任何代码。来源列表同时显示可用技能数和 URL 缓存不可用状态；登记与刷新响应也带同一组诊断字段。

远程市场源只接受 https:// 清单，拒绝账号密码、token/key/secret 等敏感查询参数、重定向、本机/私有地址和无法解析的主机。清单格式为 {"version":1,"skills":[{"slug","name","description","content"}]}，最多 50 个技能，单技能正文最多 64 KiB，清单最多 256 KiB，下载超时 5 秒。清单中的 content 按 SKILL.md 缓存到 CREW_HOME/skill_market_cache/ 后与本地源同样列出和复制安装；移除 URL 源会清理该缓存。登记中的缓存路径必须位于该目录，越界条目不会被扫描或删除。crew skill source refresh 重新下载清单并替换缓存，抓取失败时保留旧缓存和旧登记。HTTP 地址、Git 仓库源和插件市场清单仍不支持。

crew skill import 接受一个已准备好的技能目录，核对 SKILL.md 存在后走同一套路径 containment、审计和原子发布，复制到用户技能目录；--slug 缺省取目录名。它跳过面向生成技能的正文长度/描述完整性编辑检查，但不会跳过文件安全校验，也不执行技能内容。目标已存在或缺少 SKILL.md 时失败退出。

同一能力通过 GET /api/skills/sources、POST /api/skills/sources、DELETE /api/skills/sources?path=… 和 POST /api/skills/import 暴露，供桌面或 Web 界面后续接入。变更接口要求管理员，本机 owner 视为管理员；注册与导入在工作线程执行，不阻塞 Gateway 事件循环。目录错误返回 400 和稳定的 code（如 source_exists、source_overlaps_skills）。

3.3 MCP HTTP/SSE 端点探测

crew mcp servers probe --url https://mcp.example.com/mcp --transport http
crew mcp servers probe --name remote --url https://mcp.example.com/mcp --headers '{"Authorization":"***"}' --json

probe 在保存前连接 HTTP/SSE 端点并列出工具，不写入 config.yaml、不注册工具、不启动常驻重连。地址必须通过与新增相同的校验；stdio 预检会执行宿主命令，因此不支持，仍需保存后连接。带 --name 时用已保存同名服务的 env/headers 与 URL 查询参数补全 ***，名称不存在时直接报错；表单无需接触明文。成功返回工具数量、名称和耗时（最多回报 50 个名称，数量单独给出），失败以非零退出码结束并按显示边界脱敏错误（URL token/userinfo、Authorization、已知密钥前缀）。加 --json 时成功结果同时以结构化 JSON 输出。

4. 安全命令

安全命令直接调用 crew.security_service / security_rules / security_audit，等价于本机宿主身份，不需要桌面端 proof。安全写操作全部是显式子命令，不提供隐式一键放行开关。

命令用途
security check-terminal --command终端守卫判定：hardline / dangerous / classify_command，输出 allow/ask/blocked。
security check-file --path --operation文件读/写/删除/补丁策略判定，输出 base 策略/规则/审批结果。
security check-network --url公网目标解析与联网授权判定。
security fake-file-actions / fake-network-actions制造文件/网络审批请求，支持 --decision 同进程决策。
security sandbox-run通过原生安全运行时执行命令，验证文件/网络沙箱边界。
进程内审批状态：审批请求保存在当前进程内存中。跨 CLI 进程无法看到另一进程创建的 pending 请求；测试完整决策链路时用 security fake-executions --decision <once|session|always|reject> 在同一进程内创建并立即决策。

4.1 会话工具权限审批

crew chat 在当前回合接收工具审批，显示动作、目标和需要追加的权限。输入 once 可允许当前动作执行一次，输入 reject、空行或结束输入则拒绝。CLI 读取当前任务的审批并在同一进程内提交决定。回合退出时，尚待处理的本回合请求按原作用域拒绝。

crew run 遇到需要人工批准的工具动作时，通过同一审批服务拒绝请求并以状态码 2 退出。JSON 摘要包含 status=stopped 和 error_code=approval_required，stream-json 保留拒绝终态事件。--yes 仅批准 Plan 内容。Plan 获批后，执行回合沿用原会话及其工作区。

4.2 模型追问

crew chat 按顺序显示普通追问和选项。单选输入编号，多选用逗号分隔。问题允许自定义时可选「其他」，文本题直接填写。提交使用选项的原始值，整组作答完成后才送给模型。/cancel、Ctrl-C 或 EOF 可取消当前问题组。

conversation_followups 将本回合的输入和审批串行化，按账号、可见会话、原请求和问题 ID 校验 FollowupWaiter。工具超时或回合退出会关闭对应输入。答案经原工具历史路径保存。crew run 无终端输入时，模型仍收到追问工具的可恢复错误。

5. Wiki Service 消费边界

每个 Wiki 叶子命令都在真正执行时调用 acquire_service_lease(KNOWLEDGE_SERVICE_KEY)。同步命令在返回或异常时释放 Lease；异步命令在整个 await 周期持有 Lease。这样新命令只会看到当前 Active Generation，旧 Provider 会等待在途命令结束后再关闭。

没有 product.wiki 运行记录的嵌入宿主可以提供外部 knowledge_service；一旦产品 Feature 存在但不可用，CLI 不回退到旧对象。SessionStore 仍属于 Host，但 Wiki Agent 会话命令同样先经过 Service Gate。文件读取只处理用户传入的本地路径，上传解析、媒体处理和 Wiki 数据目录均留在 Provider。

5.1 Work Service 消费边界

Work 命令通过 _set_work_handler 显式注册，入口解析 WORK_SERVICE_KEY 并把同代 Service 限定在命令上下文。同步返回、异常及异步取消都释放 Lease；同步 callable 返回 awaitable 时，Lease 与 Service 上下文延续至 awaitable 完成或取消，同时普通同步 handler 仍直接返回 CliResult。存在 product.work 记录时不回退到宿主残留字段；无该记录的嵌入式宿主仍可注入外部 Service。参数、Owner 和业务返回结构保持兼容。见 ADR-0026。
