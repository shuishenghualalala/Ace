CLI 子系统

crew/cli/ · 进程内命令树、非交互自动化、结构化输出 · 2026-08-13 重构

1. 定位

CLI 是 Crew 的本地自动化入口：默认交互式 REPL（chat），同时提供一次性对话（run）和覆盖全部后端模块的管理子命令。CLI 进程内直调 build_app() 装配的 service/store，不依赖 Gateway 或桌面端；与 occ 默认 CLI 的进程内架构一致。

自动化目标：所有命令支持 --json 结构化输出，失败返回非零退出码，可直接接入 pytest、shell 脚本与 CI。

2. 架构

2.1 文件布局

文件职责
crew/cli/main.py全局参数提取（任意位置）、argparse 子命令树、统一分发与退出码。
crew/cli/app.pyCliContext 懒加载 App、running_app() 生命周期、CliResult/emit 输出。
crew/cli/chat.py交互 REPL 与一次性 run（text/json/stream-json）。
crew/cli/management.pyconfig / session / workspace / task / cron / system / migrate。
crew/cli/knowledge.pywiki / skill。
crew/cli/integration.pymcp / plugin / channel / runtime / browser / weixin-login。
crew/cli/security.pysecurity：审批模式、请求决策、规则、审计、capabilities。
crew/cli/content.pysite / work。
crew/cli/weixin_login.py微信扫码登录（保留旧入口）。

2.2 全局参数

参数说明
--owner / -oowner_account_id，默认 CREW_CLI_ACCOUNT 或 local。
--workspace-id默认工作空间，默认 default。
--config指定 config.yaml 路径。
--json所有命令输出结构化 JSON。
--quiet文本模式下抑制人类可读输出。

全局参数可从命令行任意位置提取（例如 crew --json cron list 与 crew cron list --json 等价）。

4. 安全命令

安全命令直接调用 crew.security_service / security_rules / security_audit，等价于本机宿主身份，不需要桌面端 proof。安全写操作全部是显式子命令，不提供隐式一键放行开关。

命令用途
security check-terminal --command终端守卫判定：hardline / dangerous / classify_command，输出 allow/ask/blocked。
security check-file --path --operation文件读/写/删除/补丁策略判定，输出 base 策略/规则/审批结果。
security check-network --url公网目标解析与联网授权判定。
security fake-file-actions / fake-network-actions制造文件/网络审批请求，支持 --decision 同进程决策。
security sandbox-run通过原生安全运行时执行命令，验证文件/网络沙箱边界。
进程内审批状态：审批请求保存在当前进程内存中。跨 CLI 进程无法看到另一进程创建的 pending 请求；测试完整决策链路时用 security fake-executions --decision <once|session|always|reject> 在同一进程内创建并立即决策。
