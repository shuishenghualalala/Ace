Tcrew/tools

工具注册、schema 暴露、执行与结果回灌；内置工具集 + 执行流水线 + 权限披露 + 安全审批 + 输出处理。

1. 职责

  • 注册与发现：Registry 管理工具注册、schema 暴露、按需加载（渐进式披露）。
  • 执行与回灌：内置工具集 + 执行流水线（输入校验 / 权限 / 结果处理），错误统一回灌给模型。
  • 安全与治理：文件/网络/外部运行时授权、敏感脱敏、终端命令防护、文件读取上限。
  • 边界：不含 Agent 循环（crew/agent/loop）、记忆（crew/memory）、工作区（crew/team）；这些模块通过本模块的 Registry 消费工具。

2. 内置工具清单

下表列出 Ace 当前内置的工具（按功能领域分组）。mcp_client 会动态接入外部 MCP server 的工具，不在此列。

2.1 文件系统

工具说明
file_read读取 UTF-8 文本文件，返回带行号内容（「行号: 内容」）；默认/最多 2000 行，offset 负数尾读；≥10 MiB 流式读取；头部嗅探拒绝二进制（引导 vision_analyze / wiki）；UTF-16 自动转码。
file_write新建、覆盖或追加 UTF-8 文本。修改已有文件前先读取，覆盖必须读完同一版本。保留 UTF-8 BOM 和文件主要行尾样式。
file_delete删除明确指定的文件，不递归删除目录；工作区外路径需精确授权。
patch传入一对 old 和 new，或非空 edits。new 可以是空字符串。局部读取支持所读范围内的精确修改。
glob按 glob 模式查找文件（如 **/*.py），按修改时间从旧到新排序。支持 limit 和 offset。
grep按正则搜索文件内容，支持文件列表、内容和匹配计数。head_limit=0 取消条数限制，输出仍受体积上限约束。

file_read 返回 file_version、read_complete 和可用的 next_offset。patch 和 file_write 可传 expected_version，省略时使用会话已观察的版本。读完同一版本所有未裁剪的分页后可以覆盖整份文件。stale_file 表示文件已变更或移除，Agent 应重新读取并重新计算修改。只读、无法替换和匹配歧义也带有独立错误码。

每个 patch 编辑项先在同一份原文快照中精确定位。要求唯一命中且已完整读取时，可通过 Unicode 归一化、引号与行尾空白查找候选。写入前把候选两端映射回原文并复核片段，返回的偏移与长度以 LF 归一化后的原文计。批量编辑按原文范围检查重叠后一次写入。同一行的全角字符、其他字段和片段外空白保持原样。命中落在单个兼容字符展开结果的内部时，工具返回 patch_no_match，可扩大原文片段后重试。

搜索结果用 scan_complete 标记扫描是否完成，用 truncated 标记分页或预览截断。未完成时保留已匹配的结果，通过 partial_reasons 和 search_notice 报告原因，例如超时、目录读取失败或文件超限。Python 路径提供已扫描和跳过计数。结果提供 next_offset 时，使用相同搜索条件在文件集合未变的情况下续查。扫描未完成时缩小路径或过滤条件重新搜索。

托管安全模式用 Python 搜索并保留验证式文件读取和链接剪枝。停止时会在下一次检查退出，当前的系统调用或正则匹配需要先返回。使用原生 ripgrep 时，超时、缓冲超限和取消均会终止本次拥有的子进程。

按请求停止工具

Gateway 按账号、会话和 request_id 查找本次请求，向前端返回 requested 或 not_active。正在执行的回合先收到中断信号，工具有机会提交结果。后续强制取消也会再次检查请求身份。同会话内其他已受理的请求继续排队。

工具运行器分别观察线程任务、终端退出事件及已发出的 MCP 请求。终端通过进程注册表停止进程树，退出事件触发后才能确认收尾。MCP 只取消对应的 SDK 请求，其他请求可继续使用连接。远端尚未返回、线程仍在执行或协程未在宽限期内退出时，工具结果携带 tool_exit_unconfirmed 和 exit_confirmed=false。工具卡和历史保留该次观察结果。运行时任务收到取消请求后仍可查询，退出确认后才写终态。

2.2 终端与进程

工具说明
terminal执行 shell 命令。前台输出按 UTF-8 字节位置发送，转后台时保留进程和任务标识。执行结果区分完成、非零退出、超时、取消和后台接收。
process管理终端进程，支持 list、poll、log、wait、kill 和 stdin。

终端日志合并 stdout 和 stderr。process(action='log', task_id=..., cursor=0) 从头读取，后续把返回的 next_offset 传给 cursor。字节页保持有效 UTF-8。gap 标记请求范围的缺失或游标未对齐。按行读取时，省略 offset 获取尾页，指定 offset=0 从第一行读取。

每个进程保留有界内存尾窗，任务日志最多落盘 64 MiB。output_retention 标记保留状态，output_truncated 标记内容缺失。Gateway 重启后可按同账号的 task_id 查询已落盘的日志。Windows 终端优先在开始执行前进入 Job Object，停止后等待输出和任务状态结算。

process(action='wait') 订阅该进程的完成事件，由输出线程在完成日志与任务状态结算后唤醒。回合取消会移除自己的订阅，后台进程继续由任务注册表管理。重启认领的进程通过短时异步存活检查结算。前台终端也复用完成事件及原有的进度刷新间隔，日志和其他阻塞操作仍在工作线程执行。

2.3 网络与搜索

工具说明
web_searchExa 托管 MCP 语义搜索（匿名免费、无需 API key，可选 EXA_API_KEY 提额），按 provider 链降级（exa → searxng），返回标题/链接/摘要。
web_extract抓取 URL 转 Markdown。正文内联上限 40k 字符，超限全文落盘到 {CREW_HOME}/tool-results/ 并在结果中给 full_text_path（file_read 按需读取），内联部分保头尾中间截断；同 URL 结果进程内缓存 15 分钟（50MB LRU），授权之后才查缓存。结果带 cached 标志。
vision_analyze分析本地图片的基础元信息（PNG/JPEG 尺寸等）。

2.4 浏览器自动化

浏览器插件注册两个按 action 分发的模型工具，执行仍由 BrowserManager 核对账号、会话、页面代次和审批，并经签名连接交给桌面宿主。独立 Gateway 或 CLI 未连接桌面宿主时不能执行浏览器动作。引擎见 浏览器自动化设计。

工具说明
browser_use导航、结构快照、定位、点击、填表、可取消等待、当前会话的标签管理及请求人工接管。下载、上传及敏感动作沿用浏览器治理策略。
browser_use_advanced经 tool_search 按需披露。从当前页保存截图、将图像提供给视觉模型或读取控制台与网络记录；高级操作仍受执行策略约束。

浏览器宿主按账号 Profile 创建持久 Electron Session，同一账号的 Crew 会话复用该 Session，以保留站点登录状态；Crew 会话之间仍分别校验标签、页面引用和控制权。因共享 Session，同源 Cookie、localStorage 与 IndexedDB 可被该账号的不同 Crew 会话复用，不构成聊天级站点存储隔离。

浏览器插件同时挂载 /browser-use 和 /web-gui-tester。后者指导模型用实际界面交互做黑盒测试，区分结构观察、已查看的截图与不能验证的环节。它不注册额外工具，不改变审批或网络规则；浏览器插件关闭时，两项从后续回合的模型技能索引隐藏。

没有桌面宿主时，浏览器 RPC 返回可重试错误并带稳定 code=browser_host_unavailable；宿主已连接但仍在初始化返回 browser_host_initializing，宿主被替换返回 browser_host_replaced。这些失败发生在发送 RPC 之前，不会声明动作已执行或浏览器已停止。

浏览器等待文本时，text 在任一同文元素可见时满足，text_gone 在可见匹配为空时满足。两个条件沿用命令的剩余截止时间。停止回合时，Gateway 通过原浏览器宿主连接取消该标签页的等待。宿主按账号、连接和原请求 ID 核对，已经执行的等待收尾后释放账号队列。

开始等待时绑定当前账号、会话、目标标签与控制代次。定时阶段释放账号队列，长等待定期查询已绑定目标。文本条件继续由 Playwright 按短时段观察，每段结束后让其他会话使用队列。开始观察、继续及生成快照前都复核目标和控制权。无原生定向目标的驱动沿用原等待路径。

视口与元素截图统一使用 Electron capturePage，元素先滚入视口再按当前边界捕获。整页正常时沿用 Playwright；字体探测超过 2 秒时使用 CDP 和内容尺寸。CSS 输出缩放到目标尺寸，device 保留原生像素。页面身份、PNG/JPEG 校验和输出目录授权在所有路径上保持一致。

截图执行段受原命令截止时间约束，超时后释放账号队列，后续操作无需等待旧调用落定。每个标签最多保留两个超时后仍在浏览器中执行的捕获；达到上限时新请求快速返回 screenshot_pending，旧调用结束后释放名额。该计数不代表截图已经成功，也不改变页面或标签生命周期。

MCP 配置校验与脱敏HTTP/SSE 地址必须是绝对 http(s) URL，不能内嵌账号密码；headers 必须是字符串对象，名必须是合法 HTTP token，值不能包含换行，最多 128 项且单值不超过 8192 字符；stdio 的 args 必须是字符串数组，最多 128 项且单项不超过 8192 字符，env 最多 128 项、键不能为空或含 =/NUL、单值不超过 8192 字符。auto_connect=false 时保存后只登记不连接，手动「重连」仍可启动；更新请求未携带 auto_connect 时保留已保存值，停旧 worker 失败仍以 200 返回配置已保存的 warning。GET 状态接口脱敏 env 敏感键、Authorization/Cookie 等 headers 以及 URL 查询中的 token/key，落盘仍保留原值。更新时 env/headers 中值为 *** 的键以及 URL 查询中值为 *** 的参数保留原值；持久化配置是状态接口的立即真值，worker 可在后台继续重连。已落地

MCP 状态工具上限GET /api/mcp/servers 每个服务最多回报 50 个工具名，另以 tool_count 给出真实数量；Web/Desktop 用该计数显示。异常状态下 tools=None 或非对象配置按空工具/空配置处理，不使整个状态接口 500。状态与探测错误按显示边界脱敏 URL query/userinfo、Authorization 和已知密钥前缀。持久化配置与 worker 仍在使用配置不一致时返回 config_pending。已落地

5. 数据模型与接口

核心类与关键签名：

class Tool:  # 注册的最小单元
    name: str; toolset: str; schema: dict
    to_schema() / ui_meta() / available() / async run(args) -> str | ToolOutput

class Registry:
    register(tool) / unregister(name) / get(name) / names()
    list_schemas() -> list[dict]              # 暴露给模型
    async execute(tool_call) -> ToolResult    # 异常统一包装为 is_error
    async resolve_permission(tool_call) -> ToolPermissionDecision | None
    result_policy(name, args) -> ToolResultPolicy

registry.register(
    ...,
    result_retention="temporary|resource|instruction|important",
    result_identity_fields=("path",),
    result_policy_resolver=optional_callable,
)

result_identity_fields 用于资源和指令去重；需要根据 action 动态判断时使用 result_policy_resolver。未声明值默认为 important，因此外部 MCP 和旧插件不会被误压缩。

Schema 私有字段约定（渐进式披露读取）：

{
  "name": "glob", "toolset": "file",
  "_crew_always_load": true,    # 常驻加载，不进延迟目录
  "_crew_should_defer": true,   # 显式延迟加载
  "_crew_is_mcp": true,         # MCP 来源的工具
  "display_name": "查找文件",    # UI 展示名
  "x_search_hint": "..."        # 检索关键词
}

执行流水线（pipeline，纯函数）：

validate_arguments(tool_name, parameters, args) -> str | None   # Stage 2 输入验证（JSON Schema）
check_permission(...) -> allow | deny | ask                      # Stage 4 权限（ask 由调用方走交互）
truncate_or_persist(...)                                         # Stage 6 结果处理（大结果落盘）

文件安全读取（file_utils，统一整读上限）：

MAX_READ_FILE_BYTES = 512 * 1024 * 1024
read_verified_bytes(path, *, max_bytes=None) -> bytes  # 读前 metadata 预检 + take(max+1) 复查
snapshot_file(path, *, max_bytes=None) -> FileVersion  # 身份 + 内容 hash，拒绝多硬链接写入

交互等待语义：追问与权限确认（2026-09-17）

wait_for_answer 的等待默认有界：调用方未显式传 timeout 时使用装配层注入的默认上限 runtime.interaction_timeout_seconds（默认 3600s，配置 0 为默认不限）——用户一直不选，到点按「用户未回答」收尾（返回空答案），回合不再无限挂起。显式传 timeout（含 None/0 维持不限语义）始终优先于默认值。ask_followup_question 与权限确认共用这套语义。

交互 CLI 为普通问题绑定回合内输入回调。工具先注册 waiter，再异步启动终端输入，等待、超时和答复历史继续使用同一核心机制。等待结束会通知 CLI 关闭同一问题的输入。权限确认以及 Gateway 的事件处理沿用各自通道。CLI 与终端追问

权限确认等待（ToolRunner._wait_permission_answer）与 interrupt 竞争（FIRST_COMPLETED）：interrupt 先到即结算挂起的追问（cancel_followup 回灌取消标记、清理 waiter 注册），返回空答案——上层按拒绝处理（安全默认），回合随后走 interrupt 收尾；回答或超时先到则 interrupt 等待 task 立即取消，绝不残留永久挂起的 task。单工具的真实执行段另有看门狗与中断语义，见 agent 模块文档。

file_read 读取引擎（2026-09-18）

file_read 由「整读后截断」改为完整的读取引擎（窗口语义对齐 dsh tool-fs 的 read，尾读与编码策略对齐 kimi agent-core 的 Read），核心在 crew/tools/file_utils.py，builtin.py 只做授权与编排：

  • 窗口语义：默认返回前 2000 行（同时是上限，tools.file.read_max_lines 可调）；输出为「行号: 内容」（文件绝对行号），正文后附续读 footer（如「(已显示第 1-2000 行，共 54321 行。用 offset=2001 继续读取。)」）；单行超过 2000 字符中段截断并在 hint 标注行号；输出预算沿用 tools.file.read_max_chars（默认 100000），超限按整行取舍而非硬切字符串；offset 越界报错（空文件 offset=1 除外）。
  • 尾读：offset 为负数表示从文件末尾读取（如 -100 读最后 100 行，|offset| ≤ 2000）；limit 从尾窗口头部截取；输出预算超限时从窗口头部丢行，保留最接近末尾的内容。
  • 流式路由：stat 一次拿大小；<10 MiB 整读，≥10 MiB 走身份校验句柄流式读取（open_verified_read，增量严格 UTF-8 解码）；行缓冲封顶 2001 字符，巨型单行内存恒定；total_lines 始终为全文件精确值。读取期间身份变化（size/mtime）仍按冲突拒绝。
  • 内容嗅探：头部 8192 字节判定——BOM（UTF-32/16/8）→ 魔数表（PNG/JPEG/GIF/ZIP/OLE/ELF/PDF 等）→ 无 BOM UTF-16 奇偶 NUL 启发式 → NUL 存在性 → 控制字符比例（>30%，避免误伤 ANSI 日志）。扩展名黑名单保留为快速路径。二进制从「温和跳过」改为 ToolError，消息按类型引导：图片→vision_analyze，文档→wiki_capture_attachment / skills。
  • 编码策略：UTF-8 严格解码，失败显式报错并提示先用 iconv 转换（替代旧的静默替换）；UTF-16（BOM 与无 BOM）≤10 MiB 自动转码显示，hint 注明编码并提示编辑前先转 UTF-8；超限报错。
  • 写保护不变：成功读取后记录 stat-only FileVersion（观察只消费 device/inode/size/mtime_ns 四元组）；写入侧 stale 校验与 digest 复核仍在写入时刻整读完成，流式化不影响 CAS 语义。
  • 压缩恢复：post_compact._reread_file_for_restore 改用共享的 slice_text_window（宽容归一，负 offset 尾读语义与工具一致），恢复视图不再把负 offset 钳成 1。

进程重启后的工具结果恢复

工具开始前，执行器先把最终使用的参数和调用身份写入会话日志。返回时保存模型实际收到的文本、工具状态和可用的图片数据。大结果额外记录完整文件的 SHA-256。重启时由应用托管目录和调用编号定位文件，验证成功后提供完整文件路径。文件已被替换或删除时，模型仍可查看执行时保存的头尾预览。

Gateway 启动时定位已失去写入进程的开放回合，按账号、当前会话分支、请求、模型步骤和工具调用编号配对。模型结果遵循原调用顺序，图片集中放在同一步所有工具结果之后。已有结果保留，缺失部分通过一次带版本检查的 SQLite 事务补入，随后记下该轮中断结局。若历史顺序需要调整，原分支和已有引用仍可读取。

有执行意图而缺少完整结果时，恢复消息要求先核对实际状态和已有改动。只有调用声明时会标明尚未派发。旧版记录只确认工具已返回时，会标明原始内容缺失。恢复不会启动工具，原发送回执继续沿用其既有状态。

对话中安装 MCP

配置工具 mcp_install 接收服务名和结构化传输配置；可带 auto_connect=false 只保存不连接，状态返回 saved_not_connected，之后由管理页或 mcp_reload 手动启动；mcp_update 改为 false 会停 worker、注销工具并保留配置。Gateway 从已认证的管理员连接授予前台回合资格。CLI 交互会话使用原有权限确认。线程级任务、子 Agent、Plan 和普通账号的前台请求继续按原工具边界运行。

工具在执行前通过既有会话权限卡确认一次。确认绑定账号、会话、请求、调用、配置文件和内容摘要。保存复用 Config.add_mcp_server，完成后仅连接新增服务。响应给出保存、连接与工具数，同名同配置复用，同名冲突保留已存在配置。工具卡和工具历史隐藏 env 与 headers 的值。

默认可使用 HTTP 或 SSE。stdio 仍要求宿主启动已被显式启用，且会话使用允许宿主进程的既有模式。注册表更新后，下轮重新计算当前会话的工具范围。连接到远程 MCP 后，首次调用仍走原有联网权限；审批归属于公开的真实请求会话和宿主任务。

只读工具 mcp_status 列出当前已配置服务的名称、传输、脱敏目标、连接状态（connected/reconnecting/failed/starting/not_started）、工具数、auto_connect 与有限错误正文，用于对话内诊断。它不返回 env、headers 或完整 URL；无法解析或端口非法的旧地址只返回空目标，不使整个查询失败。仅在管理员前台上下文中可见，子 Agent、Plan 和普通账号的前台请求继续隐藏。

移除使用 mcp_remove：管理员在前台对话确认一次，批准绑定账号、会话、请求、调用、配置文件和当前服务配置摘要。配置删除后断开运行实例；已不存在的服务按幂等返回；配置已删除但运行实例移除失败时如实返回 warning，不回滚配置。服务配置在批准后发生变化时，原批准失效。

重连使用 mcp_reload：用现有已批准配置停止旧 worker 并新建连接，重置重连预算；不修改配置文件。返回 reloaded 与该服务当前状态，失败后仍可通过 mcp_status 查看原因。

更新使用 mcp_update：一次批准同时绑定旧配置与新配置摘要，批准后旧配置被替换则拒绝执行。配置持久化后停止旧 worker 并重连，返回 changed、reloaded 与当前状态；auto_connect=false 时只保存、停止旧 worker 并返回 reloaded=false，之后可手动 reload。重连失败保留新配置并提示可用 mcp_reload 重试，传输方式、命令、URL、环境变量和请求头均可替换。

MCP 服务生命周期按服务名串行：并发 add/reload/remove 不会同时停止旧 worker 并追加两个替代连接；不同服务仍可并行。关闭竞态下晚到的 worker（含初始自动启动）会立即停止并从列表移除，不留下协程或连接。

MCP 工具结果

Worker 从 MCP SDK 中读取文本、图片和结构化字段。非空结构进入模型的工具正文，标记为 Structured content。当原文本已包含同一 JSON 对象时保留原文。结构字段保持文本载荷，图片仍由协议图片块提供。MCP isError 响应继续结算为工具失败，正文同时保留可用的结构化错误详情。

混合结果先为完整图片保留外层 JSON 的预算，再按转义后的字符数截取文字的首尾。图片组本身放不进预算时，正文显示原因且省略该图片组。Worker 诊断采集将结构字段传为映射，复用既有敏感键脱敏。模型、历史和回执仍通过原工具结果的权限及持久化链路。

MCP 工具执行进度

通过授权的 MCP 调用随 SDK 请求注册独立进度接收器。收到有限数值时，使用发起调用的上下文向现有工具通道发送进度，帧仍携带原会话、请求和工具调用 ID。进度文案限制为单行 400 字符，没有文案时显示已完成数和有效总量。

每次调用最多保留一条待发进度，发送间隔不小于 250 毫秒。SDK 回调不等待桌面发送。同一服务上的其他调用继续独立收发。调用完成、超时或停止时清理转发任务。进度不延长排队和执行的绝对截止时间，也不作为模型工具输出和持久工具结果保存。

桌面只接受当前请求中已知且仍在运行的工具更新。每个工具行只显示最新一条 MCP 进度。完成或停止后收起进度，迟到帧无法绑定新请求或复活已结束的工具行。

MCP 调用截止时间

排队和执行共享调用的绝对截止时间。worker 在出队、执行和调用方等待三个位置复用同一错误映射。未派发标记为 mcp_queue_timeout，已派发标记为 mcp_call_timeout 并说明副作用状态未知。Registry 将结构化异常转成模型正文与工具元数据。UI 和持久回执都按失败处理，调用方保持原取消和重连规则。

MCP 同服务调用调度

每个已配置服务在同一连接上最多同时执行两条明确标注为只读且声明一致的请求。调度按当前工具清单分类，变更、未知、冲突声明和重复工具名统一独占，队首独占请求等待其他调用收尾，后续只读请求继续排队。原队列容量包含尚未派发的队首。每次请求沿用自己的安全审批、上下文和绝对截止时间，断线后只恢复尚未派发且未过期的请求。

完整模型响应进入 Agent 分段时读取当前服务清单。远程 MCP 在 Full Access 或 AutoReview 已有覆盖该端点的会话授权时可进入只读并发段。已声明独占的工具仍单独串行。启动帧发出后再复核清单及授权，执行仍逐次走现有权限入口。未授权和逐次审批流程按序推进。

连接关闭时，已派发调用以 mcp_connection_lost 结算，副作用状态为 unknown。被清退的队列及已停止连接的新请求返回 mcp_unavailable，副作用状态为 none。单次调用响应异常但连接探活成功时，本次用 mcp_call_failed 结算，其他调用继续共享该连接。

本次更新：工具与 MCP 观测（2026-09-23）

工具执行边界记录逻辑调用、实际工具输入输出和错误状态；MCP 队列项携带不可变 observation context，常驻 worker 出队后 attach，完成后 reset，避免跨请求串线。搜索、浏览器、渠道和外部 agent 边界保留 coverage/black-box 标记，未把不可见的第三方内部状态伪装成细粒度 span。
