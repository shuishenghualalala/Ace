Tcrew/tools

工具注册、schema 暴露、执行与结果回灌；内置工具集 + 执行流水线 + 权限披露 + 安全审批 + 输出处理。

1. 职责

  • 注册与发现：Registry 管理工具注册、schema 暴露、按需加载（渐进式披露）。
  • 执行与回灌：内置工具集 + 执行流水线（输入校验 / 权限 / 结果处理），错误统一回灌给模型。
  • 安全与治理：文件/网络/外部运行时授权、敏感脱敏、终端命令防护、文件读取上限。
  • 边界：不含 Agent 循环（crew/agent/loop）、记忆（crew/memory）、工作区（crew/team）；这些模块通过本模块的 Registry 消费工具。

2. 内置工具清单

下表列出 Ace 当前内置的工具（按功能领域分组）。mcp_client 会动态接入外部 MCP server 的工具，不在此列。

2.1 文件系统

工具说明
file_read读取文本文件，支持 offset/limit 分页、保留行尾符、自动处理 UTF-8 BOM。
file_write写入文件（覆盖或追加），自动创建父目录；保留原文件行尾符与 BOM；拒绝敏感系统路径。
file_delete删除明确指定的文件，不递归删除目录；工作区外路径需精确授权。
patch对文本文件执行替换补丁（old → new），保留行尾符与 BOM。
glob按 glob 模式查找文件（如 **/*.py），优先使用托管 rg，Python 兜底。
grep按 ripgrep 正则搜索文件内容，优先使用托管 rg，Python 兜底。

工具说明
terminal执行 shell 命令；支持前台/后台、超时、精确权限申请与沙箱策略。

2.3 网络与搜索

5. 数据模型与接口

核心类与关键签名：

class Tool:  # 注册的最小单元
    name: str; toolset: str; schema: dict
    to_schema() / ui_meta() / available() / async run(args) -> str | ToolOutput

class Registry:
    register(tool) / unregister(name) / get(name) / names()
    list_schemas() -> list[dict]              # 暴露给模型
    async execute(tool_call) -> ToolResult    # 异常统一包装为 is_error
    async resolve_permission(tool_call) -> ToolPermissionDecision | None
    result_policy(name, args) -> ToolResultPolicy

registry.register(
    ...,
    result_retention="temporary|resource|instruction|important",
    result_identity_fields=("path",),
    result_policy_resolver=optional_callable,
)

result_identity_fields 用于资源和指令去重；需要根据 action 动态判断时使用 result_policy_resolver。未声明值默认为 important，因此外部 MCP 和旧插件不会被误压缩。

Schema 私有字段约定（渐进式披露读取）：

{
  "name": "glob", "toolset": "file",
  "_crew_always_load": true,    # 常驻加载，不进延迟目录
  "_crew_should_defer": true,   # 显式延迟加载
  "_crew_is_mcp": true,         # MCP 来源的工具
  "display_name": "查找文件",    # UI 展示名
  "x_search_hint": "..."        # 检索关键词
}

执行流水线（pipeline，纯函数）：

validate_arguments(tool_name, parameters, args) -> str | None   # Stage 2 输入验证（JSON Schema）
check_permission(...) -> allow | deny | ask                      # Stage 4 权限（ask 由调用方走交互）
truncate_or_persist(...)                                         # Stage 6 结果处理（大结果落盘）

文件安全读取（file_utils，统一整读上限）：

MAX_READ_FILE_BYTES = 512 * 1024 * 1024
read_verified_bytes(path, *, max_bytes=None) -> bytes  # 读前 metadata 预检 + take(max+1) 复查
snapshot_file(path, *, max_bytes=None) -> FileVersion  # 身份 + 内容 hash，拒绝多硬链接写入

6. 当前存在的问题 / TODO

  • file_read 对 ≤512 MiB 的大文本文件仍是「整读后截断」：读整个文件只为返回 read_max_chars（默认 100000 字符），存在内存浪费；后续可改为按 offset/limit 流式读取。
  • file_write 覆盖写旧文件时 snapshot_file 整读旧文件（用于 BOM/行尾保留与写前校验）；append 场景下为必要读取，普通覆盖场景可优化为只读头部。
  • 各工具 schema 的参数枚举与必填校验主要依赖执行期业务校验，schema 层未做严格枚举约束。

7. 扩展点

  • 新增工具：在 register_builtin_tools 或对应领域 register_xxx_tools 里 registry.register(...)，声明 schema + handler（async）+ display_name + search_hint。
  • 声明结果生命周期：列表/日志等可重查结果用 temporary；file_read 等文件读取也用 temporary（旧分片由 L1 清理，压缩后按 path 从磁盘重读恢复）；Wiki 页面等用 resource 并声明 identity；Skill 主说明用 instruction；用户决定或 Agent 结论用 important。
  • 延迟加载工具：schema 加 _crew_should_defer=true，由 tool_search 按需披露。
  • 外部工具：通过 MCP client 注册，或 CUA setup 接入。
  • 遵守契约：文件类工具复用 file_utils 的安全读取与整读上限；网络类复用 security_guard 授权；不跨目录重复实现。
