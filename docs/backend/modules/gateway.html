Acrew/gateway

Gateway 网关：HTTP/WebSocket API 入口、认证与 owner 归一化边界、渠道（飞书/微信等）接入与归属、请求分发。

1. 职责

  • 对外入口：桌面端/浏览器的 HTTP API 与 WebSocket（app.py 装配，routers/ 分域路由，ws.py WS 入口），以及平台渠道（飞书/微信等，经 platform_registry + plugins/platforms）的接入与生命周期管理。
  • 认证与 owner 归一化边界：auth.py 把可信传输映射为 AccountContext（loopback → 本机 owner local；remote/email → 签名会话 → provider:user）；dispatcher.py 是 ContextVar set 点，normalize_owner_account_id 只在这类系统边界出现。
  • 请求分发：dispatcher.py 对同一 session 串行化执行（per-session FIFO + 忙时策略 queue/interrupt/steer + 全局并发上限），触发 session/agent 生命周期钩子。
  • 渠道归属：按 (platform, owner) 注册/投递渠道实例（channel_manager / delivery / channel_sessions / channel_bindings），对话事件实时广播给桌面 WS 观察者（broadcast）。
  • 不做：业务逻辑与 LLM 调用（在 crew/app.py / agent 层），gateway 只做协议转换、鉴权、串行化与投递。

2. 功能拆解

子功能说明状态

交互桥（interaction_bridge.py）外部 Runtime（MCP 子进程）与 Crew 主会话之间的短期绑定：token → ExternalInteractionBinding（含 owner_account_id、显示/控制 session、权限画像、过期时间），把 MCP 交互请求安全映射回发起任务的会话。已落地
上下文兼容 API（context.py）保留上传与结构化路径解析；Browser 标签页解析暂时重导出。静态 REFERENCE_INJECTORS 已删除。迁移中
Session Source Contributor（session_context.py）拥有渠道来源数据和 formatter，通过 Feature Runtime 输出规范化 source 与动态模型上下文。已落地
Wiki Knowledge Consumer（routers/wiki.py / routers/misc.py）REST 与附件捕获按请求解析 Knowledge Service 并持有 Generation Lease；能力停用统一返回 503 或跳过后台捕获。已落地
Feature Event Dispatch（ws.py）回合结束只调度中立 Event Contributor Registry；事件来源与 Generation 属于各 Feature，Gateway 提供标准帧 sink。已落地

4. 数据模型与接口

owner 归一化在 gateway 的边界规则（归一化原语 normalize_owner_account_id() / LOCAL_OWNER_ACCOUNT_ID 定义在 crew/core/runctx.py）：

认证（auth.py）        loopback → AccountContext(owner="local")；remote/email → owner="provider:user"
ContextVar set 点       dispatcher.run(): current_owner_account_id.set(normalize_owner_account_id(envelope.user_id))
渠道注册（app.py）      显式绑定 owner 的渠道 include_env=False（凭证只读 owner overlay）
                        未绑定渠道归本机 owner local，include_env=True（env 凭证启用，决策⑦）
入站消息（channel_sessions.py）
                        有绑定者：envelope.user_id 改写为绑定桌面账号（binder）；
                        无绑定渠道：归本机 owner local（决策⑥）；
                        平台原始 uid 只保留在 params.platform_uid，严禁充当 owner

边界之内 owner 恒非空：HTTP 路由经 account_from_request(request).owner_account_id 取 owner 显式传给 CrewApp/store；渠道路径经 dispatcher 的 ContextVar 继承。channel_manager / delivery 的 {"", "local", "dev:dev"} 全局特判已删除，渠道一律按 (platform, owner) 精确归属。

service, lease = plugins.acquire_service_lease(
    KNOWLEDGE_SERVICE_KEY,
    label="gateway:wiki",
)
async with lease:
    return await handle_with(service)

Wiki Router 树仍在应用构造期挂载，但能力按请求动态解析。draining 后新请求得到 503；已进入请求持有旧 Generation，结束后才允许 Provider 关闭。外部嵌入宿主没有产品 Feature 记录时，可继续通过兼容 Service 注入。

5. 当前存在的问题 / TODO

  • 签名清扫未完成：routers/channels.py（19 处）、channel_manager.py（11 处）、dispatcher.py（9 处）、connections.py（9 处）等仍有 owner_account_id: str = "" 默认值待收紧（交接文档第三节 B）。

6. 扩展点

  • 新增渠道平台：在 plugins/platforms 实现 adapter 并注册进 platform_registry；渠道实例自动获得广播、投递与 owner 归属能力，无需改 gateway 本体。
  • 新增 HTTP 路由：在 routers/ 新建 create_xxx_router 并在 app.py 挂载；owner 一律经 account_from_request 获取，不要自行解析。
  • 出站内容处理：归 response_filters.py 过滤链，不在各 adapter 里私写。
