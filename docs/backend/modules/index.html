1. 模块列表

#模块职责
1core待补充 · crew/core/Core 契约：Envelope、Message、接口，所有模块共同语言。
2state待补充 · crew/state/State 状态：配置、日志、会话、工作空间。
3providers待补充 · crew/providers/Provider 模型：隔离模型厂商 SDK，连接 OpenAI 兼容端点。
4tools待补充 · crew/tools/Tools 工具：工具注册、schema 暴露、工具执行和结果回灌。
5agent待补充 · crew/agent/Agent 内核：单智能体循环（历史、记忆、模型、工具、保存）；含 external / executor / loop / plan / subagent / compact 子模块。External Runtime 删除继续保护仍被 Agent 引用的记录；无 Agent 引用时会清理仅用于原生进程续接的 Runtime Session Binding，保留 Crew 会话与历史消息。删除 Agent 时同步清理其续接绑定，避免遗留记录。ACP、Codex app-server 和 Claude stream-json 的 managed 双向 stdin/stdout 由 Security Broker 与 Native Runtime interactive transport 托管；Crew ask_followup_question 通过短期 binding 的 crew-interaction MCP proxy 回调受控 Gateway loopback；普通 CLI 继续复用 managed captured execution。Native Runtime 按 Windows/Linux/macOS 平台制品启动，构建脚本统一生成带源码与二进制摘要的 manifest；制品缺失时保持 fail-closed，不回退宿主直启。macOS 仅在 managed profile 明确覆盖用户 Home 时复用真实 HOME，启动前执行通用 Seatbelt preflight；Gateway 的 Darwin live probe 区分运行时不可用与平台不支持。ACP reader 透传 native/子进程原始错误，认证失败或 Seatbelt 不可用不再误报为 protocol stream EOF。Hermes 探测使用 30 秒冷启动阈值，普通 ACP 保持 15 秒，执行任务超时不变。
6memory待补充 · crew/memory/Memory 记忆：对话前召回和对话后写入。
7plugins待补充 · crew/plugins/Plugins 插件：LLM/工具调用生命周期钩子。
8app.py待补充 · crew/app.pyApp 装配：依赖注入、Agent 缓存、agent/team 路由。
9gateway / auth ✅crew/gateway/ + crew/state/Gateway 网关与认证：Web/API/WS 入口、按 Owner 的认证会话、退出清理、Cron 和渠道资源隔离。Runtime 路由提供列表、扫描、管理员注册与管理员删除；扫描为固定内置探测命令建立显式 host ProcessLaunch。删除仍被 Agent 引用的 Runtime 返回 409；只有历史原生会话续接绑定时由存储层安全清理后完成删除。认证模型详见 Owner 会话与资源隔离。
10cli ✅CLI 入口：进程内命令树、非交互 run、管理子命令、JSON 输出与安全命令。
11team待补充 · crew/team/Team 多智能体：Leader 委派 Teammate，复用 Agent 内核。
12tasks待补充 · crew/tasks/Tasks 任务：委派任务的状态流转和任务看板。
13cron待补充 · crew/cron/Cron 计划任务：定时自动化入口。

16skills ✅Skills 技能运行时：三层目录发现 / 加载 / 激活 / 装卸 / 审计（框架代码在 crew/agent/skills.py，crew/skills/ 为业务技能包）。
17dynamickanban待补充 · crew/dynamickanban/动态看板：多智能体 DAG 工作流引擎。
18mcp_servers待补充 · crew/mcp_servers/内置 MCP server：随仓库发布的 stdio MCP server 承载位。
19browser浏览器自动化：Electron 登录态、录制体验、playwright-core 引擎。详见 引擎设计 / 录制契约 / 横向对比。

2. 搭建顺序

  1. Core：先固定 Envelope、Message、接口，确保所有模块说同一种语言。
  2. State + Provider + Tools：补齐 Agent 需要的历史、模型和行动能力。
  3. Agent：把历史、记忆、插件、模型、工具串成单智能体循环。
  4. App + Gateway/CLI：用 app.py 做装配，入口层只负责协议转换。
  5. Team + Tasks + Cron：在单 Agent 基础上增加多智能体协同、任务看板和自动化。

3. 与 Crew 的差异

本索引对应 Ace（Crew 开源版）实际代码。Ace 的 sites 模块对外提供“灵感”统一 App 库；内部继续保留网站 Release 与 Canvas/Widget 运行时。Ace 移除了 api 模块（开源版脱敏移除）。
