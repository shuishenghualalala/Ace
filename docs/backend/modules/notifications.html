通知中心（Notification Center）

crew/notifications/ + crew/core/interfaces.py + crew/gateway/routers/notifications.py · 2026-08-28 建立

1. 定位

统一的消息提醒中心：桌面端左上角 Crew logo 旁铃铛 + 未读角标 + 通知面板。采用「中心存储 + 来源推送（push）」模式：core 只定义契约，各业务模块在自己的事件产生点调一次 publish() 即完事，中心统一持久化、统一未读数、统一 WS 推送。来源模块互不感知，拔掉任何一个来源只是少几次 publish 调用，中心与 UI 照常工作。

4. 可插拔约定

  • 来源方零依赖：cron / security 等永远不 import crew/notifications，只接收可选回调（如 CronService.set_on_run_finished()、SecurityApprovalService.set_notification_hooks()），与 TaskRuntime.set_callbacks 同一套路。
  • 来源缺席无影响：模块未装配 = 没人调 publish；UI 面板来源列表从数据动态渲染，不写死。
  • 新增来源不改核心：在 app.py 装配处拿 center 句柄调 publish 即可，core / 中心 / UI 零改动。

5. API 契约

方法路径说明
GET/api/notifications?limit=50&offset=0&unread_only=false{"notifications":[...], "unread_count":n}，created_at 倒序，limit 上限 200
GET/api/notifications/unread-count{"unread_count":n}
POST/api/notifications/{id}/read单条已读
POST/api/notifications/read-all全部已读
DELETE/api/notifications清空当前 owner

notification JSON：{id, source, kind, title, body, payload: object|null, created_at, read_at: float|null}。WS 实时帧：{"kind":"notification","notification":{...}}，经 ConnectionManager.notify_owner 账号级广播；WS 只负责唤醒角标，面板打开时总是 REST 全量拉取（与 security-approval 的推送唤醒 + 拉取兜底模式一致）。

7. 前端

desktop 端 features/notification-center.ts（唯一新模块文件）：铃铛按钮挂在 brand 块（application-shell.ts），未读角标 0 隐藏 / 99+ 封顶；面板点外部或 Esc 关闭；面板只展示未读（拉取固定 unreadOnly，单条已读后立即从列表移除，后端历史不动），条目点击按 payload 跳转（session_id → 打开会话，approval → 触发审批弹窗），并支持单条已读 / 全部已读。WS 帧走应用级常驻 BackendChatSocket 的 applyChunk 分发，带 push id 去重。

9. 变更记录

2026-09-01：新增两个通知来源。① followup（kind=followup_pending）：crew/core/followup.py 在 send_followup_question_to 发出追问后触发模块级注入钩子 set_followup_notification_hooks(on_pending/on_resolved)（fire-and-forget，钩子异常只记日志），仅 record_history=True 的普通追问发通知——record_history=False 是权限确认 side-channel UI，已由 approval 来源覆盖；FollowupWaiter 的 resolve / cancel / wait-finally（超时）三处触发 on_resolved，由 app 侧 mark_read_by_payload("followup", question_id) 自动已读（幂等）。owner 解析：followup 层只有 session_id，app 回调经新增的 SessionStore.resolve_owner_account_id（按 updated_at 取最近一行）反查。② plan（kind=plan_review_pending）：crew/gateway/ws.py 在 plan_review 帧推送后调 CrewApp.publish_plan_review_notification，仅非 empty（可审批）的 review 发通知，「计划为空」提示卡不进待办；plan_approve / plan_reject / plan_reject_and_exit / plan_exit 四个决策分支调 mark_plan_review_notification_read 自动已读。桌面端 SOURCE_LABELS 新增「追问 / 计划」标签。③ 面板改为只展示未读：拉取固定 unreadOnly、已读即移出列表、空态文案改「没有未读通知」；移除「清空」按钮（后端 clear 接口保留，仅不再暴露 UI）；修复面板头部落入 .mw-app-titlebar 拖拽区导致「全部已读」点不动的问题（.mw-notification-panel 加 -webkit-app-region: no-drag）。
