Acrew/wiki

Wiki 知识库：KB/页面管理、编译检索、Agent 工具与 Prompt Context。

1. 职责

  • 管理按 Owner 隔离的知识库、原始来源、页面、编译、检索与摘要。
  • 提供 Wiki Agent 工具、Preset 内容，以及模型可见的活跃知识库上下文。
  • 拥有 Wiki Attachment 的构造和 KB 解析，不把产品语义放入 Agent Runtime。

2. 功能拆解

子功能说明状态
知识库存储持久化 KB、raw source、page 与索引元数据，并按 owner/kb 隔离。已落地
编译与检索把来源编译为知识页，提供 orient/search/read 等 Agent 工具。已落地
会话 KBWikiSessionManager 维护会话当前活跃 KB。已落地
Prompt Contextwiki.agent.context 贡献活跃 KB 和 KB 列表的 persistent hidden attachment。已落地
完整 Wiki BundleTool、API、Preset、Store、Context 和 Event 收敛到同一 FeatureDefinition。待迁移

3. 关键文件

文件作用
crew/wiki/store.py文件系统知识库数据与 Owner 隔离。
crew/wiki/manager.py会话活跃 KB 状态。
crew/wiki/compiler.py来源到知识页的编译流程。
crew/wiki/querier.py知识库查询与读取。
crew/wiki/tools.pyWiki Agent 工具注册和 Handler。
crew/wiki/attachments.py隐藏附件工厂与 Wiki Prompt Contributor Handler。

4. 数据模型与接口

build_wiki_agent_context_contributor(
    manager,
    session_store,
) -> ContextContributorHandler

ContextContributor(
    contributor_id="wiki.agent.context",
    phase=ContextPhase.PROMPT,
    priority=100,
    model_visible=True,
    persistent=True,
)

Contributor 只接受带 wiki context tag 的 Agent。KB 选择顺序为本轮 wiki_kb_id、会话保存值、Manager 当前值、default；输出的 Message 使用 attachment_type=wiki_agent_context 和 reminderType=agent_context。

5. 当前存在的问题 / TODO

  • Wiki Tool、Router、Store、Preset 和 Context 尚未归属同一个可启停 Wiki Bundle。
  • 完整 Bundle 迁移前，Host 组合根仍负责构造 Wiki 服务和注册 Contributor bridge。

6. 扩展点

  • 新增模型上下文应扩展 Wiki-owned Contributor，不向 crew.agent.runtime 添加 Wiki 判断。
  • 新增 Wiki 工具保持 Owner/KB 参数显式，并在未来由 Wiki Bundle 的 FeatureScope 统一拥有。
