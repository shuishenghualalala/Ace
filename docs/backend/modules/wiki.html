Acrew/wiki

Wiki 知识库：Knowledge Service、本地 Provider、KB/页面管理、编译检索、Agent 工具与 Prompt Context。

1. 职责

  • 管理按 Owner 隔离的知识库、原始来源、页面、编译、检索与摘要。
  • 提供 Wiki Agent 工具、Preset 内容，以及模型可见的活跃知识库上下文。
  • 拥有 Wiki Attachment 的构造和 KB 解析，不把产品语义放入 Agent Runtime。
  • 通过 product.wiki Feature Generation 管理本地 Provider、Tools、Context 与后台 Task。

ContextContributor(
    contributor_id="wiki.agent.context",
    phase=ContextPhase.PROMPT,
    priority=100,
    model_visible=True,
    persistent=True,
)

Service 是 Provider 可替换边界；Gateway 与 CLI 已只消费该边界，Components 视图仅服务尚未迁移的 Work 调用方。Contributor 只接受带 wiki context tag 的 Agent。KB 选择顺序为本轮 wiki_kb_id、会话保存值、Manager 当前值、default。

5. 当前存在的问题 / TODO

  • Route 与 UI Contribution 尚未归属 Wiki Bundle。
  • Work 仍直接持有 Wiki Store；阶段 3C 改为可选 knowledge Service Consumer。

6. 扩展点

  • 新增模型上下文应扩展 Wiki-owned Contributor，不向 crew.agent.runtime 添加 Wiki 判断。
  • 新增 Wiki 工具保持 Owner/KB 参数显式，并由 Wiki Bundle 的 FeatureScope 统一拥有和绑定 Lease。
  • 新增 Provider 实现 KnowledgeService，不得让消费者依赖本地文件布局。

7. KnowledgeService 契约一致性测试（2026-09-11）

演进计划阶段 6 首个切片：tests/wiki/test_service_contract.py 把 KnowledgeService 协议面的行为断言写成与实现无关的参数化套件，为未来 Local/Remote Provider 替换建立统一契约门禁。

  • 工厂参数化：套件通过 PROVIDER_FACTORIES 注册表按工厂 id 参数化；当前只接入 local（LocalWikiProvider）。工厂走与生产 Bundle（feature.make_provider）相同的组件构造路径——真实 FileSystemWikiStore、WikiQuerier、WikiCompiler、WikiSummarizer、WikiSessionManager，不 mock 存储/检索组件；仅 LLM 边界使用脚本化 FakeProvider（与 compiler 单测同一策略）。未来 Remote Provider 只需注册一个新工厂，全部用例自动复跑。
  • 断言语义而非"不抛错"：覆盖协议全部方法——query/search/search_pages、ingest（progress 阶段序与回调容错、预取消抛 CancelledError 且零写入）、read_document、index_status、initialize 幂等、KB 增删列（default/tutorial 保护与缺失返回 False）、页面增删改与分页/brief 列表、related_pages 方向与去重、vault 文档、upload→source 面（source_pages/source_titles/source_files/source_file/delete_source）、capture_text 去重与校验、capture_attachment、compile_all/lint/graph、session_kb_id/cancel_confirmation 默认值，以及 owner 与 kb 两个维度的隔离性。
  • 序列化边界结论：协议返回的 DTO 中，KnowledgeQuery、KnowledgeIndexStatus、KnowledgeVaultDocument、KnowledgeBase、WikiPage（dataclass 载荷）、WikiPageRelation、IngestResult、RawSource、CompileResult、WikiGraph、lint issue dict 均可无损 JSON round-trip（严格 json.dumps 无需 default），证明其传输无关。锁定现状形态的三处：KnowledgeSourceFile.content 为 bytes，严格序列化抛 TypeError、default=str 后退化为不可还原的 repr 字符串（远程化前需 base64 等显式编码）；KnowledgeUploadResult.pages/issues 的 tuple 经 JSON 后到达对端为 list；WikiPage.to_dict 完整模式不含 summary（仅 brief 模式携带，且 brief 读取端用正文头部摘录覆盖显式 summary）。
