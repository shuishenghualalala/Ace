Acrew/wiki

Wiki 知识库：Knowledge Service、本地 Provider、KB/页面管理、编译检索、Agent 工具与 Prompt Context。

1. 职责

  • 管理按 Owner 隔离的知识库、原始来源、页面、编译、检索与摘要。
  • 提供 Wiki Agent 工具、Preset 内容，以及模型可见的活跃知识库上下文。
  • 拥有 Wiki Attachment 的构造和 KB 解析，不把产品语义放入 Agent Runtime。
  • 通过 product.wiki Feature Generation 管理本地 Provider、Tools、Context 与后台 Task。

4. 数据模型与接口

KNOWLEDGE_SERVICE_KEY = ServiceKey[KnowledgeService]("knowledge")

service.query(question, owner_account_id, top_k, kb_id)
service.search(query, owner_account_id, top_k, kb_id)
service.search_pages(query, owner_account_id, top_k, kb_id)
await service.ingest(source_id, owner_account_id, ...)
service.read_document(page_id, owner_account_id, kb_id)
service.index_status(owner_account_id, kb_id)

build_wiki_agent_context_contributor(manager, session_store)

ContextContributor(
    contributor_id="wiki.agent.context",
    phase=ContextPhase.PROMPT,
    priority=100,
    model_visible=True,
    persistent=True,
)

Service 是 Provider 可替换边界；Gateway 已只消费该边界，Components 视图仅服务尚未迁移的 CLI 与 Work 调用方。Contributor 只接受带 wiki context tag 的 Agent。KB 选择顺序为本轮 wiki_kb_id、会话保存值、Manager 当前值、default。

5. 当前存在的问题 / TODO

  • CLI 仍通过迁移期 Components 视图访问细粒度实现，下一切片迁到 Knowledge Service。
  • Agent Preset、Event、Route 与 UI Contribution 尚未全部归属 Wiki Bundle。
  • Work 仍直接持有 Wiki Store；阶段 3C 改为可选 knowledge Service Consumer。

6. 扩展点

  • 新增模型上下文应扩展 Wiki-owned Contributor，不向 crew.agent.runtime 添加 Wiki 判断。
  • 新增 Wiki 工具保持 Owner/KB 参数显式，并由 Wiki Bundle 的 FeatureScope 统一拥有和绑定 Lease。
  • 新增 Provider 实现 KnowledgeService，不得让消费者依赖本地文件布局。
