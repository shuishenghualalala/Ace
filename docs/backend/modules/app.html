Acrew/app

Host 组合根：依赖注入、公共请求前处理和 Execution Driver 分派。

1. 职责

  • 构造默认 Provider、Store、Tool、Feature 与宿主级服务，并管理应用关闭顺序。
  • 在所有执行模式共享的边界完成 Owner、Workspace 与安全上下文。
  • 通过 Execution Driver Registry 解析开放 mode；不再把未知 mode 静默当成默认 Agent。
  • 默认 Agent、Team 与 Dynamic Kanban 均作为生命周期拥有的 Driver；核心路由不认识具体业务 mode。
  • 按阶段执行 Context Contributor，并把参数更新、通用 prompt fragment 与受控 persistent message 交给后续 Driver。

4. 数据模型与接口

Host 只负责一次公共前处理和一次 Driver 解析。具体执行能力通过 Feature 安装上下文注册：

def install(context):
    context.register_execution_driver(
        ExecutionDriver("feature.echo", execute_echo)
    )

await feature_runtime.activate(FeatureDefinition("echo", install))
async for chunk in app.handle(envelope):
    ...

Feature 停用后 Registry 立即不再解析该 mode；活跃流持有 Lease，drain 会等待它结束。未注册 mode 返回最终 error chunk，body.code 为 capability_unavailable。

5. 当前存在的问题 / TODO

  • 把默认 Agent Scope 从同步组合根桥接迁为完整 Core FeatureDefinition，并进入统一启动审计。
  • 把 Team 与 Dynamic Kanban 的 Manager、Store 和后台任务所有权从桥接 Scope 逐步迁入完整 Product Feature。
  • 将 Plan reminder 迁入 Context Contributor（后台结果通知已落地，见 ADR-0013）。

6. 扩展点

  • 新增执行模式应注册 Execution Driver，不得向 CrewApp.handle() 添加 mode 分支。
  • Driver 应通过 FeatureScope 获得所有权；停用使用统一 drain/cancel 策略。
