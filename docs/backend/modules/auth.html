Owner 会话与资源隔离

记录日期：2026-08-17 · 认证会话、退出清理、Cron、渠道和 Desktop 错误透传

1. Owner 会话模型

Gateway 的登录身份由请求 Cookie 解析为 AccountContext，其 owner_account_id 是所有持久化数据和运行态资源的隔离键。邮箱账号分别形成 email:user-a@example.com 与 email:user-b@example.com，互不覆盖。

数据隔离键语义
owner_session_leaseowner_account_id登记每个已验证账号的会话租约；同一账号重复请求只刷新自己的 verified_at。
owner_logout_intentowner_account_id记录某个账号在退出清理超时后需要在下次 Gateway 启动完成的退出意图。
HTTP / WebSocket当前请求的 Owner普通请求只 claim/refresh 当前 Owner，不检查或抢占其它账号的租约。
渠道 / Delivery(platform, owner_account_id)同一平台的不同账号使用不同配置、实例、锁、入站处理器和出站 sender。

2. Gateway 鉴权流程

  1. 登录接口签发 crew_auth_session Cookie。每个受保护 HTTP 请求或 WebSocket 连接从 Cookie 确定 AccountContext。
  2. Gateway 对当前 Owner 调用 active_owner.claim(owner) 并激活该 Owner 的 Dispatcher、Task Runtime、Cron 和渠道；不会因为其它 Owner 已登录而返回跨账号冲突。
  3. /api/auth/session、业务 API 与 WebSocket 都只访问当前 Owner 的数据。退出请求进入该 Owner 的 LogoutCoordinator，其它 Owner 的连接和任务继续工作。
  4. WebSocket 的关闭、订阅、回放和连接注册都带 Owner；关闭 A 的连接不会关闭 B。
Cookie → AccountContext(owner)
       → owner_session_lease(owner)
       → owner-scoped Dispatcher / Task / Cron / Channel / Socket

3. Cron、渠道和退出清理

3.1 Cron

CronService 使用 mounted_owners 和按 Owner 的 Job 集合。挂载 A 不会卸载 B；到期执行、取消、重试和调度同步都校验 Job 的 Owner。A 退出只撤下 A 的任务。

3.2 渠道

ChannelManager 以复合键管理实例、状态、生命周期锁和 Owner 注入的入站处理器。ChannelBindingsStore 以 (platform, owner_account_id) 保存绑定；旧的单平台绑定会在打开数据库时迁移。飞书 webhook 会按候选实例验证 token，入站 envelope 携带实例 Owner；DeliveryRouter 按 Owner 选择 sender，避免 Cron 或渠道回复串号。

明确的渠道级断开、重连和删除只影响当前 Owner。第三方平台若拒绝同平台多连接，错误收敛在该渠道实例，不会回滚或阻塞账号认证。

3.3 LogoutCoordinator

退出顺序保持为：Owner draining → 撤下 Cron → 停止 Dispatcher / Team / Task → 停止该 Owner 渠道 → 关闭该 Owner WebSocket → 释放该 Owner 租约。清理失败会保留该 Owner 租约和 draining fence，便于重试；超时会持久化该 Owner 的 restart fence，不把 Gateway 其它账号变成不可用。

4. 数据迁移与异常重启

  • 旧的 active_owner_lease 单行记录和 active_owner_logout_intent 单行记录会复制到新的 Owner 表；旧数据不会再作为全局锁，因此旧账号残留不会阻塞新邮箱登录。
  • 旧的 channel_bindings 单平台主键会迁移到复合主键，保留已有绑定并允许另一个 Owner 建立同平台绑定。
  • Gateway 启动先完成所有遗留 restart logout，再启动业务；没有可恢复凭据的旧 local 租约在 email/remote 模式启动边界释放。
  • 正常退出只删除当前 Owner 的租约；异常退出留下的租约最多影响该 Owner 的恢复流程，新的 Owner 可以直接建立自己的会话。

5. Desktop 错误契约

DesktopAuthSession.refreshConfig() 验证 Cookie 失败时仍清理本地 Cookie 和持久化会话，但保存 Gateway 返回的 JSON error、code 与 HTTP 状态。loginWithEmail() 将这些字段返回给现有登录 UI，因此账号冲突、Gateway 清理中或其它认证错误不会被统一改写为“邮箱会话验证失败，请重试”。
