Acrew/agent

Agent 内核：单智能体循环、工具调度、上下文压缩、规划与会话保存。

1. 职责

  • 组织主 Agent 的模型调用与多轮工具循环，维护 canonical 历史和仅发送给模型的 request view。
  • 在上下文预算内执行分层压缩，保护已加载指令与不可重放的重要结论，并按 path 从磁盘重读最近文件。
  • 提供子 Agent、外部 Agent、Plan/Todo 和 Skill 索引等运行时能力；具体工具实现仍归所属 Feature。

4. 数据模型与接口

ContextCompactor.compact_preview_view(messages)  # 纯规则 L1 视图
await ContextCompactor.compact_view(messages)   # 超预算时可进入 L3

ToolResultRetention:
  TEMPORARY   # 临时过程，可由 L1 压缩
  RESOURCE    # 按 identity 保留最近资源版本
  INSTRUCTION # 持续生效的已加载指令
  IMPORTANT   # 用户决定、Agent 结论等不可重放结果

未声明生命周期的工具默认使用 IMPORTANT。L1 不再按“最近六个工具”统一清理；keep_recent_tools 只计算 TEMPORARY 工具。file_read 声明为 TEMPORARY：旧分片由 L1 清成含 path/offset 的一行摘要，完整压缩后按 path 去重、从磁盘重读最新内容恢复（不回放旧快照）。

切分点（_safe_split）接受 user 或 assistant 边界——recent 以 assistant 开头时其 tool_calls 结果同在 recent，配对完整；因此单个长回合内的早期迭代也能被 L3 摘要，不再整回合受保护。摘要消息尾部附 canonical 历史回溯指引（会话数据库路径 + session_id）。恢复预算（指令 5 条 / 重要结论 8 条 / 附件总量等）见 agent.compaction.post_compact_* 配置。

中断 / 超时 / deadline 语义（2026-09-17）

中断是协作式的：TurnControl.interrupt(message=...) 置标志 + set 中断事件，executor 在轮初 / 模型产出后 / 工具执行后检查点消费；等在这些检查点之外的长操作（工具执行、权限等待、compact 摘要）通过 wait_interrupted() 与自身任务竞争，interrupt 先到即取消并走收尾。停止按钮因此对"卡在工具 await 里"的回合同样有效。

控制面：  TurnControl.interrupt(message) / .steer(text) / .interrupted / .drain_steer()
           TurnControl.wait_interrupted()      # 执行侧与在途操作竞争用
           TurnControl.drain_interrupt_message()  # 回合收尾消费一次
看门狗：  runtime.tool_execution_timeout_seconds  # 默认 600s，0=关闭
deadline: runtime.turn_deadline_seconds         # 默认 0=不限
等待上限： runtime.interaction_timeout_seconds   # 追问/权限默认等待，默认 3600s，0=默认不限

看门狗只包裹真实执行段（不含权限等待）：超时或被中断都不走异常通道，而是合成 timed out after X.Xs / aborted by user after X.Xs 的 is_error tool output 回灌模型——tool_call 与 tool output 历史配对完整，回合继续推进，单个挂死工具不再冻结整轮回合。interrupt 触发时先给 0.1s 优雅窗口，窗口内完成的工具原样收取结果。deadline 到点复用同一套优雅收尾：写 interrupt（deadline exceeded 消息）、在途工具走 aborted 语义、final 带 reason="deadline"，历史/输出含 deadline 标记。权限确认等待被 interrupt 取消时按"用户未回答"结算（取消挂起追问 + 清理 waiter），上层按拒绝处理（安全默认）。

回合收尾时 interrupt_message 被消费一次：追加 [回合中断] {message} user 标记消息到 canonical 历史（is_meta=False，落库且下回合进入 LLM 视图，模型据此知晓上轮为何停止），同时经既有 status 通道透出给前端；与 codex 的 interrupted marker 历史语义对齐。

子 Agent 收尾与后台任务（2026-09-17）

子 agent 收尾顺序固定为先下中断标志再关流：interrupt() 必须在 gen.aclose() 之前设置——aclose 会把 GeneratorExit 推进子 agent 收尾逻辑，interrupt 在关流后才设置则收尾阶段永远观察不到（超时场景）。批量 delegate_task 执行具异常隔离：asyncio.gather(return_exceptions=True) 把单个子任务 runner 逃逸的异常折叠成该子任务的结构化失败结果（status=error），其余子任务结果照常返回；CancelledError 等 BaseException 不折叠、向上传播。后台子任务的完成事件表 bg_events entry 带完成时间戳，已完成且超过 TTL（3600s）的 entry 在新后台任务起飞时顺带清扫——模型从不 collect 时不再永久驻留。

后台子任务路径上的同步 TaskManager 写库（create/mark_running/update_status/touch_activity 的 sqlite busy 重试会睡眠）一律经 asyncio.to_thread 挪到工作线程；事件循环上只允许 execute_async 异步写路径（见 state 模块文档）。

LLM 重试与 error 帧结构化（2026-09-17，ADR-0045 批次 3）

重试判定从 isinstance(exc, ProviderError) and exc.retryable 收敛为 isinstance(exc, CrewError) and exc.is_retryable()（ProviderError 显式 retryable 优先语义不变）；等待时长优先取服务端建议的 retry_delay（Retry-After / body 字段，批次 2 解析），封顶 _RETRY_DELAY_CAP_SECONDS = 60s 防异常大值拖死重试循环，无建议值时维持本地指数退避 + jitter。非 CrewError 异常不重试、走既有兜底。unsupported_capability 降级分支改按 exc.kind 判定（不再比对字符串 category）。

LLM 路径 error 帧（重试耗尽 / 流中断不可恢复）统一经 _llm_error_chunk 发出：CrewError 时 code 传 kind 值（如 "timeout"），body 附加 retryable 与 retry_delay（有则带，纯增量）；非类型化异常保持纯 message 帧。出站 enrich_error_chunk 的 category 优先取类型化分类（无 exc 时可从 body 的 kind code 反推），文本兜底仅保留给非类型化异常。

工具总预算与 durable boundary（2026-09-18）

ToolRunner 现在以 _execute_total_guarded 包住从 middleware、权限、执行到结果 hook 的完整管线；执行段保留更短的局部看门狗。取消只等待有限宽限期，无法及时退出的第三方 task 被登记并由完成回调清理，不再用无上限等待拖住当前回合。

工具结果统一带 code、retryable、retry_delay、side_effect_state 和 details，同时透传到 ResponseChunk.tool_event 的 result_metadata。持久会话在用户消息、工具执行 intent、工具结果 commit 处形成恢复边界；进程退出后有 intent 无结果的调用只标记为 interrupted/unknown，不自动重放副作用。

Gateway 创建 agent turn 时把 TaskRuntime.execution_timeout 注入 ExecutionContext.deadline_seconds，TaskRuntime 取消先触发 TurnControl.interrupt，再进入 worker 的硬取消宽限。直接调用 executor 时仍可使用 turn_deadline_seconds 作为兼容回退。

本次更新：Agent Loop 与 Compact 观测（2026-09-23）

Agent Loop 为每次迭代写入稳定的 module=agent/component=loop 事件，包含 iteration、budget 和 grace 信息；避免在 async generator 的 yield 期间泄漏 provider ContextVar。Compact 的 concrete public boundary 产生 module=agent/component=compact span，operation 分别标识 view/maybe/force/now。

工具执行仍区分逻辑调用、重试和实际 tool span，MCP 常驻 worker 取出队列项时 attach/reset 不可变 observation context。
