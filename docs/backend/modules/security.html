1. 职责

  • 定义不依赖具体产品 Feature 的安全决策、授权、审计和执行边界。
  • 统一命令风险识别、Workspace 读写边界与外部 Runtime 权限分类。
  • 管理安全上下文、临时授权、持久规则、Native Runtime 调用和进程清理。
  • 不负责 Team 编排、Agent 业务流程或具体 Tool 的实现；这些模块只能消费安全能力。

2. 功能拆解

安全模块是 Host 与 Feature 共同依赖的稳定底座。策略数据可以由上层提供，但裁决逻辑归安全模块所有。

2.1 会话安全模式与单命令权限

「请求批准」(request_approval) 和「替我审批」(auto_review) 使用相同的原生工作区写入沙箱。审批策略决定何时询问用户，原生运行组件负责约束进程。选择「完全访问权限」(full_access) 后，Ace 的终端命令使用当前操作系统用户权限执行。

2.1.1 两个受管模式共享什么

settings_for_mode 会把请求批准和替我审批都编译成 PermissionProfileKind.MANAGED，并设置 full_disk_read=true。普通文件在系统权限和保护规则允许时可读，写入仅限工作区、临时目录和获批路径。

  • macOS/Linux 的普通宿主文件默认只读。Windows 使用专用账户的现有 NTFS 读取权限，额外文件读取可按路径授权。
  • 当前工作空间可写。Windows 为每次受管命令提供独立临时目录，通过 TEMP、TMP 和 TMPDIR 传递。macOS 与 Linux 使用现有临时目录策略。
  • .git、.agents、.crew 等项目元数据重新覆盖成只读。
  • Ace 数据库、认证、配置、审计、日志和 owner 凭据路径使用更具体的不可升级拒绝。
  • 网络权限独立配置。默认离线，可以审批精确目标或在应用配置中启用工作区写入模式的直连网络。
  • 内置终端的 HOME/USERPROFILE 指向宿主用户目录，因此 ~/Desktop 与文件工具看到的是同一位置；这只改变路径语义，不自动赋予写权限。外部智能体若投影凭据文件，仍使用一次性私有 HOME。

2.1.2 请求批准

请求批准采用受管沙箱。基础边界允许的常规操作直接执行。高风险动作、超出当前权限范围或内置网页工具请求公网目标时，Gateway 先匹配已有授权，再为仍需确认的动作发起审批。

工作空间内的结构化写入、补丁、删除不询问由基础可写根与项目元数据只读覆盖共同约束。

2.1.3 替我审批的判定规则

Gateway 的 SecurityService 按固定规则做决定。这一步无需调用模型。安全服务使用宿主确认的账号、工作区和会话，以及真实命令、执行目录、文件路径、网络目标和所请求的附加权限。

  1. 检查禁止项。命中永久禁止的破坏性命令、显式拒绝规则或受管模式下不可授权的私有路径时，直接拦截。
  2. 匹配当前权限。两种受管模式都允许在基础沙箱内运行普通命令及进行常规文件操作。已有长期规则、对话授权或单次授权可以覆盖相匹配的动作。
  3. 自动批准合格的公网目标。内置网页工具按精确主机、端口和协议授权，并在重定向时重新检查。网页工具拒绝本机、私网及其他非公开目标。
  4. 等待用户确认扩权。高风险命令和未获授权的额外权限进入对话审批。拒绝或审批过期时，动作停止。

Agent 的工具调度也会读取会话模式。请求批准按顺序派发工具，替我审批可以根据并发配置提前派发或并行执行符合条件的工具，各动作仍经过独立的授权检查。

从其他模式切换过来时，Gateway 要求原生文件沙箱通过实际能力探针，失败就保留原模式。新会话确认已经生效的默认模式时可直接发送文本，受管命令启动时仍要经过原生运行组件。

2.1.4 完全访问权限

完全访问对应 PermissionProfileKind.DISABLED。compile_process_launch 以当前系统用户权限运行命令，原生文件与网络沙箱关闭。

  • 普通动作不逐项询问，工作空间外文件和宿主网络不再由原生沙箱拦截。
  • 系统 ACL、文件所有权和企业策略继续生效。Ace 使用当前用户权限，管理员权限仍由操作系统单独管理。
  • 永久禁止的破坏性命令、匹配的显式拒绝规则、进程树回收、输出脱敏和审计仍生效。结构化文件工具仍禁止写入文件系统根目录，专用网络工具保留自身的目标校验。
  • 受管模式中的 Ace 私有路径 deny 不再作为文件沙箱规则生效，因此这是需要用户明确确认的高信任模式。

2.1.6 单条命令的三种执行边界

会话模式之外，终端动作还携带一个只作用于本命令的 sandbox_permissions。其中有三种取值。

字段含义审批与执行
use_default不扩大当前会话的沙箱能力。普通命令直接按基础 profile 执行；高风险分类仍可单独触发动作审批。
with_additional_permissions留在沙箱内，增加明确宿主文件根、网络目标或本地监听能力。宿主绝对路径可以直接加入沙箱视图；审批面板逐条展示范围，批准后 overlay 进入 Native Runtime 请求，不需要脱离沙箱。
require_escalated请求让当前完整命令使用宿主用户权限。必须提供 justification 并明确批准；批准后，该命令以当前系统用户权限执行。单次或对话内授权绑定完整命令与 cwd，持久前缀规则还需单独校验。

2.1.6.1 终端命令如何判定风险

terminal_guard.py 先匹配永久禁令和高风险命令，再用 classify_command 检查命令结构。结构检查覆盖空白与控制字符、引号和转义、替换与变量展开、重定向、命令分隔符、部分程序的危险参数以及畸形 token。永久禁令直接拒绝。高风险或需人工确认的动作在受管模式下进入审批。

受管终端还会由原生组件解析实际 shell 命令。Gateway 用解析结果检查破坏性操作的路径，并把解析结果及摘要绑定到规范化动作，审批后按同一动作执行。原生文件、网络和进程边界持续约束实际运行的子进程。

2.1.7 新对话默认权限与模式切换

在「设置 → 安全 → 权限」修改「新对话默认权限」。启用沙箱且未保存偏好时，默认是「替我审批」。开启「启用『完全访问』选项」后，可经系统确认将完全访问设为默认，也可单独为对话选择。关闭该选项会隐藏完全访问选项，已保存的完全访问默认值会重置为「替我审批」。已确认的现有对话继续沿用各自模式。

发送第一条消息前即可从输入框旁选择权限。当前草稿的显式选择优先于桌面端默认值，发送时等 Gateway 确认后才提交消息。草稿选择仅用于该草稿，后续新对话按保存的默认值开始。

Desktop 选择模式后不会先假定成功。Gateway 校验上下文与本机能力，更新 SecurityService 中的会话模式并返回 ACK；只有 ACK 成功，界面才展示新模式。模式变化会撤销旧模式下尚未处理的审批，并停止继续使用旧 ProcessLaunch 快照的 turn。下一轮执行重新从安全服务编译策略。

用户已授予的对话权限在切换模式时保留。这些 grant 绑定 OS user、owner、workspace 和 session，在真正结束会话、登出或 Gateway 重启时清理。新的操作按切换后的模式检查，同时可匹配仍有效的对话授权。

2.2 审批选择、授权范围与执行流程

2.2.1 先把动作变成稳定事实

NormalizedAction 是授权系统的共同语言，分为 exec、file 和 network。它先解析绝对路径、规范化主机名与协议，再计算 SHA-256 摘要。命令需要越过基础沙箱时，还会携带独立的 AdditionalPermissionProfile；两者共同决定授权是否匹配。

动作摘要绑定的关键字段防止的问题
命令最终 argv、用户可见 shell 文本、cwd审批后替换参数、目录或整段脚本。
文件规范化路径、read/write/patch/delete、offset/limit、写入内容摘要把已批准的读取变成写入，或在审批后替换写入内容。
网络精确 host、port、protocol用 wildcard、URL path 或协议变化扩大联网权限。

2.2.2 判定顺序

禁止项和匹配的显式拒绝优先。文件工具先判断基础文件权限，再检查规则和临时授权。受管终端先匹配动作授权，再判断命令能否在基础边界内执行。应用内 HTTP 授权先检查规则和临时授权，再按所选模式处理。替我审批的判定规则

2.2.4 一次批准如何真正进入执行边界

用户批准后，终端重新按同一动作执行授权判断，再把获批的权限范围编译进实际进程启动参数。

1. Agent 提交动作
   └─ NormalizedAction + AdditionalPermissionProfile

2. SecurityService 判断需要审批
   └─ 创建 request：action digest + 权限范围 + nonce + 上下文

3. Desktop 展示并提交 decision
   └─ Gateway 校验 owner/workspace/session/task/nonce

4. 后端生成 grant、exact rule 或已校验的 prefix rule
   └─ once / session / always 的作用域各自落地

5. 工具用同一个规范化动作重新授权
   └─ 命中 grant/rule，取回获批 AdditionalPermissionProfile

6. compile_process_launch 重新读取当前会话模式
   └─ base PermissionProfile + 获批 overlay

7. SecurityExecutionBroker 编译原生请求
   └─ writable/readable/readonly/denied roots + network rules

8. Native Runtime 建立 OS 边界后启动命令
   └─ 批准的能力在这里才真正生效

目录授权可以覆盖其后代，单文件授权只覆盖该文件；只读授权不能匹配写入请求。网络授权按 host、port、protocol 精确匹配。会话能力与原始动作分离，后续命令会继承已批准的精确范围。require_escalated 不进入这份可复用 profile；once/session 都只能为完整命令重试提供宿主权限，安全前缀则只属于 terminal 的明确 always 规则。

2.3 文件边界与工作区

内置文件、补丁和搜索工具先检查具体操作类型和目标路径。受管 shell 及已启用 Ace 托管的外援由操作系统限制其文件能力。完全访问按宿主用户权限运行，仍保留匹配的显式拒绝规则及 模式本身的工具限制。

2.3.1 基础权限

  • 项目会话把项目根设为可读写根；未选择项目的普通会话使用 owner 隔离的 task_workspaces/<workspace-id> 作为有效工作目录和可写根。系统提示会把这个 host 生成的 cwd 与宿主 HOME 明确标为可信路径。内置终端用宿主 HOME 解析 ~，但 cwd 仍是工作空间，且 HOME 下只有基础只读或已批准的精确写权限；外部智能体的投影凭据使用私有 HOME。
  • 路径在判断前会解析为最终规范路径；符号链接、junction 和 TOCTOU 交换由文件工具与平台测试覆盖。
  • 结构化文件工具永久拒绝写入文件系统根目录。
  • 在请求批准与替我审批中，Ace 数据目录、security DB 及其 WAL/SHM/journal 属于不可升级拒绝。
  • 在请求批准与替我审批中，workspace 下的 .git、.agents、.crew 默认是只读元数据；需要提交、暂存或维护项目配置时，会以整个元数据目录为真实原生边界展示并申请写权限。Ace 数据库、凭据与宿主配置仍不可升级。

2.3.2 权限合并规则

基础 profile 与用户追加授权按路径具体程度合并：更深的路径比父目录更具体，同等具体时 deny 获胜；标记为 escalatable=false 的拒绝和只读项永远不能被追加授权升级为写入。终端只能申请已存在的精确文件或目录；创建新文件时申请已存在的父目录，文件系统根写入永不开放。

可写工作区内的只读路径。Broker 把工作空间可写根内部的 READ entry 编译为协议字段 readonly_roots。helper 握手必须声明同名能力，否则 Gateway 按协议不兼容失败关闭。Linux 在可写 bind 之上重新挂载只读路径；Windows 为账户与 capability SID 同时授予读取并拒绝写入/删除；macOS 在 writable allow 之后为目标本身与子路径追加 deny file-write*。只有标记可升级且审批 overlay 覆盖相同目录时才移除此 carve-out；不可升级项始终保留。

2.4 进程执行、外援与工具链

compile_process_launch 在每个 turn 入口根据可信上下文编译 ProcessLaunch。审批通过后，命中的 grant/rule 与会话 permission profile 合并后写入启动快照；前台、后台进程和 captured adapter 都把同一 overlay 交给 Native Runtime。Ace terminal 支持 use_default、with_additional_permissions 与 require_escalated，并接受 justification；prefix_rule 只能与 require_escalated 一起使用，不属于 publish_site、MCP 或其他合成执行工具。

前台与后台桥接请求都会显式传递 full_disk_read，避免策略层显示“广泛只读”、原生运行层却仍从空文件系统启动。终端结果同时返回实际 cwd、HOME、执行边界、批准决定和实际应用的路径/网络权限，Agent 不应再把沙箱内精确扩权误述为失败或“文件工具绕过了沙箱”。

默认任务目录可能位于受保护运行时 home 的更深层。Broker 会在前台和后台共用同一个文件计划编译器：当一个 deny 是已认证工作区或已激活 Skill 只读根的严格祖先时，不把这个冲突的祖先 deny 交给原生后端；精确 deny、工作区内受保护元数据和 deny 的子路径仍保留。各后端保持 default-deny，因此该 carve-out 不会让同级凭据、数据库或其他 owner 目录变成可见资源。

2.4.1 失败关闭

  • 缺少 ProcessLaunch 时，受管适配器拒绝执行，不回退到当前 Python/Electron 用户权限。
  • helper 缺失、完整性错误、握手失败、能力不足、协议乱序或异常退出均返回稳定错误码。
  • 一个 monotonic deadline 覆盖启动、请求、输出和退出全过程。
  • 取消、超时、输出超过上限和协议错误都会终止 helper 及其进程树。
  • 原生协议具备双向 stdio 能力；尚未接入该 transport 的外部 adapter 会明确拒绝或使用已声明的受管兼容路径，不静默降级为宿主裸进程。

2.4.2 输入、环境与输出

  • 捕获式执行的 stdin 是一次性载荷，默认上限 1 MiB。交互式受管会话通过单独的双向通道传输。
  • 环境覆盖必须使用合法变量名，禁止覆盖 ACE_SECURITY_*、ACE_BUNDLED_* 和代理保留变量，总体默认上限 256 KiB。
  • 各原生后端从受控环境构建子进程环境；内置终端在 full_disk_read 受管基线中使用宿主 HOME，但 shell 以非登录模式启动，不隐式加载用户 profile。TMPDIR 仍由平台沙箱控制。携带 home_files 的外部智能体始终使用私有投影 HOME，避免凭据落入宿主目录。受管 PATH 会保留系统命令目录，并把随包 Python/Node/npm/npx 置于最前。
  • 用户显式激活的 Skill 根会重新对照当前 Skill 注册表和 realpath，匹配后仅作为本轮只读根继承到 terminal；伪造、移动或被替换的 Skill activation 失败关闭。Skill 的额外数据目录、虚拟环境和外部程序不会由 Skill 根隐式获得权限。
  • stdout 与 stderr 总量默认限制为 2 MiB，单帧最多 64 KiB；超限会停止进程。
  • 返回模型和任务日志前，会按注入的秘密值精确脱敏，并再执行通用敏感文本脱敏。

2.4.3 外部智能体兼容路径

features.external_agents.security_enabled 默认关闭。已配置的 Codex、Claude Code 和 ACP 外援继续使用各自的宿主适配器，包括原生流式协议、会话恢复、MCP 和已有权限回调。此时外援进程用当前操作系统用户身份启动。经 Ace 执行的内建工具仍按 Ace 会话授权。

显式启用外援托管后，Ace 的 ProcessLaunch.external_managed 选择原生运行边界。Codex 和 Claude Code 使用现有一次性执行路径，接入相关能力的 ACP 适配器使用原生双向 stdio。Codex/Claude Code 的一次性执行路径提供基础响应和工作区操作，动态 MCP、恢复及双向工具事件取决于所用适配器。托管外援的网络继续按适配器声明并获批的精确目标限制，即使 Ace 内建终端已启用直连。

2.4.4 灵感站点构建

publish_site 不把模型给出的包管理器字符串直接交给宿主 PATH。host 先限制命令族为 npm/pnpm/yarn/bun，再解析实际 Node 与包管理器脚本入口，以最终 argv/cwd 进入统一 exec 审核；批准后只把解析出的运行时安装根作为可信只读资源加入本次 ProcessLaunch。构建写权限仍只有当前 Workspace，网络仍由会话 overlay 决定。Node 子脚本使用受控 PATH；OpenSSL 不读取宿主全局配置。这样既能让打包 Node、Homebrew、nvm 和 Windows Node 安装工作，也不会把用户 HOME 或任意 PATH 目录整体开放。

2.5 终端、网页工具与浏览器联网

受管终端默认由操作系统阻止直接联网。精确授权后，网络请求通过运行组件建立的受管代理。日常开发如果需要访问依赖仓库、Git 远端或本地开发服务，可以在受信任的 Ace 应用配置中开启直连。

security:
  sandbox_enabled: true
  sandbox_workspace_write:
    network_access: true

此配置适用于使用工作区写入模式的 Ace 受管命令及其子进程。工作区写入权限、受保护路径和进程回收继续生效。直连由系统网络策略约束，可访问本地和私网服务，代理的逐目标校验仅适用于代理模式。浏览器、网页工具、模型 API 和外援分别沿用各自的网络策略。

终端结果的 network_mode 标识本次请求采用的网络策略。直连请求通过握手和启动能力检查，成功后执行审计记录 direct_network。旧运行组件拒绝直连请求。

2.5.1 搜索、网页提取、Wiki URL 与灵感 Automation

web_search、web_extract、Wiki URL 抓取和灵感 http_json Automation 共用 crew/security/outbound.py：只接受公开 HTTP(S)，拒绝 URL 凭据、localhost、私网、链路本地与保留地址；每次重定向重新校验。直连时只连接已校验为公网的数字地址。使用上游代理时的解析差异见下节。响应体有硬大小上限。网页工具和 Agent 手动 Automation 还会把精确 host/port/protocol 交给安全服务：请求批准模式等待 owner 决定，替我审批自动授权合格的公网目标，完全访问按宿主权限授权。跨域重定向会逐目标检查，授权决定进入网络审计。完全访问不会改变某个专用工具自身“仅公网 URL”的输入契约，但可以通过宿主命令使用完整网络能力。灵感预览响应同时设置 connect-src 'none'，生成页面不能另开一条未审核的 Chromium 联网旁路。

拒绝不是换工具的提示：结构化文件工具与 terminal 是两条都受安全服务控制的执行路径。前者由 Gateway 对单个动作实施路径策略，后者由 Native Runtime 对整个进程树实施操作系统隔离。用户明确拒绝任一安全审批后，当前 turn 建立统一拒绝栅栏并停止；后续 glob、file_read、Wiki、Skill、MCP 或 terminal 调用不会再执行。请求批准模式还会关闭工具预热与安全调用并发，防止另一个读取工具在审批结果到达前先完成。

批准后若 Native Runtime 返回 runtime_crashed、runtime_protocol_mismatch 或 sandbox_unavailable，这属于安全基础设施故障，不表示路径“在沙箱外”。终端把这些结果标记为真实工具错误并结束当前 turn，Agent 不得改用结构化文件工具掩盖故障。Desktop 的受管启动桥把宿主组装的工具链 PATH 从普通环境覆盖中分离：模型仍不能覆盖 PATH，但批准后的进程能够使用随包 Python/Node 与系统命令目录。

2.5.3 进程内 HTTP 支持上游代理级联

outbound.py 的安全口径与 Native Runtime 受管代理一致。判断通过后，默认把流量级联到用户已有的上游代理，由代理负责到达目标；没有上游代理时才直连。代理解析优先级（高到低）：调用方显式传入 → 配置 network.upstream_proxy（load_config 加载后注入为进程级默认）→ 环境变量 HTTP_PROXY/HTTPS_PROXY/ALL_PROXY（大小写都读）。支持 http://、https://、socks5://、socks5h://，纯标准库实现，三平台行为一致。

  • HTTP/HTTPS 代理走 CONNECT host:port 隧道；authority 始终带端口，CONNECT 握手限时后回到阻塞模式再做 TLS。
  • SOCKS5 走 RFC 1928 握手，支持无认证与用户名/密码；socks5h 把域名交给代理解析，socks5 由本地解析后再发 IP。
  • HTTP/HTTPS CONNECT 或 socks5h 可由上游代理解析域名。此时最终解析结果由受信任的上游代理决定。
  • 代理本身的 loopback 地址（127.0.0.1/::1）默认允许（本地 Clash 等场景）；network.allow_loopback_proxy: false 时拒绝。
  • 私网目标拒绝、URL 凭据拒绝、重定向逐目标授权、响应大小上限在代理模式下全部保留。

2.5.4 浏览器上传边界

上传和拖放先按结构化文件读取策略授权源路径；受管模式的广泛只读基线允许读取工作目录外的普通文件，但 Ace 私有路径与显式拒绝路径仍不可见。读取通过后，Python 在账号浏览器目录下创建一次性 approved-uploads/<nonce>，安全快照普通文件或目录，拒绝符号链接、junction/reparse point 与特殊文件，并执行总字节和条目数护栏。Electron Host 再独立验证暂存根、目标 realpath 和整棵目录；Playwright 操作结束后立即清理该次暂存区。Host 不再接受工作目录原始路径，也不再使用与 Playwright 能力不一致的 256 个顶层路径硬限制。

2.6.2 Windows：低权限身份 + ACL + WFP + Job

发行版在用户首次打开可见主窗口时自动检查随包组件和当前用户的沙箱身份。正式安装器已做过初始化时，此处只复用有效身份。直接启动的独立用户目录若仍缺少身份，使用与安装器相同的 Windows 授权与复查路径。隐藏登录自启期间不做准备。用户随后从托盘或再次启动应用打开窗口时，沿用同一套检查；同一进程内重复显示窗口不会再触发。CI 跳过自动准备，取消系统授权后可从设置页重试。

安全中心在 Gateway 确认需要防护设置时提供操作入口。该入口共用首次启动的安装协调器。已有自动检查或安装时等待同一结果；否则先核验身份与防火墙策略，再按需请求 UAC。完成后重新获取 Gateway 的本机防护状态。

Windows 保留系统与用户目录现有的访问权限。额外读取或写入使用精确 ACL 授权，进程结束后逐条清理。自检只授权临时测试范围。受管 PowerShell 会将工作区挂载为当前会话的 AceCurrentWorkspace:，相对路径从该工作区解析。$PWD.ProviderPath 返回实际文件系统路径。

安装期创建专用技术账户并持久化受保护身份状态。当前 Windows 后端使用专用账号和受限令牌。各网络模式分别选用离线、代理和直连账户。每次命令在跨进程 mutex 内下发临时 ACL lease，使用 restricted token 和 capability SID 启动，只继承显式句柄，再放入 kill-on-close Job Object。可写根内的受保护元数据对账户和 capability SID 都施加精确 ACL。离线账户由 WFP 阻断联网，代理账户只能连接运行组件固定的本机代理端口。已有安装缺少直连账户时，会在「设置 → 安全」提示完成 Windows 防护配置。

2.6.3 macOS：Seatbelt deny-default profile

macOS 每次运行生成独立 Seatbelt profile，并通过系统 /usr/bin/sandbox-exec 启动。workspace-write profile 开放广泛文件读取，写入只开放工作空间、临时目录和精确获批根；随后对 readonly_roots 与 denied roots 重新施加更具体的拒绝。用户路径通过 -D 参数进入策略。Seatbelt 分别应用离线、精确代理和直连策略。helper 为子命令建立独立进程组，取消或退出时整体清理。

2.8 状态持久化、审计与并发

新版审批请求带 decision_receipts: 1。用户点击后，桌面先保存本次的提交 ID、所选决定、工作区、会话和任务。持久前缀只保存 SHA-256 摘要，审批 nonce 留在主进程。Gateway 把这些字段、请求 ID、操作系统用户和认证账号绑定到对应的 approval_decision 审计事件。相同提交再次到达时读取原回执，首次有效决定才会发放权限并唤醒等待的工具。

服务端确认丢失时，桌面持有同一提交 ID，仅查询审计记录。账号切换会隔离待核对项，重启后可继续查询。匹配的 recorded 表明决定已经持久化，工具是否实际执行由对应的工具结果和回合终态记录。pending 表明请求仍待处理，unknown 表明当前存储中没有这次提交的确认。已有待核对项在客户端最多保留 24 小时，服务端沿用审计保留周期。产品内置 SQLite 库用同一事务写入持久规则、规则审计和审批回执。

2.8.2 审计记录与授权事务

在「设置 → 安全 → 安全审计记录」查看放行、请求批准、拒绝等决定及实际执行结果。审计菜单可导出当前账号的记录，或清理该账号 30 天前的记录。

审批决定、规则创建/禁用/删除和秘密注入是关键事件，无法持久写入时会让授权失败并回滚刚创建的 grant 或规则。普通事件可进入有界内存缓冲，后续成功写入时再刷新。这样不会出现“执行已经放行，但决定没有证据”的静默状态。

审计保存动作摘要和动作 hash，不直接依赖原始工具参数展示。命令行 token/password、HTTP 鉴权头、注入的秘密值等会在事件创建与入库阶段重复脱敏。查询始终按 owner 过滤，OS 用户仅保存 SHA-256。每次 captured execution，以及终端前台/后台进程结束时，都会写入 exec_result，包含实际 sandbox backend、已启用 capability、exit code；超时、runtime 崩溃、协议不匹配和 sandbox 拒绝则保存稳定错误码。后台 bridge 通过位于 Ace 受保护目录的随机 nonce sidecar 回传运行元数据，命令本身不能伪造该结果。

2.8.3 并发边界

  • decision lock 把 grant/rule 发布、审计提交与授权消费串成同一临界区；审计失败回滚时，不会有另一个线程已经消费临时权限并开始执行。
  • 切换模式会撤销旧的待审批。会话结束或登出会清理对应的待审批和临时授权。这些动作与审批提交共用决策边界。
  • Windows ACL lease 使用跨进程 mutex；固定代理端口的生命周期与 lease 串行，避免不同任务共用错误网络策略。

2.10 架构与安全边界

  5. 执行。批准的受管动作由工具策略或原生运行组件执行。完全访问使用宿主操作系统用户权限。
  6. 记录。能力探针、审计和发布物检查分别记录设备能力、实际决定与运行组件完整性。

4.1 原生协议与运行组件完整性

终端桥接子进程使用精简环境。Windows 的运行组件架构由当前 Python 的编译目标识别，兼容 x64 与 ARM64。组件清单核对平台和目标架构，随后核对二进制 SHA-256。

4.1.1 每任务 stdio 协议与身份校验

Gateway 每次执行都会启动新的 helper，通过 stdio 交换 NDJSON；helper 不监听网络端口。协议版本为 v3：

helper 启动
  └─ 从 ACE_SECURITY_RUNTIME_TOKEN 读取随机启动令牌（至少 32 字节）
  └─ ready { version: 3, capabilities: [stdin_once, stream_output, full_disk_read] }

host 请求
  └─ { version, token, nonce, request }

helper 响应
  └─ started(seq=0, capabilities, pid?)
  └─ stdout / stderr(seq++)*
  └─ completed | error(seq++)
  └─ EOF

令牌使用常量时间比较；nonce 至少 16 字符并在有界缓存中防重放。host 校验每帧的 version、nonce、严格递增 seq、事件顺序、终态和 EOF。Windows helper 还必须同时报告 restricted token、ACL、Job Object 和显式句柄继承能力，否则 host 拒绝结果。

4.1.2 helper 从哪里来

运行组件不会从任务 cwd 或任意 PATH 中搜索。开发态依次选择：

  1. ACE_SECURITY_RUNTIME 指定的绝对路径；
  2. desktop/security-runtime-bin 本机 staging；
  3. security-runtime/prebuilt/<platform>-<arch> 的仓库预编译目录。

manifest 存在时必须匹配 schema、平台、架构、文件名和二进制 SHA-256。源码树中的预编译产物还记录 source_hash：Rust 源码、测试、Cargo.toml 或 Cargo.lock 变化但未重建时，安全中心报告 runtime stale，不把旧二进制声明为可用防护。
