Acrew/security

宿主安全内核：命令与工作区策略、审批、沙箱、审计及 Native Runtime 边界。

1. 职责

  • 定义不依赖具体产品 Feature 的安全决策、授权、审计和执行边界。
  • 统一命令风险识别、Workspace 读写边界与外部 Runtime 权限分类。
  • 管理安全上下文、临时授权、持久规则、Native Runtime 调用和进程清理。
  • 不负责 Team 编排、Agent 业务流程或具体 Tool 的实现；这些模块只能消费安全能力。

2. 功能拆解

安全模块是 Host 与 Feature 共同依赖的稳定底座。策略数据可以由上层提供，但裁决逻辑归安全模块所有。

子功能说明状态
terminal_guard跨平台识别 hardline、dangerous 与需要审批的命令。已归位
workspace_guard校验工具和外部 Runtime 对可读、可写路径及网络副作用的访问。已归位
context / policy / grants构造安全上下文，解析模式策略并管理临时执行授权。已落地
service / broker统一审批、规则选择、审计和 Native Runtime 执行入口。已落地
launch / process_lifecycle封装 macOS、Linux、Windows 的安全启动与进程树终止差异。已落地

4. 数据模型与接口

调用方传入普通数据结构，安全模块返回不可变决策；调用方不得绕过裁决自行解释结果。

check_workspace_guard(tool_name, args, guard, *, cwd) -> WorkspaceGuardDecision
classify_external_permission(tool_call, guard, *, cwd) -> WorkspacePermissionDecision
classify_command(command) -> CommandClassification
detect_hardline_command(command) -> tuple[bool, str]

6. 扩展点

  • 新增安全策略应放入 crew/security，保持纯 Python、跨平台和可单元测试。
  • Feature 只能提交动作描述、权限上下文和策略配置，不得导入安全模块内部实现后绕过公开决策。
  • 新增依赖必须通过 lint-imports；历史豁免必须标注删除阶段，禁止扩大通配范围。
