Acrew/team

Team 多智能体：Formation 长期组队与 Runtime 临时补员。

1. 职责

  • 管理 Team roster、任务协作、成员通信、共享历史与结果呈现。
  • 通过 mode=team Execution Driver 对外提供一次协作请求，不参与核心 mode 路由。
  • 当前 Manager 仍由 Host 构造；完整 Product Feature 生命周期将在复杂并发迁移阶段收口。

2. 功能拆解

按子功能或核心流程拆解，这是本模块文档的重点。

子功能说明状态
Team Driver桥接 InProcessTeamManager.interact()，保留会话配置中的 external_team_id 解析。已落地
协作编排Formation、成员调度、任务图、mailbox 与协作历史。已落地
完整 Feature 所有权Manager、后台任务、Provider 与活动协作状态迁入 Team Generation。待迁移

3. 关键文件

文件作用
crew/team/team_manager.pyTeam 协作入口与运行状态。
crew/app.py迁移期 Team Driver Adapter 的同步装配。
crew/features/drivers.pymode 注册、解析与请求 Lease。

4. 数据模型与接口

Host 启用 Team 时注册一个独立桥接 Generation；请求期间 Registry 自动持有 Lease。

mode = "team"
generation = "product.team-driver-adapter@g1"
execute = InProcessTeamManager.interact

5. 当前存在的问题 / TODO

  • 桥接 Scope 当前只拥有 Driver 入口，尚未拥有 Team Manager 和内部后台任务。
  • team_internal 仍是 Core ResponseChunk kind，后续迁入命名空间 Feature Event。

6. 扩展点

  • 新增 Team 执行入口应通过 Team Feature 注册能力，不得在 CrewApp.handle() 增加分支。
