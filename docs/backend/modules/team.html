Acrew/team

Team 多智能体：Formation 长期组队与 Runtime 临时补员。

1. 职责

  • 管理 Team roster、任务协作、成员通信、共享历史与结果呈现。
  • 通过 mode=team Execution Driver 对外提供一次协作请求，不参与核心 mode 路由。
  • product.team Feature Bundle 统一拥有 InProcessTeamManager、mode=team Execution Driver 与 owner Provider 缓存生命周期（阶段 4C-1）。

2. 功能拆解

按子功能或核心流程拆解，这是本模块文档的重点。

子功能说明状态
Team Driver桥接 InProcessTeamManager.interact()，保留会话配置中的 external_team_id 解析。已落地
协作编排Formation、成员调度、任务图、mailbox 与协作历史。已落地
外援存储门面TeamExternalAgentStore 继承纯外援 Catalog，拥有 external_team/external_team_member 表、历史 formation 迁移、Team CRUD 与删除守卫事务；组合根用它维持 app.external_agents 既有行为。已落地（4A-1）
看板 Consumer生产装配注入动态 Consumer Provider；TeamPlanStore 与 Manager 按调用读取当前代，并在同步操作期间持有 Lease。停用后不回退旧 Store，业务行保留。已落地（4B-1）
完整 Feature 所有权Manager、后台任务、Provider 与活动协作状态迁入 Team Generation；通过 build_team_feature() 装配，CrewApp 不再手写构造 Manager/Driver。已落地（4C-1）

3. 关键文件

文件作用
crew/team/feature.pyTeam Product Feature Bundle：构造 Manager、注册 mode=team Driver 与 team Service，接入 Feature Runtime。
crew/team/team_manager.pyTeam 协作入口与运行状态。
crew/team/external_store.pyTeam 外援存储门面：Team 表、迁移与 CRUD，仍满足外援 Catalog 契约。
crew/app.py生产装配调用 build_team_feature()；保留 set_team_manager 与 app.team 兼容表面。
crew/features/drivers.pymode 注册、解析与请求 Lease。

4. 数据模型与接口

Host 启用 Team 时由 build_team_feature() 激活 product.team Generation；Generation 拥有 Manager、Driver 与 team Service。请求期间 Registry 自动持有 Lease。

feature_id = "product.team"
mode = "team"
service = ServiceKey("team")  # InProcessTeamManager
execute = build_team_feature(...).definition

5. 当前存在的问题 / TODO

  • team_internal 仍是 Core ResponseChunk kind，后续迁入命名空间 Feature Event。

6. 扩展点

  • 新增 Team 执行入口应通过 Team Feature 注册能力，不得在 CrewApp.handle() 增加分支。
