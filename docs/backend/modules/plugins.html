Ace / 后端模块 / features + plugins

Acrew/features · crew/plugins

Feature Runtime 统一所有权内核；Plugins 是迁移期目录发现与兼容入口。

1. 职责

  • 用 Feature Generation 和 Scope 管理第一方、第三方能力的统一生命周期。
  • 向插件提供受控注册上下文，并在启用/停用时管理插件贡献的工具与钩子。
  • 插件工具沿用核心 Registry 契约，可声明结果在 Agent 上下文中的生命周期。
  • 当前 crew/features 不包含目录发现或产品逻辑；PluginManager 将作为兼容 Facade 接入。

4. 数据模型与接口

generation = FeatureGeneration("wiki", sequence=1)
async with FeatureTransaction(generation) as transaction:
    transaction.register(dispose_service, label="service:knowledge")
    scope = transaction.commit()

await scope.dispose()  # 返回时该 Generation 已完成全部异步清理

注册标签必须能说明贡献类型和身份。Scope 进入停止状态后拒绝新注册和后台 Task；先关闭 Contribution，再清理 Resource，两相内部按后进先出执行。context.create_task() 创建的逃逸任务由单一 Task Owner cancel/join，不随任务次数累积 Token。

knowledge = ServiceKey[KnowledgeService]("knowledge")
services.register(
    feature_scope,
    knowledge,
    provider,
    scope_kind=ServiceScopeKind.WORKSPACE,
    scope_path=ServiceScopePath.workspace(workspace_id),
)
service = services.resolve(knowledge, request_scope)

解析从最窄的请求作用域逐级回退。同一代处于 ACTIVATING 时贡献仍不可见；Scope 提交为 ACTIVE 后统一生效。

acquired = plugins.acquire_service_lease(
    knowledge,
    label="gateway:wiki",
)
if acquired is not None:
    service, lease = acquired
    async with lease:
        await consume(service)

Consumer 不应先 resolve 再单独定位 Scope；acquire_service_lease() 保证 Service 与 Lease 来自同一可见 Generation。进入 draining 后新请求不可取得租约，旧请求释放前资源不会关闭。

PluginContext.register_tool(
    name, toolset, schema, handler,
    result_retention="important",
    result_identity_fields=None,
    result_policy_resolver=None,
)

资源工具应提供稳定 identity；根据 action 同时提供读写能力的工具可通过 resolver 动态返回策略。未声明的旧插件保持兼容，并按重要结果保护。

await plugins.discover_and_load_async(...)
await plugins.activate_phase_async("startup")
await plugins.update_plugin_async("browser", desired_config_revision=2)
await plugins.unload_plugin_async("browser")
failed = await plugins.aclose()

同步 discover_and_load() 继续服务现有构造入口；manifest 默认 activation_phase=build。创建长期 asyncio Task 的插件声明 startup，Definition 先进入 DISCOVERED，再由宿主长期事件循环激活。同步 unload_plugin() 不允许在事件循环中假报完成。

requires:
  - storage
optional:
  - owner_model
provides:
  - knowledge

ctx.register_service("knowledge", provider)
storage = ctx.resolve_service("storage")

Runtime 先发现全部定义再规划激活批次。声明 provides 后必须由同一 Scope 兑现注册；Consumer 不依赖目录扫描顺序。组合根通过 publish_host_services() 发布 Host 能力，并在服务就绪后重试 Waiting 插件。

crew --dump-features
crew --dump-features --json

启动审计与 CLI 使用同一结构化快照；Waiting/Failed 会列出缺失 Service 或原始错误，CLI 同时返回非零退出码。

stop_policy: drain
drain_timeout_seconds: 30

async with context.acquire_lease("request:42"):
    await execute_request()

目录插件的 Tool、Hook、Middleware 和 Command 由 Adapter 自动持有 Lease。drain 等待旧请求，cancel 通知并取消活跃异步任务，immediate 直接清理并记录被越过的 Lease，restart_required 保留当前 Generation 到宿主关闭。同步 Tool 即使收到取消，也会等工作线程真正退出后才释放 Lease，避免后台线程继续使用已关闭资源。

result = await runtime.update(
    FeatureDefinition(
        "provider",
        install_new_config,
        desired_config_revision=2,
        update_strategy=FeatureUpdateStrategy.REPLACE,
    )
)

更新请求必须提交递增且已验证的不可变定义。replace 允许同一 Feature 的新旧 Generation 短暂并存：新服务仅在新 Scope 提交后可见，Registry 选择最新 Active Generation，旧代随后关闭 Lease 入口并退役。restart 用于独占资源：先 drain 并清理旧代，再安装新代；安装失败会以旧定义创建恢复 Generation。失败期间 desired revision 保留用户意图，effective revision 始终反映实际运行配置。

ctx.register_execution_driver(
    "feature.echo",
    execute,
    capabilities=("demo.echo",),
)

async for chunk in runtime.execution_drivers.dispatch(envelope):
    ...

Feature 与目录插件共享同一个 Driver Registry。注册发生在 Activating Scope 时仍不可见，Scope 提交后才可解析；Driver 执行自动持有所属 Generation Lease，插件卸载或 Feature 停用后 mode 贡献随 Token 一起撤销。

ContextContribution(
    prompt_parts=("dynamic context",),
    messages=(Message.system_reminder("persistent context"),),
)

Prompt Contributor 可以返回动态 fragment；只有同时声明 persistent=true 和 model-visible 的 Contributor 才能返回要写入 canonical history 的 Message。预览使用同一贡献链，但不会写回 Store。

ctx.register_event_contributor(
    FeatureEventContributor(
        contributor_id="feature.session.events",
        handler=take_pending_event,
        priority=100,
    )
)
await runtime.event_contributors.dispatch(envelope, push_feature_event)

事件 Contributor 与其 Feature Generation 同生共灭。Registry 先按 priority 和 ID 排序，再在对应 Lease 内生成并投递；Feature handler 的降级与 Host sink 的传输失败分开处理。

context.register_agent_preset(
    AgentPresetContribution(
        name="Knowledge",
        system_prompt="...",
        toolset_additions=("knowledge.read",),
        context_tags=("knowledge",),
    )
)

Preset 只声明中立策略。Host 在解析后持有其 Generation Lease，并将代次写入有效 Agent 配置；产品专属 prompt、工具与 Skill 不进入中心装配分支。

5. 当前存在的问题 / TODO

  • 运行期 Provider 消失后的 Consumer 级联 drain/retry 尚未实现，将在配置更新与依赖重算时收口。
  • 目录插件已有通用 restart 更新入口；运行期配置快照、校验与用户控制面 API 仍需在具体 Feature 迁移时接入。
  • ctx.services 兼容字典仍在使用，待 Service Adapter 完成后删除。
  • 外部 MCP 协议当前不携带 Ace 生命周期元数据，因此默认按重要结果保护。

6. 扩展点

  • 新增运行时注册类型必须返回 disposer 并归属一个明确 Generation，不得另建独立清理清单。
  • 新增插件工具时在插件注册处声明结果语义，不向 Agent 压缩器添加插件工具名判断。

宿主能力状态投影（6AB）

FeatureRuntime.capability_snapshot() 同步读取真实 records，以 Feature ID 为键提供 state / available / generation。当前 Scope 可接受新 Lease 时才报告可用；未声明项缺席，drain、失败、停用不可用；replace 候选安装期间仍投影正在服务的旧代。读取不创建 Lease，也不导出错误、配置或完整诊断。

此快照表示宿主运行时准入，不替代账号权限。Team 和 Dynamic Kanban 保持各自身份，不在 Runtime 中新增业务枚举。见 ADR-0040 与 6AB 测试记录。
