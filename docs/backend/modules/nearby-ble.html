Ace Nearby 蓝牙同伴

Ace 的“同伴”模块通过 Bluetooth Low Energy 发现附近运行 Ace 的电脑。用户选择设备后建立一对一会话，请求通过 BLE GATT 发送给对方的 Ace Agent，Agent 回复再沿原连接返回；两台电脑不需要连接同一局域网，消息传输也不经过云端中继。

产品流程

  1. 进入“同伴”页面后，Ace 发布 BLE GATT 服务并扫描附近使用相同服务 UUID 的设备。
  2. 发现结果只作为候选设备展示，不会自动进入聊天状态。
  3. 用户点击“连接”后发送 peer.connect 控制消息；双方界面同步显示已连接。
  4. 发起端发送 agent.request；接收端按对端隔离的会话调用本机 Agent，并返回 agent.response 或 agent.error。
  5. 关闭“允许被发现”会停止本机 BLE 广播；停止查找只影响本机扫描。

BLE 协议

服务 UUID 为 5957645b-4b06-49cf-bde2-366a593e73a7。GATT 服务包含 PeerInfo、IncomingMessage 和 OutgoingMessage 三个特征。Central 订阅 OutgoingMessage 通知，并向 IncomingMessage 写入分片 JSON 帧。

每个实例持久化一个随机 Peer ID。物理连接建立后，Central 先读取静态 PeerInfo，再按两个 Peer ID 确定唯一连接发起方；非发起方会在写入通知订阅前关闭重复物理连接，避免 macOS 与 Windows 同时扫描和广播时争用 GATT 会话。保留连接随后订阅 OutgoingMessage 并完成 hello 身份握手。Windows 写入 Notify 的 CCCD 失败时会清理监听器并最多重试 3 次，日志保留底层 WinRT 状态和完整错误链。

只有用户选择设备并交换 peer.connect 后，界面才进入已连接状态。主动断开使用 peer.disconnect。Agent 对话协议版本为 v2：请求使用 agent.request，回复使用 agent.response，失败使用 agent.error；回复通过 request_id 关联原请求，单条文字上限 8000 字符。旧版普通消息协议不会被误认为兼容客户端。

BLE 连接不依赖 Wi-Fi 或局域网。实际可发现距离、连接稳定性和吞吐受蓝牙适配器、系统权限、射频环境以及操作系统节能策略影响。

桌面 IPC

方向类型用途
Renderer → Ruststart_discovery / stop_discovery开始或暂停 BLE 扫描。
Renderer → Rustset_discoverable启用或停止本机 BLE 广播。
Renderer → Rustconnect_peer / disconnect_peer手动建立或断开指定 Peer 的逻辑会话。
Renderer → Rustsend_agent_request向已连接 Peer 的 Ace Agent 发送请求。
Main → Rustsend_agent_reply将本机 Agent 的回复或错误返回给请求方；Renderer 不能直接构造此命令。
Rust → Rendererpeer_discovered / peer_unavailable更新附近设备列表。
Rust → Rendererpeer_connected / peer_disconnected / peer_connection_failed更新一对一连接状态。
Rust → Desktopmessage传递 agent.request、agent.response 或 agent.error。

运行与调试

cargo run --manifest-path nearby/Cargo.toml -- \
  --ipc \
  --transport ble \
  --display-name "Mac Ace" \
  --agent-name "Ace Agent" \
  --peer-id ace_mac

# 无蓝牙硬件时使用 mock 后端做协议联调
cargo run --manifest-path nearby/Cargo.toml -- --ipc --transport mock

桌面开发模式使用 cd desktop && npm run dev。诊断日志输出到 stderr，stdout 只输出 JSONL IPC 事件。

macOS + Windows 双机验收

  1. 打开两台电脑的蓝牙；Wi-Fi 可以关闭，两台电脑不需要连接同一网络。
  2. 在两台电脑安装并启动同一版本 Ace，授予系统蓝牙权限后进入“同伴”。
  3. 保持“允许被发现”开启，确认双方列表出现对方设备，未点击前状态为“可连接”。
  4. 在 Mac 点击 Windows 设备的“连接”，确认双方都显示“已连接”。
  5. Mac 发送问题，确认 Windows 自动调用本机 Ace Agent，Mac 随后收到 Agent 回复；不需要 Windows 用户手工输入回复。
  6. 连续发送第二个问题，确认对方 Agent 保留该 Peer 的上一轮上下文；再换一台 Peer 时应使用独立上下文。
  7. 点击“断开”，确认双方输入框被禁用；再次连接后重复双向发送。
  8. 关闭一端“允许被发现”，另一端重新查找后不应再出现新的发现结果。

当前边界

  • 只支持一对一文字消息；不提供群聊、文件、提及和回复。
  • Nearby 页面记录只保存在页面内存中；对端 Agent 上下文会按 Peer ID 持久化，但当前没有单独的历史管理界面。
  • 当前调用对端的默认内置 Ace Agent，不支持由请求方选择对端的其他 Agent。
  • Nearby Agent 会话固定禁用全部工具与 Skills，只能生成文字回复；附近设备不能借此访问对方电脑的文件、账号或连接工具。
  • Peer 间请求与回复不经过局域网或聊天中继；Agent 生成回复时，内容仍会按接收端现有模型配置提交给本机或外部模型服务。
  • 接收端必须保持“同伴”页面打开，使 Nearby 服务继续运行，并且本机模型配置可用。
  • 当前未实现配对码与应用层端到端加密，不应发送敏感信息。
  • BLE 通道吞吐有限，不适合大文件或高频消息。
