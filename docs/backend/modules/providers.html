Acrew/providers

Provider 层：把内核 Message/工具 schema 翻译成具体厂商 API，隔离厂商 SDK 与 wire 协议差异。

1. 职责

  • 实现 crew.core.interfaces.LLMProvider（chat / stream_chat），负责"翻译"：内核 Message ↔ 厂商 wire 格式，不掺业务逻辑。
  • 维护厂商档案表（vendors.py）：把 OpenAI/Anthropic 两种 wire 协议之下的厂商专属差异收口成显式数据。
  • 不做：会话管理、重试策略（属 agent/executor 层）、工具执行。

2. 功能拆解

子功能说明状态
openai_providerOpenAI Chat Completions 兼容 Provider（openai SDK + httpx）。base_url 可指向任意兼容端点；工具调用增量拼装与流式提前派发；reasoning 字段别名解析（reasoning_content / reasoning / reasoning_text）；厂商思考参数（extra_body）按 compat 开关注入；DeepSeek 式 assistant 消息 reasoning_content 回填。已落地
anthropic_providerAnthropic Messages API Provider（httpx 直连）。base_url 覆盖后同样服务走 Anthropic 协议的厂商端点（Kimi For Coding、MiniMax）。已落地
vendors（厂商档案）厂商注册表：VendorProfile（协议 / base_url / api_key_env / 模型目录）+ VendorCompat（思考参数格式、reasoning_effort 支持、回传要求、等级映射）。收录 DeepSeek、ZAI（全球/CN coding 端点）、Moonshot（全球/CN）、Kimi For Coding（Anthropic 协议）、MiniMax（全球/CN，Anthropic 协议）、Qwen Token Plan。已落地
ssl_context进程级共享 SSLContext（cadata 一次性加载），所有 provider 的 httpx/openai 客户端共用，避免 cacert.pem 病态微读拖慢启动。已落地
classify（异常分类）两个 provider 共用的异常分类助手：classify_provider_error() 把 SDK/httpx 异常解析为 ErrorClassification(kind/status/retryable/retry_delay/category)；吸收原有两份类名启发式（isinstance + __cause__ 递归 + 消息文本 + 类名/status）；429/503 解析 Retry-After（响应头秒数格式优先，body retry_delay 兜底，解析失败静默回落 None）；过载（503）与欠费从可重试中分离。已落地

4. 数据模型与接口

LLMProvider 契约（crew/core/interfaces.py）：reasoning_mode 取值 None = 模型默认；"off"/"disabled" = 关闭思考；minimal/low/medium/high/xhigh/max = 思考等级，由档案映射为厂商参数。

VendorProfile:  id / name / protocol("openai"|"anthropic") / base_url / api_key_env
                / models: tuple[VendorModel] / compat: VendorCompat
VendorModel:    id / reasoning / vision / context_window / max_tokens / thinking_level_map
VendorCompat:   thinking_format("none"|"deepseek"|"zai"|"qwen")
                / supports_reasoning_effort / requires_reasoning_echo / thinking_level_map

resolve_vendor(provider_id, base_url, model)   # id 精确匹配 > host 匹配 > 模型 id 匹配
compat_for_model(vendor, model_id)             # 填入等级映射；不支持思考的模型收掉思考参数

装配（crew/app.py）：provider_id 写厂商 id（如 deepseek）即按档案装配——base_url / API key（档案默认环境变量，如 DEEPSEEK_API_KEY）/ vision（模型目录标记）取档案默认值，用户显式配置优先。通用 openai/anthropic 配置按 base_url host / 模型 id 兜底识别厂商（host 匹配不受协议过滤，URL 即端点身份；模型 id 匹配仅在同名协议厂商内，避免协议劫持）；未知 id 仍抛 ValueError。key 解析按 owner 作用域：凭证库按 owner 隔离存储，owner 私有 key 写 owner overlay .env（accounts/<hash>/.env），不同步进程环境；全局/内置模型走共享层（共享 config.yaml + 系统 env）。

# config.yaml 示例：env 里放 DEEPSEEK_API_KEY 即可，无需填 base_url
provider: deepseek
model: deepseek-reasoner
