Acrew/cron

Cron 计划任务：持久调度、触发执行、投递与 Agent Prompt Context。

1. 职责

  • 持久化按 Owner 隔离的定时任务和运行记录，计算 trigger 并调度执行。
  • 构造 Cron Envelope，交给共享 SessionDispatcher 执行，并记录终态。
  • 拥有定时任务触发轮的模型上下文；Agent Runtime 不理解 Cron 产品语义。

2. 功能拆解

子功能说明状态
任务与运行存储保存 schedule、trigger、投递目标、Owner 和 fire 幂等记录。已落地
调度服务定时 claim、并发上限、重试与完成回调。已落地
自然语言计划解析 interval、once 等用户输入并构造 trigger。已落地
Trigger Contextcron.trigger.reminder 为触发轮贡献瞬时 prompt fragment。已落地
Cron Runtime Featureproduct.cron 统一拥有 Scheduler、Tools、Context、Host Binding、Owner mount 与 restart 更新。已落地
Cron 数据平面持久任务数据独立于运行代；停用撤销运行能力但不删除任务记录。已落地
Route ContributionHTTP 路由进入 Cron Bundle 与 Route Registry。待迁移

3. 关键文件

文件作用
crew/cron/jobs.py任务/运行存储、trigger 构造和 schedule 解析。

4. 数据模型与接口

ContextContributor(
    contributor_id="cron.trigger.reminder",
    phase=ContextPhase.PROMPT,
    priority=50,
    persistent=False,
)

await contribute_cron_trigger_reminder(envelope)

bundle = build_cron_feature(host, registry, store, enabled=True, max_parallel_jobs=2)
app.declare_managed_feature(bundle.definition)
await app.update_managed_feature(next_bundle.definition)

只有 channel=cron 的 Envelope 产生 fragment；任务名来自 cron_job_name。product.cron 在宿主事件循环中激活，六个工具和每次 Fire 都持有本 Generation Lease。更新采用 restart：先取消并清理旧代，再启动新 Scheduler，最后重新挂载当前 Active Owner；失败由 FeatureRuntime 恢复旧定义。

5. 当前存在的问题 / TODO

  • HTTP Route 仍由 Gateway 内置路由表装配；下一步迁入 Cron Bundle 的 Route Contribution。
  • 持久 Store 当前作为停用后仍可访问的数据平面由 Host 关闭；后续引入稳定数据服务契约后再移除 CrewApp.cron_store 兼容字段。

6. 扩展点

  • 新增触发轮上下文在 Cron Contributor 中扩展，不向 Agent Runtime 添加渠道判断。
  • 新增 Scheduler 资源必须能被 Scope drain/cancel，持久任务数据不随 disable 删除。
