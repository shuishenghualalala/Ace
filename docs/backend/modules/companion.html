Acompanion

状态文档：目前无后端实现；历史原型已废弃，原型数据库表已清理。

1. 当前状态

companion（同伴 / 附近会话）在 HEAD 中没有后端实现：不存在 crew/companion/ 模块，也没有 crew/gateway/routers/companion.py。本模块文档此前是未填写的模板占位。

曾在分叉分支（2db4cb4「feat(companion): integrate pluggable nearby conversations」、9efc3a0「feat(desktop): enhance companion and workspace experience」）原型化，含 crew/companion/service.py、crew/gateway/routers/companion.py、desktop/src/ui/features/companion-composer-presence.ts，但该分支被废弃、代码从未进入 HEAD。

2. 原型数据库清理

原型在本地开发库 crew_data/crew.db 创建了 8 张 companion 表，全部为空（0 行），且不在 crew/state/_migration.py 的任何归属清单（OWNER_TABLE_LABELS 与全部 *_DB_TABLES）中。它们会与未来任何 companion 功能产生碰撞，因此已按用户确认范围从主库删除。

表用途
companion_profilecompanion 账号资料（展示名 / 头像 / 可发现性）
companion_room会话房间
companion_room_member房间成员
companion_outbox待投递事件发件箱
companion_peer附近对端
companion_conversation_binding会话绑定（conversation ↔ session）
companion_agent_publicationAgent 公开发布
companion_agent_runcompanion Agent 执行记录

删除决策：8 表均 0 行、无代码引用、不在任何归属清单；删除后仅这 8 张表消失，其余表（含 ADR-0038 拆库备份表）不受影响。

3. 未来方向

companion 的产品范围推迟到未来的 Channel Bundle 决策（产品 PRD 与 插件架构演进计划）。届时按目标形态实现，并作为「不允许中心接线」功能的第一个验证样本（见计划 §8.4）。

4. 防回归

为阻止「幽灵表」再次无声出现，crew migrate orphans（crew/state/_migration.py 的 orphan_main_db_tables，只读诊断）可扫描主库中未被任何归属清单覆盖的表；companion 未来若落库，其表必须登记进 OWNER_TABLE_LABELS 或对应 *_DB_TABLES 清单。
