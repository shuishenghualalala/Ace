Ace「灵感」统一 App 库

“灵感”是用户可创建、使用和继续设计的本地 App 集合。内部继续复用 sites 模块，并保留 site 与 canvas 两种运行时实现；图库、详情、对话和操作层不向用户暴露这一区别。

实现范围：统一图库、真实内容预览、原对话修改、ZIP 分享、固定到桌面、受控删除、对话 Surface 和元素批注。源码与原对话始终保留；不包含导入、在线公开分享、跨设备同步或重启恢复悬浮窗。

1. 用户模型与主流程

  1. 侧栏一级入口显示“灵感”，首页直接加载当前账号所有已部署 App，不要求先选择 Workspace。
  2. 首页按更新时间倒序显示响应式卡片；卡片使用懒加载、不可交互的缩放 iframe 展示真实内容，并支持名称和描述搜索。
  3. 点击卡片进入完整可交互 App。详情统一提供“修改、分享、固定到桌面、删除”。
  4. “修改”进入资源记录的原始 sessionId；“分享”保存离线 ZIP；“固定到桌面”打开无系统标题栏、可拖动缩放且始终置顶的便利贴；“删除”仅清理运行产物和不再共享的派生资产。
  5. 新建入口创建 inspiration_creation=true 的 builtin Session，标题和输入提示统一为“灵感 / 描述你想创建的 App”。旧 site_creation 会话继续识别为“灵感”。
  6. Agent 生成或发布内容时返回标准 surface，聊天历史中显示可恢复的生成物卡片。点击后在右侧 Inspector 进入“使用”或“批注”模式。

新建灵感 → 对话设计 → Surface 预览/批注 → 部署到图库 → 使用/分享/固定/继续修改

4. HTTP 接口

方法与路径作用
GET /api/sites/inspirations列出当前 owner 的网站与 Canvas，按 updatedAt 倒序。
GET /api/sites/inspirations/{id}读取统一详情和批注。
DELETE /api/sites/inspirations/{id}按内部生命周期安全清理运行资源。
POST /api/sites/inspirations/{id}/export生成网站 Release ZIP 或 Canvas 离线 ZIP。
POST /api/sites/inspirations/{id}/annotations创建统一批注。
PATCH /api/sites/inspirations/{id}/annotations/{annotation_id}更新批注状态。
GET /api/sites/canvases/{canvas_id}/render渲染包含 Widget iframe 的完整 Canvas App。

旧网站、Canvas、Widget、Automation 接口继续保留，使已有客户端、数据和工具调用不失效。

5. 预览与 Surface

ace-site://{resource_id}/ 只接受规范的 site_*、canvas_* 或 widget_* ID。主进程把请求映射到当前认证 Gateway；站点资源路径由后端再次执行 release 根目录边界校验。Canvas 入口将 12 列布局渲染为完整 App，每个 Widget 继续在独立 iframe 内运行。

publish_site、Canvas.show 与 Widget.show 都返回 kind=inspiration 的 Surface。聊天渲染器从持久化工具结果中提取最小 Surface 元数据，因此刷新、历史回放和重新进入 Session 后仍可显示生成物卡片。网站 Surface 使用完整 App iframe；Canvas/Widget Surface 依据 resourceRevision 验证并刷新。

6. 批注链路

网站预览桥返回 route、CSS selector、元素标签、截断文本和上下文。Widget Runtime 还返回 Canvas、Widget 与 mount 标识；嵌套 Canvas iframe 把事件转发到 Desktop。统一批注表使用 targetKind 区分 site_dom、canvas、widget 和 widget_dom。

批注按原 Session 聚合为 Composer 草稿。发送内容包含源码路径、内部资源标识、页面路由、selector、当前文本、revision 与修改要求。网站修改后等待用户明确重新部署；Widget 修改后调用 Widget.validate 并刷新 Surface。该差异由 Agent 工作流处理，不要求用户选择类型。

旧 site_annotations 会在 Store 初始化时使用相同 ID 迁移；网站旧草稿 localStorage key 也会转存到 ace.inspirationAnnotationDrafts.v1，避免升级后丢失未发送批注。

7. 分享与删除

7.1 网站

分享包沿用 active release，包含构建后的静态文件，不包含源码、日志、批注和绝对路径。删除时移除数据库运行记录、release、export 和统一批注；Workspace 源码与原 Session 保留。

7.2 Canvas

离线 ZIP 包含 index.html、无敏感元数据的 manifest、Widget 静态文件、布局和最近成功数据快照。Runtime 保留客户端交互，但不包含实时刷新入口、Automation URL、运行日志、批注、认证信息、本地绝对路径或 source map。

删除 Canvas 时先移除 placement，再清理不再被任何 Canvas 使用的 Widget；随之删除没有其他 Binding 的 Automation、Binding 和 Run，并停止对应调度。共享 Widget、仍有绑定的 Automation、工作区源码和原 Session 均保留。

8. Electron 安全边界

  • 悬浮窗 IPC 只接受规范的 site_*/canvas_* ID，不能传 URL；同一资源最多一个窗口。
  • 便利贴在 macOS 使用透明圆角，在 Windows/Linux 使用兼容性更稳定的实色无边框窗口；三端均支持拖动、缩放、置顶和应用内取消固定。
  • 小窗启用 contextIsolation、sandbox、webSecurity，禁用 Node、webview、新窗口和资源外导航。
  • 固定状态仅存于主进程内存；关闭、取消固定、删除或应用退出会销毁窗口。
  • ZIP 保存只接受当前 owner 的 sites/{site|canvas}_*/exports/*.zip canonical regular file，再由系统保存对话框确定目标。
  • 所有 API 查询和写入继续以 owner_account_id 隔离。

  • 后端覆盖：混合列表排序和 owner 隔离、旧批注迁移、统一批注上下文、Canvas 离线包敏感信息排除、共享资产删除。
  • Desktop 覆盖：单一图库、搜索、真实预览、四个操作、原对话跳转、历史 Surface、批注聚合。
  • Electron 覆盖：Canvas 协议、非法资源 ID、悬浮窗安全配置和受控 ZIP 保存。
  • 交付检查：Pytest、Vitest、TypeScript、ESLint、安全扫描、CSS lint 与重复选择器审计。
