## 2. 实际实现

- **独立执行内核**：SQLite 事务交接、稳定 task/unit 与独立 attempt、依赖调度、并发上限、
  同成员槽位、声明的共享资源互斥。先保存调用意图，再执行真实调用。
- **明确恢复**：失败与不确定结果分开；原成员重试保留旧尝试；unknown 须明确核实确认，
  不无脑重放；已完成工作不重复执行。暂停/取消/恢复及版本检查有对应约束。
- **资料权限**：当前 owner 的知识库 Source 快照，记录文件名、页面、原文及 SHA256；
  禁止未解析/越权来源、重复标题和静默截断。独立审阅不读取互相的草稿。
- **真实评审契约**：必须是真实 fork/join 四节点，两个不同审阅成员；内置审阅禁用工具，
  直接交付正文；最终 3 项目 × 4 维度、有具体材料主张/判断/待确认、逐字引文与三个追问。
  校验失败保留实际输出，不使用示范答案补成成功。
- **双端可见性**：桌面/Web 使用同一执行投影，展示实际状态、分配依据、执行者与尝试历史；
  不再用平滑进度冒充完成；完整 Markdown 表格和文末追问可阅读，失败原文有单独标签。
- **实机修复**：Leader 工作包被旧 query 覆盖、空事件前缀恢复、无效计划继续执行、
  最终 join 缺依赖、截断续写丢失前文，以及开发版 Electron 构建与启动竞态。

参考 DeepSeek `dsh-superagent-prototype@8c32a9dc5d72c033816c6a8110b37f40cf94fba4` 的
domain/execution 设计，借鉴工作身份/尝试分离、意图先于效果、明确恢复的思想；
未复制其实现，也未宣称研究原型本身已经生产就绪。

## 4. 评审内容复核与使用提示

实际报告正确区分了：

- A 的均值 × 1.1 代码与尚未实现的 AI 解释；99 元/5 店只是模拟假设，效果未实测。
- B 的静态字符串插值与计划中的 LLM；49 元/20 次反馈不是付费或留存验证。
- C 的按距离排序与未来匹配优化；10 单/日只是设想，付费方和食品安全流程未获证明。
- 三案都缺真实运行与商业验证，不能自动评分、排序或录取。

**仍需评委复核，不能宣称语义准确率 100%。** 交付前开发助手复读发现的措辞边界：

1. B 商业卡“假想 20 次试用反馈支持需求判断”容易误读。原文只说反馈由演示作者编写，
   未声称它能证明需求。使用时应读作“材料列出作者编写的 20 次假想反馈，不构成需求验证”。
   同行的引文和分析已经明确否定真实验证；交付的原始模型报告未被人工改写。
2. 三案“材料完整与可复核”的“强”仅支持**这些文件确实存在、边界披露可查**这一窄主张，
   不是项目质量强，也不是部署、合规、市场或 AI 效果证据强。
3. “可替代性高”“99 元覆盖风险偏高”属于待验证的分析假设，不是有竞争测试或成本测算的事实。
   应要求补充替代品比较、单客服务成本与实证记录。

机器审计检查结构、引用、依赖、执行身份、快照哈希与时间重叠，
不检查所有推论是否成立。状态保留 pending 正是这一边界。

## 7. 恢复与运行

交付 bundle 包含 `dev` 的完整历史，不含 node_modules、虚拟环境、本机凭据和运行数据库。
在新目录恢复，勿覆盖已有仓库：

```bash
git clone /absolute/path/ace-dev-collaboration.bundle ace-review -b dev
cd ace-review
uv sync --extra dev
```

基于仓库配置示例填写本机 `config/config.yaml`，真实模型密钥只从环境读取。
合并 `examples/project-review/team-config.yaml` 中的两个内置审阅成员。
本轮配置模型 `kimi-for-coding`，Anthropic 兼容接口，`max_tokens: 24000`、`timeout: 360`。
这是本机测试配置，不是所有模型的通用最优值。确认自己的模型额度及服务可用。

```bash
cd desktop
pnpm install --frozen-lockfile
pnpm dev
```

另一个终端回到仓库根目录：

```bash
uv run python scripts/run_project_review_gateway.py --output /absolute/path/new-review-run
uv run python scripts/audit_review_execution.py /absolute/path/new-review-run/executions.json
```

脚本会创建新知识库与会话，导入 13 份来源，触发真实模型调用，产生实际费用；
未全完成会非零退出并保存失败记录，不制造“成功答案”。
专用 `project_review_v1` 契约目前由该脚本/WS 参数显式开启；
**普通聊天框尚无该契约专用开关**，普通团队聊天不自动附带固定三项目校验。
桌面打开新会话 → 看板 → 协作 → 放大 → 综合节点，可看完整报告与尝试历史。

模型失败时按 `docs/collaboration-runtime.md` 的恢复 API 或节点“原成员重试”操作。
先检查原因；unknown 状态必须核实外部副作用。不能把网络失败后再次运行整个脚本当作同一任务恢复。
