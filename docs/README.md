# Ace 文档维护指南

> 黑白简约 · 按模块组织 · 一份文档讲清一个模块的功能拆解、开发内容与当前问题。

---

## 1. 文档目录结构

```
docs/
├── README.md                 # 本文档：维护规范与风格
├── index.html                # 文档总览入口
├── backend/
│   ├── modules/
│   │   ├── _template.html    # 模块文档模板
│   │   ├── index.html        # 后端模块索引
│   │   ├── agent.html        # 一个模块一份文档
│   │   ├── cli.html
│   │   └── ...
│   └── weixin-channel.html   # 跨模块/渠道设计文档
├── browser/                  # 浏览器自动化
├── deploy/                   # 部署与发布
├── frontend/                 # 前端与桌面端
├── product/                  # 产品需求与 PRD
├── security/                 # 安全运行时与策略
└── testing/                  # 测试方案与报告
```

原则：

- `backend/modules/` 与 `crew/` 子目录一一对应。
- `browser/`、`security/` 虽在 `crew/` 下存在同名模块，但因涉及独立工程（Playwright、Security Runtime），单独成册。
- 产品、部署、测试、前端按领域分层，不混在 `backend/modules/` 里。

---

## 2. 模块文档必备章节

每个 `backend/modules/<module>.html` 必须包含以下章节，复制 `_template.html` 后填写：

| 章节 | 说明 |
|------|------|
| **1. 职责** | 一句话职责 + 边界（做什么、不做什么）。 |
| **2. 功能拆解** | 核心流程、子功能、状态机、对外暴露的能力。这是文档的重点。 |
| **3. 关键文件** | 表格列出 `crew/<module>/` 下核心文件及作用。 |
| **4. 数据模型与接口** | 关键类、函数签名、Schema、事件/消息约定。 |
| **5. 当前存在的问题 / TODO** | 已知 bug、技术债、待决策项、后续计划。 |
| **6. 扩展点** | 后续如何在此模块上新增功能，需遵守的契约。 |
| **7. 变更记录** | 每次代码改动后追加一行：日期 + 变更 + 影响面。 |

小更新（单文件单行修复、无行为变更）不强求更新文档；涉及职责、接口、新增子功能时必须更新。

## 3. 文档风格

### 3.1 视觉

- **黑白简约**：白底黑字，仅使用 `#111` / `#555` / `#999` / `#e8e8e8` / `#fafafa` 五色。
- **无装饰元素**：不使用 emoji、图标字体、渐变、阴影、动画。
- **字体**：系统无衬线 + 等宽字体，不引入外部字体。
- **版式**：最大宽度 `960px` 居中，标题下加细线分隔，表格与代码块使用浅灰边框。

### 3.2 写作

- **先讲功能，再讲代码**：模块文档首先是「功能拆解文档」，开发内容是附录。
- **一句职责优先**：每个模块文档开头必须有一句话说明它是做什么的。
- **表格优于长段落**：关键文件、接口、变更记录用表格。
- **代码块签名**：对外接口只放关键签名，不放完整实现。
- **问题单列一节**：不要把 TODO 散落在正文里，统一放在「当前存在的问题 / TODO」。

### 3.3 文件命名

| 类型 | 命名示例 |
|------|---------|
| 模块文档 | `agent.html`、`tools.html` |
| 设计/方案文档 | `<主题>.html` 或 `<主题>.md`，如 `weixin-channel.html` |
| 故障/事故报告 | `故障报告-<模块>-<简述>-<YYYYMMDD>.html` |
| 模板 | `_template.html`（下划线前缀，不参与索引列表） |

## 4. 维护流程

1. **开发前**：确认改动属于哪个模块；若新增模块，先在此 README 与 `backend/modules/index.html` 登记。
2. **开发中**：按模块内聚原则组织代码，尽量把相关功能组成子模块/子功能，不随意新建调用文件。
3. **开发后**：
   - 运行相关测试并确保通过。
   - 若涉及行为变更，更新对应 `backend/modules/<module>.html`：功能拆解、关键文件、接口、问题/TODO、变更记录。
   - 小更新可跳过文档。
4. **索引更新**：新增模块或调整阅读顺序时，同步修改 `docs/index.html` 与 `backend/modules/index.html`。

---

## 5. 快速开始

新增一个后端模块文档：

```bash
cp docs/backend/modules/_template.html docs/backend/modules/<module>.html
# 编辑 <module>.html，替换所有 <module> 占位符
```

然后在 `docs/backend/modules/index.html` 的模块列表中追加一行，并在 `docs/index.html` 中确认导航入口已包含。
