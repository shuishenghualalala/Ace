Ace 原生安全运行时

本模块负责把会话权限编译为真实操作系统边界。Gateway 只把已批准的文件根、网络目标、stdin 和环境覆盖交给每任务运行组件；运行组件失败时不会退回宿主直接执行。

macOS 策略

security-runtime/src/macos/mod.rs 使用系统 /usr/bin/sandbox-exec。策略以 deny default 开始，只开放系统运行所需只读目录、明确的 readable/writable roots、一次性私有 HOME，以及命令本身。用户路径通过 -D 参数进入 Seatbelt，避免路径内容改变策略语法。

denied roots 同时拒绝读取与写入，并覆盖更宽的工作区写权限。子进程环境从空环境重建，只保留固定 PATH、私有 HOME/TMPDIR 和 Gateway 已验证的环境覆盖。

网络路径

离线请求不生成任何 outbound allow rule。在线请求先在宿主运行组件内启动随机 loopback 端口，再让 Seatbelt 子进程只能访问该精确端口。HTTP/HTTPS 请求经代理解析后，由既有规则引擎核对协议、域名、端口、私网许可并执行 DNS pinning。直接 socket、绕过代理和未批准目标均失败关闭。

能力探针与界面

Gateway 的 /api/security/capabilities 会在 macOS 上先在工作区写入探针标记，再尝试读取同级秘密文件；只有标记写入成功、秘密文件读取失败且运行组件正常返回能力帧，文件沙箱才显示已启用。这样 Seatbelt 启动失败不会被误报为“读取被拒绝”。联网能力使用独立探针。桌面端同时读取主进程运行平台作为兜底，网关暂时不可达或未返回平台时不会误判为某个系统，也不会展示错误的安装操作。

安全接口使用短时、单次消费的 Desktop 实例证明。签名必须显式绑定当前 Gateway 的绝对 CREW_HOME；开发态、账号态或未来新增的运行模式即使使用不同数据目录，也只能读取对应实例密钥，不能隐式回退到其他目录。

安全中心只呈现“安全防护”“安装 / 修复防护”等统一文案。需要系统级安装的场景由运行环境自动决定；系统内置防护直接显示能力状态，不要求用户选择系统类型。

构建与发布

deb-package/pack_mac.sh 在生成 Electron 应用前执行 release/locked Rust 构建，再通过 Desktop staging 脚本生成包含 SHA-256 的 manifest。开发态优先使用 desktop/security-runtime-bin，其次使用 security-runtime/bin；打包态使用 Resources 内的同平台文件名。Desktop 和 Python Gateway 都按 runtime 旁边的 manifest 校验二进制，打包 manifest 没有源码哈希时不会被误判为源码漂移。

security-macos 工作流在真实 macOS runner 上运行 fmt、clippy、Rust 测试、Python 安全套件、原生文件/网络矩阵和 Desktop staging 校验，并生成绑定 commit 与实际二进制摘要的证据。

测试入口

  • cargo test --manifest-path security-runtime/Cargo.toml --release --locked
  • python tests/security/security_matrix.py --platform macos --runtime ...
  • pytest tests/security tests/gateway/test_security_api.py
  • npm test -- --run tests/unit/security-center-view.test.ts tests/unit/security-banner.test.ts

嵌套在另一个 Seatbelt 会话中的进程可能无法再次调用 sandbox-exec。发布证据必须来自允许创建 Seatbelt profile 的真实 macOS runner，不能用 mock 或仅协议测试代替。
