Crew / 部署与发布

三平台桌面发行包发布

macOS、Linux（UOS / Kylin）、Windows 安装包的制作内容与 GitHub Release 发布流程。

发布入口

仓库新增 workflow .github/workflows/release-desktop.yml，两种触发方式：

方式触发条件说明
自动推送 v* tag（例如 v1.1.0）同时构建四个任务并上传到对应 GitHub Release
手动Actions 页面选择 release-desktop，填写 tag 输入适合打包已存在的旧 tag，例如 v1.1.0
自动触发只对“包含该 workflow 的提交上打出的 tag”生效。仓库中已存在的旧 tag 不会自动触发，需要用手动方式，或先合入代码后打新 tag。

发布产物

平台产物组成
macOS arm64 crew-desktop_<版本>_arm64.dmg Electron 桌面端 + PyInstaller Gateway + 内嵌 Python/Node 运行时 + macOS 安全运行组件
macOS x64 crew-desktop_<版本>_x64.dmg
Linux UOS crew-desktop_<版本>_uos_amd64.deb /opt/crew-desktop（Electron + bwrap + 安全运行组件）+ /opt/crew-gateway（PyInstaller Gateway）+ 内嵌运行时
Linux Kylin crew-desktop_<版本>_kylin_amd64.deb
Windows x64 Crew_Setup_v<版本>.exe win-unpacked 桌面端 + PyInstaller Gateway + 内嵌 Python/Node 运行时 + Windows 安全运行组件，Inno Setup 安装器

Release 同时附带 SHA256SUMS 校验文件和各平台体积报告。

打包内容约定

三个平台的安装包都不包含 web/ 目录及其构建产物 web/dist。桌面端界面来自 desktop/dist；Gateway 缺少 web 静态资源时，浏览器直连管理台显示“前端未构建”占位页，桌面端功能不受影响。

内置 skills 随 Gateway 进入包内 _internal/crew/skills；用户自定义 skills 保留在 ~/.Crew/skills，安装包不覆盖、不写入用户数据。docs、测试、源码、本地配置与密钥一律不进包。

发布步骤

自动发布（推荐）

git checkout main
git pull
git tag v1.1.0
git push origin v1.1.0

推送后进入 GitHub Actions 的 release-desktop 运行页观察四个构建任务，完成后 GitHub Release 自动生成并附带全部安装包。

手动发布旧 tag

进入 Actions 页面，选择 release-desktop，点击 Run workflow，在 tag 输入框填写 v1.1.0，分支选择包含该 workflow 的分支（例如 main）。workflow 会检出该 tag 并使用其代码打包。

注意事项

  • 当前产物未做 Apple 签名与公证，macOS 首次打开需要右键打开；Windows 侧未做 Authenticode 签名时 SmartScreen 可能拦截。
  • 每个构建任务都在目标原生平台 runner 上执行，PyInstaller / Electron 不做交叉编译。
  • Linux 构建依赖 Docker，Windows 构建依赖 Inno Setup 6，workflow 已自动安装。
