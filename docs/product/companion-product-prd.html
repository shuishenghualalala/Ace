01 · Executive Summary

同伴管理关系，主对话承载所有交流

现有 Nearby 能力已经走通，不需要再造一套消息列表和输入框。同伴页面应成为发现与关系管理中心，所有私聊和群聊通过 Session 跳转到主对话页面。

三条硬规则：私聊只允许人和人；Agent 只能在主人仍为成员的群聊中参与；同伴页负责管理，主对话页负责交流。

产品的安全原语是“主人在群”：人可以私聊人；任何 Agent 只能在主人仍是成员的群聊中出现。Agent 没有私信入口，也不能在群外互相调用。
  1. 同伴页只做发现、同伴、Agent 名片和群管理
  2. 发消息与进入群聊统一跳转主对话
  3. 私聊只显示人，不出现 Agent @ 候选
  4. Agent 入群必须同时满足主人在群和主人授权
  5. UI、会话路由和后端共同执行安全边界

03 · Design Principles

年轻感来自关系与语言，不来自蓝色、渐变和动画堆叠

01

人先于技术

页面展示名字、状态和 Agent，Peer ID、信号值和协议版本只进诊断信息。

02

一屏一个主动作

发现页是“打个招呼”，邀请页是“接受”，建群页是“建群”，不并列三个强调按钮。

03

Agent 只在有主人的群里

人不能私聊 Agent，Agent 不能私聊人或 Agent；主人离群时 Agent 同步退出。

04

管理与对话分层

同伴页管理对象与权限，主对话页承载消息；用户不需要学习第二套聊天系统。

05

设置退到上下文

群成员、Agent 权限和工具白名单从头像、成员抽屉或 Agent 名片进入。

06

桌面系统保持一致

白色画布、6–8px 常规圆角、中性选中态、黑色主按钮与细边框优先。

09 · Page Specification

页面功能和交互规则

发现同伴

  • 进入同伴页自动扫描，无需单独“开始扫描”
  • 主区一次聚焦 1 张同伴双生名片
  • 主动作“打个招呼”，次动作只有“暂时略过”
  • 只显示大致距离：就在旁边、附近、信号较弱
  • 权限失败才展示平台专属修复横幅

同伴与邀约

  • 同伴关系只建立在人与人之间
  • 邀请允许附 1 句开场白，接受后创建人类私聊 Session
  • 人物主动作“发消息”跳转主对话并恢复同一私聊
  • 随行 Agent 只作能力预览，不随接受关系自动授权
  • 移除同伴进入人物名片的更多菜单

人与人私聊

  • 在主对话页打开，标题只展示两个人类身份
  • 输入 @ 不展示 Agent 候选，路由也拒绝 agent.request
  • 需要 Agent 时提供“一起建群”，不提供临时私聊例外
  • 对方离线时历史只读可见，草稿保留且不伪装发送
  • 从标题“同伴”来源标识可返回人物资料

创建与管理群聊

  • 第一步只选人和群名，不自动携带任何 Agent
  • 人加入后，各主人分别决定是否携带自己的 Agent
  • 添加他人 Agent 时，系统先验证其主人已是群成员
  • 主人离群，所属 Agent 自动离群并暂停任务
  • “进入群聊”跳转主对话，不在同伴页展开消息流

人机群聊

  • 主对话页沿用消息流、输入框、附件和历史列表
  • @候选按人和 Agent 分组；Agent 行必须显示主人
  • 单 Agent 回复显示“主人在群”，多 Agent 使用有界任务卡
  • Agent 文本中的 @ 不自动唤醒另一个 Agent
  • 群资料返回同伴页的群管理详情

Agent 名片

  • 展示名称、主人、擅长事项、可加入群和工具授权结果
  • 不存在“私聊”“问问 Agent”或复制私聊链接
  • 他人主动作是“加入共同群”；没有合格群时是“与主人一起建群”
  • 主人按群设置是否可被 @、是否纯文本回复和工具白名单
  • 模型密钥与审批细节永远不向其他成员公开
